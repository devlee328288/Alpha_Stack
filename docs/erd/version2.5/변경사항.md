> 2026-09-10 · 이동원 · 마이그레이션 **v14 · v15** · 이 문서는 데이터파트 v4.3 과 함께

Minor 개정입니다. **두 판을 한 번에 담습니다** — v2.4 가 v13 에서 멈춰 있던 사이 스키마가
둘 늘었습니다. 표가 21 → **22** 개가 되고, `daily_price` 에 칸 셋이 붙었습니다.

| | 무엇 | 언제 | 어디 |
|---|---|---|---|
| **v14** | `dividend` 표 신설 — 배당 71,681행 | 2026-09-09 | [§2.10](ERD.md#210-dividend--배당-이력-v14-) |
| **v15** | `daily_price` 총수익 3칸 | 2026-09-10 | [§2.1](ERD.md#21-daily_price--종목-일별-시세-) |

문서 개정을 두 판으로 나누지 않은 이유는 **둘이 한 사건**이기 때문입니다. v14 는 재료를

## 1. `dividend` 표 신설 (v14) — 표가 21 → 22 개

### 1.1 무엇을 받았나

공공데이터포털 **금융위원회 주식배당정보**입니다.

| | 값 |
|---|---:|
| 행 수 | **71,681** |
| 기간 | 1985 ~ 2026 |
| 호출 | **72콜** (쪽당 1,000행) |
| 기본키 | `(isin_cd, dvdn_bas_dt, dvdn_rcd)` — 전량에서 중복 0 확인 |

**72콜로 끝난 이유**가 설계에서 중요합니다. 응답의 `basDt` 는 이벤트 날짜가 아니라
**적재일**이라, 날짜별로 훑으면 같은 자료를 날마다 다시 받습니다. 빼고 부르면 전량이
한 번에 옵니다 — 시세처럼 4,000일을 도는 것과 비교하면 **두 자릿수 차이**입니다.

### 1.2 🔴 기준일은 거래일이 아니다 — 그래서 칸을 하나 계산해 넣었다

포털이 주는 것은 **배당기준일**(`dvdn_bas_dt`)인데 12월 결산법인이면 12월 31일이고
**그날은 휴장**입니다. 실측하면 **12월 기준일 중 거래일인 것은 0.3%** 입니다.

값이 실제로 움직이는 날은 **배당락일**이고, 결제(T+2) 때문에 기준일에서 거래일 두 걸음
앞입니다. 그래서 `ex_date` 를 **거래일 달력으로 계산해 함께 담습니다.**

```
ex_date = prev_session(prev_session(기준일, inclusive=True))
```

계산값이므로 행마다 `ex_date_rule` 을 남깁니다 — 규칙을 바꾸면 어느 행이 옛 규칙으로
세워졌는지 알아야 합니다. 거시(`macro_series.known_at`)와 같은 성질입니다.

**결과가 깨끗합니다.** `ex_date` 가 있는 43,464행은 **전부 거래일**이고 `daily_price` 에도
있습니다(100%). `code` 가 있는 57,212행도 전부 `daily_price` 안에 있습니다.

### 1.3 함정 셋을 칸 이름에 적었다

| 칸 | 함정 | 어떻게 했나 |
|---|---|---|
| `par_price_at_load` | **그날의 액면가가 아니다** — 적재 시점 값이라 삼성전자 1987년 행에도 100원(2018년 분할 뒤)이 들어 있다 | 이름에 `_at_load` 를 붙였다. 금액이 빈 행은 **빈 채로 둔다** — 지어내지 않는다 |
| `src_bas_dt` | 응답의 `basDt` 는 **적재일**이지 이벤트 날짜가 아니다 | 이름을 갈라 담았다 — 기준일과 헷갈리지 않게 |
| `genr_dvdn_amt` = 0 | **무배당과 "금액을 안 적었다" 를 구별하지 못한다** (2010 이후 현금·동시배당 26,008행 중 3,324행이 0) | 판정은 `dvdn_rcd_nm`(배당구분)으로 하고 금액은 참고로만 본다 |

## 2. `daily_price` 에 총수익 3칸 (v15)

### 2.1 왜 필요했나 — 우리 수익률에 배당이 빠져 있었다

`FinanceDataReader` 로 만든 `adj_close` 는 액면분할·무상증자·주식배당까지만 폅니다.
**현금배당은 안 폅니다.** 학계 표준인 CRSP 는 이 둘을 나눠서 주는데, 우리가 가진 것은
`RETX`(배당 제외) 쪽뿐이었습니다.

빠진 것이 **라벨에 닿습니다** — 배당락일의 평균 일간수익률이 평소보다 **1.4665%p 낮고
17년이 전부 음수**입니다. 개별종목 중립대가 ±2% 이므로 5거래일 창에 배당락일이 들어오면
그 라벨이 조용히 아래로 밀립니다.

### 2.2 무엇을 더했나

| 칸 | 형 | 뜻 |
|---|---|---|
| `adj_close_tr` | REAL | 총수익 지수 — 배당까지 재투자한 값 |
| `adj_dividend` | REAL | 그날 얹힌 주당 배당 (**배율을 태운 값**) |
| `is_dividend_suspect` | INTEGER | 원본 배당금의 단위 오류 표시 |

```
adj_dividend_t = 배당금_t × (adj_close_t / close_t)
adj_close_tr_t = adj_close_tr_{t-1} × (adj_close_t + adj_dividend_t) / adj_close_{t-1}
```

### 2.3 🔴 `adj_close` 를 고치지 않았다

이것이 이 판의 요점입니다. 배당을 `adj_close` 에 섞어 넣지 않고 **옆에 세웠습니다.**
원가격(`close`)을 남긴 것과 같은 이유입니다 — 둘은 답하는 질문이 다릅니다.

| | 답하는 질문 |
|---|---|
| `adj_close` | "분할·병합을 편 주가가 얼마였나" (**가격 축**) |
| `adj_close_tr` | "배당까지 재투자하면 얼마가 됐나" (**성과 축**) |

그리고 **총수익 칸은 피처가 아닙니다.** 배당 확정은 주주총회라 그날 이전에는 금액을 알 수
없으므로, 입력으로 넣으면 미래참조가 됩니다. 라벨은 지금처럼 `adj_open`(T+1 시가 → T+6
시가)으로 만들고 이 칸들은 **성과를 잴 때만** 씁니다.

### 2.4 배당에도 같은 배율을 태워야 한다

배당금은 그날의 **원 단위 절대금액**이고 `adj_close` 는 분할 배율이 곱해진 값이라, 원금액을
그대로 더하면 축이 어긋납니다. 조인되는 20,248행 중 `adj_close/close ≠ 1` 인 행이
**6,245행(30.8%)** 입니다 — 안 맞추면 그만큼 틀립니다. 실제 배율은 0.1·0.2·0.5·2·5·10 배가
모두 나옵니다.

### 2.5 실측 — 배당락일 눌림이 뒤집혔다

전 종목 3,678개 · 9,231,938행 적재 (2026-09-10).

| | 값 |
|---|---:|
| 총수익이 채워진 행 | 9,223,800 (99.91%) |
| 채워지지 않은 행 | 8,138 — `adj_close` 가 빈 행과 **정확히 같다** |
| 배당이 얹힌 행 | 20,243 |
| 단위 오류로 뺀 행 | **1** |
| 총수익이 가격 아래로 내려간 행 | **0** |

배당락일 효과 (개발구간 · 종목별 전일 대비):

| 축 | 배당락일 | 평소 | 차이 |
|---|---:|---:|---:|
| 가격 `adj_close` | −0.2595% | +0.8870% | **−1.1465%p** |
| 총수익 `adj_close_tr` | +2.2106% | +0.8870% | **+1.3235%p** |

연도별로 가격 축이 음수인 해가 **11/15** 였는데 총수익 축은 **1/15** 입니다. 남은 한 해
(2013)는 배당락일과 겹친 큰 하락이 따로 있었다는 뜻이고 배당으로는 설명되지 않습니다.

### 2.6 단위 오류를 크기로 자르지 않았다

원본에 **주당 18.5억원** 이라는 배당이 있습니다(윙입푸드홀딩스 2018-12-27). 명백한 오류라
빼야 하는데, **"크면 뺀다"** 로 규칙을 세우면 안 됩니다. 배당이 종가보다 큰 행 넷 중
**셋이 정당한 청산분배금**이었습니다.

| 행 | 배당수익률 | 정체 | 판정 |
|---|---:|---|---|
| 윙입푸드홀딩스 20181227 | 132,722,717% | 배당률도 액면가도 0 | **오류** |
| 한국투자ANKOR 20221214 | 5,964% | 유전펀드 청산분배 (종가 28원) | 정상 |
| 코람코더원 20260828 | 381% | 리츠 분배 · 역산 액면 500 정합 | 정상 |
| 한국투자패러랠 20231227 | 279% | 유전펀드 분배 | 정상 |

**대신 원본이 자기 정합적인가로 가릅니다.** `genr_cash_dvdn_rt` 는 시가배당률이 아니라
**액면가 대비** 배당률이라(현대차 2,500원 = 액면 5,000 × 50%) 금액을 그 비율로 나누면
**그날의 액면가**가 되짚어집니다 — `par_price_at_load` 로는 못 하는 일입니다.

| 갈래 | 행 수 | 비율 | 판정 |
|---|---:|---:|---|
| 되짚어 표준·적재 액면가에 붙는다 | 20,104 | **99.29%** | 믿는다 |
| 되짚히는데 어디에도 안 붙는다 | 111 | 0.55% | 전부 정당했다 (유전·인프라 펀드가 좌당 기준가로 배당률을 매긴다) |
| 배당률이 없어 되짚을 수 없다 | 33 | 0.16% | 전수로 봤다 — 32행이 KDR·외국기업이고 정상 |

되짚을 수 없는 33행 안에서 1위(132,722,717%)와 2위(19.5%)의 간극이 **680만 배**입니다.
임계를 어디에 두든 걸리는 것은 한 행뿐이라 **임계값을 고민할 필요가 없습니다.**

걸린 행도 **지우지 않고 표시만** 합니다. CRSP 가 `DlyDistRetFlg` 로 배분 종류를 남기는
것과 같은 이유로, 판정을 나중에 되짚을 수 있어야 합니다.

## 4. 옛 대용치를 바로잡았다

코드 주석 여섯 곳에 배당락 효과가 **−0.455%p** 로 적혀 있던 것을 **−1.4665%p** 로 고쳤습니다.

| | 대용치 (v4.1) | 실제 배당락일 (v4.2) |
|---|---:|---:|
| 배당락일 효과 | −0.455%p | **−1.4665%p** |
| 음수인 해 | 15년 중 11년 | **17년 전부** |

**3.2배였습니다.** 대용치(*"KOSPI 시총 상위 100 · 연말 마지막 거래일 대비 위치"*)가 사건을
흐린 이유는 둘입니다 — 연말만 봐서 **분기배당을 놓치고**, 상위 100 만 봐서 **고배당
중소형주를 놓쳤습니다.**

> **대용치는 크기를 줄이는 쪽으로 틀립니다.** 원자료가 생기면 다시 재야 합니다.

⚠️ 숫자를 옮길 때는 **측정 조건을 같이 옮겨야** 합니다. 이 판의 §2.5 실측(−1.1465%p)은
v4.2 측정(−1.4665%p)과 또 조금 다릅니다 — 여기는 **전 종목 · 개발구간**이고 그쪽은 표본과
구간이 달랐습니다. 어느 쪽도 틀린 것이 아니라 **무엇을 재는지가 다릅니다.**

## 5. 다음 빈 번호는 v16

`v14` 를 배당이, `v15` 를 총수익이 가져갔습니다. 후보는 **기업행위 이벤트 표**
(`corporate_action` · `ex_date`·비율·출처)입니다 — `adj_price` 의 `chain` 판정과 대조해

**번호는 선착순 인덱스**라 확정이 아닙니다(v11 이 그랬습니다). 바꿀 때는 세 곳을 함께

`tests/test_migrations.py` 가 셋이 어긋나면 걸어 줍니다 (이번에 실제로 걸렸습니다).
