# ERD v1.0 → v2.0 변경사항

> 2026-09-02 · 이동원

## 한 줄 요약

**설계도를 버리고 실물을 그렸습니다.** v1.0 은 PostgreSQL `data-service` 스키마의
설계도였는데, 실제로 서 있는 것은 SQLite 파일 하나(`krx_cache.db` · v8 · 표 16개)입니다.
문서가 8일 동안 존재하지 않는 DB 를 가리키고 있었습니다.

## 무엇이 왜 바뀌었나

### 1. 정본 선언이 바뀌었다 — `sql/init/` → `ingest/store/migrations.py`

v1.0 첫 줄은 *"정본은 `sql/init/` 입니다"* 였습니다. 그러나 그 SQL 이 만드는
Postgres 는 실행된 적이 없고(`asyncpg` 미설치 · 관련 경로는 죽은 코드), 실제 표는
전부 `migrations.py` 가 만들었습니다. 문서와 코드가 어긋날 때 어느 쪽이 맞는지의
기준 자체가 틀려 있었으므로 Major 로 올립니다.

### 2. 표가 전부 다르다

| v1.0 (Postgres 설계) | v2.0 (SQLite 실물) |
|---|---|
| `securities` 종목 마스터 | 없음 — 종목 정보는 `daily_price` 행에 함께 산다 |
| `ohlcv` (RANGE 파티션) | `daily_price` (PK `(bas_dd, code)`) |
| `trading_calendar` | 없음 — **실측 달력은 v9 에서 들어올 예정** (이슈 #51) |
| `ohlcv_sync_log` · `watermark` | `collect_log` (5상태 대장) + 옛 `fetch_log` 2표 |
| — | 반입 3표 · `dart_financial` · `macro_series` · `raw_response` · `call_budget` · `robots_cache` · `ingest_run` 2표 |

### 3. 함정 칸이 실측으로 채워졌다

v1.0 에 없던, 코드를 짜다 실제로 밟은 함정들이 칸으로 들어왔습니다 —
수정주가 아님(#51) · 종목코드 영문 84종 · `account_detail` 빠지면 6.4% 소실 ·
`known_at` 은 계산값 · `market_cap` 의 float64 한계.

## 남긴 것

v1.0 폴더는 그대로 둡니다. *"처음에 Postgres 로 설계했다가 왜 접었나"* 의 증거이고,
그 결정은 [데이터파트 v2.1 명세서 §6](../../데이터파트/version2.1/명세서.md)
(PostgreSQL Won't)에 기록돼 있습니다.
