# ERD 변경사항 — v2.3 → v2.4

> 2026-09-07 · 이동원 · 마이그레이션 **v13** · PR #157 · 이슈 #144 · 이 문서는 데이터파트 v3.9 와 함께

Minor 개정입니다. **표는 21개 그대로이고 기본키 하나가 바뀌었습니다** — `index_price` 의 기본키에
`index_class`(시장)가 들어갔습니다. 표가 늘지 않은 개정을 굳이 판으로 올리는 이유는, 이 기본키가
**자료를 잃었던 원인**이고 ERD 를 보고 조인하는 사람이 같은 함정에 빠지지 않아야 하기 때문입니다.

---

## 1. `index_price` 기본키 — `(bas_dd, index_name)` → `(bas_dd, index_name, index_class)`

| | v2.3 | **v2.4** |
|---|---|---|
| 기본키 | `(bas_dd, index_name)` | `(bas_dd, index_name, index_class)` |
| `index_class` | 칸은 있었다 (계열 · NULL 허용) | **`NOT NULL` · 기본키의 일부** · 값은 `KOSPI` / `KOSDAQ` |
| 막는 자리 | `krx_index._시장가드` 가 받기 **전에** 차단 (v3.8) | **기본키가 답한다.** 가드는 그대로 두되 마지막 방어선이 아니다 |
| 마이그레이션 | — | 새 표 `index_price_v13` 를 만들고 옮기고 지우고 이름을 바꾼다. `index_class` 가 빈 행이 있으면 세우고 **무엇을 하라고 적는다** |
| 실측 | 196,119행 (09-04) | **196,272행 · KOSPI 51종 · KOSDAQ 0종** (09-07) |
| 시험 | — | `tests/test_migrations.py` 신설 (171줄) |

### 왜 — 같은 이름의 업종지수가 둘이다

KOSPI 와 KOSDAQ 은 `건설` · `금속` · `화학` 같은 **같은 이름의 업종지수를 각각** 가집니다. 옛 기본키에서
KOSDAQ 업종지수를 받으면 `INSERT OR REPLACE` 가 같은 `(bas_dd, index_name)` 의 KOSPI 행을 덮습니다.
2026-09-07 아침에 실제로 그랬습니다 — KOSPI 업종지수 **17종 × 40,324행**(20170102~20260904)이 사라졌고,
오류도 경고도 없었습니다. 🔴 **행 수는 오히려 늘었습니다**(196,272 → 244,108). `index_class` 별로
세고서야 드러났습니다. 완전 복구했고(오염 흔적 0일 · HF 배포본 영향 없음), 같은 날 오후 기본키를 고쳤습니다.

배운 것 — **행 수 검증은 덮어쓰기를 못 잡습니다.** 합계가 아니라 키의 축마다 셉니다. 이것이
[데이터 품질 원장 설계 §2.4](../../데이터파트/version3.9/데이터_품질_원장_설계.md) 의 "중복" 축이 됐습니다.

### 조인하는 사람에게

지수를 종목에 붙일 때 `index_name` 만으로 붙이면 KOSDAQ 종목이 KOSPI 업종지수에 붙습니다. **시장을
함께** 겁니다. `supply.sector` 와 `verify_sector` §4 는 v3.8 부터 시장별로 봅니다.

## 3. 다음 빈 번호는 v14

선착순이라 확정이 아닙니다. 지금 보이는 후보 하나 — 이슈 #159 의 지수 준비구간(2009년 KOSPI200 ·
