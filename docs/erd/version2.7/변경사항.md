## 왜 스키마가 안 바뀌었는데 판을 올리나

이번 판에서 드러난 것이 **표의 칸이 아니라 표를 여는 코드의 문제**였기 때문입니다.

| 표 | 시점 칸 | 문 (고치기 전) | 문 (고친 뒤) |
|---|---|---|---|
| `dart_financial` | `rcept_dt` | **없음** — `features/` 0건 | 🆕 `supply.financial` · 접수일 다음 거래일 |
| `macro_series` | `known_at` | **없음** | 🆕 `supply.macro` · `known_at` · 순환변동치 기본 제외 |
| `dart_disclosure` + `text_signal` | `rcept_dt` (제목 점수엔 없음) | HF 반출 파일에만 | 🆕 `supply.text` · 반출과 같은 규칙 |
| `stock_base_info` | `known_at` | `attach_security_type` — **같은 날짜 조인** 🔴 | `known_at <= 행` |
| 업종 스냅샷 (`inbox_accepted`) | 계산 `known_at` | `attach_industry` — **스냅샷 날짜로** 🔴 | `known_at <= 행` |

아래 둘은 `known_at` 칸이 **있었는데도** 새 정보를 하루 먼저 봤습니다(업종 5,300행 · 주권종류
소속부 6,276행 · 상장 첫날 3,677행 — 실측 2026-09-11). ERD 가 칸만 적으면 이것이 안 보입니다.

## 🆕 DB 밖의 기록 — `reports/unseal.log`

홀드아웃 개봉 기록은 DB 가 아니라 **git 이 추적하는 파일**입니다(`*.log` gitignore 의 예외).
ADR 0004 의 증거가 *"사전등록 커밋 시각이 이 파일 첫 행보다 앞선다"* 이고, 그 대조는 git 이력으로만
할 수 있기 때문입니다. 형식은 ADR 0004 §1 을 글자 그대로 따릅니다.

```
# reports/unseal.log — 한 줄 = 한 번의 개봉. 행이 2개가 되는 순간 프로젝트는 실패로 보고한다.
unsealed_at_kst | git_commit | snapshot_sha256 | preregistration_commit | requested_by | reason
```
