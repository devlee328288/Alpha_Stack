# ERD 변경사항 — v2.2 → v2.3

> 2026-09-04 · 이동원 · 마이그레이션 **v11 · v12** · PR #102 · #108 · 이 문서 PR

Minor 개정입니다. **표가 둘 늘어 19 → 21개**입니다 — 하나는 v2.2 가 나온 날 오후에 적용된
v11(종목기본정보)이고, 하나는 이튿날 v12(텍스트 신호)입니다. v2.2 는 v11 을 "다음 빈 번호 —
텍스트 신호 예정" 이라 적었는데 **선착순이라 확정이 아니라던 그 말대로** 종목기본정보가 먼저
가져갔습니다.

## 2. v2.2 가 예상하지 못했던 것 셋

### 2.1 `stock_base_info` 는 "지금" 이 아니라 "그날" 이다

같은 엔드포인트를 다른 날짜로 부르면 다른 답이 옵니다 — 유가 20150102 899행 · 20200102 916행 ·
20260901 943행, 2015 에만 있고 지금은 없는 종목 159종. 그래서 PK 에 `bas_dd` 가 있습니다.
날짜를 키에서 빼면 "지금 무엇인가" 만 남고 "그때는 무엇이었나" 를 잃습니다.

이 성질 덕에 #92 의 걱정(*"2026년에 확인한 값을 2015년에도 같았다고 적용"*)이 여기서는 안
생깁니다 — 2015년 값을 2015년에 직접 물어볼 수 있습니다.

### 2.2 `text_signal` 에는 시점 칸이 없다

설계([고도화 설계 §2.4](../../데이터파트/version3.4/고도화_설계.md))는 `code`·`rcept_no`·`known_at` 을
표에 두려 했습니다. 실제 표는 **제목 단위 캐시**라 시점이 없습니다 — 155만 행의 고유 제목이
18,600개(1.2%)뿐이라 행마다 매기면 같은 문장을 84번씩 읽습니다. 시점(`known_at`)은 **반출할 때**
접수번호마다 접수일에서 만듭니다. 표에 없는 칸이 파일에는 있는 첫 경우입니다.

### 2.3 확률 제약을 DB 가 건다

`CHECK (ABS(p_neg + p_neu + p_pos - 1.0) < 0.01)` · 범위 `[0,1]` 셋. softmax 를 빠뜨려 logit 이
그대로 들어오면 INSERT 에서 걸립니다. 값의 품질을 스키마가 막는 첫 표입니다 — 지금까지 CHECK 는
길이·패턴(`code GLOB`)뿐이었습니다.
