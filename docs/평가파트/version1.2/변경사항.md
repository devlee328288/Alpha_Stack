## 3. 🔴 라벨 축이 파일마다 다릅니다 — 실측

[ADR 0002](../../decisions/0002-예측대상과-레이블.md) 는 **T일 종가 정보 → T+1일 시가 체결
→ T+6일 시가 평가** 입니다. 코드로 재 봤습니다.

| 파일 | 식 | 뜻 | ADR 0002 |
|---|---|---|---|
| `run_full_pipeline.py` | `open.shift(-6) / open.shift(-1)` | T+1 시가 → T+6 시가 | ✅ **맞음** |
| `step5_optimize_6params.py` (fallback) | `open.shift(-5) / open` | **T 시가** → T+5 시가 | 🔴 **하루 앞** |

`step5` 는 `df_train` 에 `label` 칸이 있으면 그것을 쓰고, **없을 때만** 위 식으로 떨어집니다.
그 fallback 이 문제입니다.

**왜 문제인가.** 같은 함수에서 예측은 `close > upper` 로 **T일 종가**를 씁니다. 그런데
라벨은 **T일 시가**부터 시작합니다. `open[T] → close[T]` 구간이 라벨 안에 들어 있고,
신호는 그 구간을 이미 알고 있습니다 — **하루치 미래참조**입니다.

주석에는 `# 3) 실제 레이블 - ADR-0002 기준 (open shift(-5) / open)` 이라고 적혀 있는데,
**ADR 0002 는 그 식이 아닙니다.** 주석이 식을 정당화해 버려서 눈에 안 띕니다.

> 🔵 **강민석 님께** — `label` 칸이 항상 붙는다면 이 fallback 은 죽은 경로이니 지우는 편이
> 낫고, 붙지 않는 경우가 있다면 `open.shift(-6) / open.shift(-1)` 로 고쳐야 합니다.
> 어느 쪽인지 알려 주시면 제가 PR 로 올리겠습니다. **남의 파일이라 손대지 않았습니다.**

## 4. ✅ 백테스트 원장이 시가축으로 왔습니다 — 계약 시험이 초록

[PR #218](https://github.com/devlee328288/Alpha_Stack/pull/218) 이 `realized_return_5d` 를
고쳤습니다.

```
전: close[T+5] / close[T]        ← 종가축
후: open[T+6] / open[T+1]        ← 체결(다음날 시가)과 같은 축
```

**데이터 파트가 걸어 둔 `xfail(strict=True)` 셋이 XPASS 로 뒤집혀 시험이 3건 실패**했고,
그것이 해소 신호였습니다([#176](https://github.com/devlee328288/Alpha_Stack/issues/176)).
표식을 지웠습니다(PR [#220](https://github.com/devlee328288/Alpha_Stack/pull/220)).

축은 이제 세 곳이 같습니다.

| 어디 | 식 |
|---|---|
| `backtest/backtest_strategies.py:720` | `open[T+6] / open[T+1]` |
| `evaluation/horizon.py:193` | `rows[i+6]["open"] / rows[i+1]["open"]` |
| `supply/backtest_ledger.py` (검증기) | 같음 |

## 5. 전략이 반전에서 추세 추종으로 바뀌었습니다

```
전: 상단 돌파 → 하락(0) · 하단 돌파 → 상승(2)      (역추세)
후: 상단 돌파 → 상승(2) · 하단 돌파 → 하락(0)      (추세 추종)
```

PR #215 본문의 근거는 *"KOSPI200 워크포워드에서 OOS 정확도가 1.18~2.94%p 높다"* 입니다.
코드에도 `# 🔥 반전 제거` 주석으로 남아 있습니다.

**⚠️ 이 결정은 개발구간 결과를 보고 내린 것입니다.** 반전/추세추종 둘 중 하나를 데이터로
골랐으므로 **시행이 하나 늘어납니다.** 최종 보고에 그 사실을 적어야 합니다 —
데이터 파트도 같은 방식으로 전처리 시행을 세고 있습니다(전처리 v1.3 · N=7).
