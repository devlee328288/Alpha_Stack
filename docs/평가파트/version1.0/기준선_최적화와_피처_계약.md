## 1. `config/features.py` — 피처 계약을 상수로 뽑았다 (#112)

### 무엇이 문제였나

평가·백테스트 코드가 `X` 를 **제외 목록**으로 만들고 있었습니다.

```python
FEATURES = [c for c in df.columns if c not in ("date", "label", "code", ...)]
```

이러면 **배포본에 칸이 늘 때마다 조용히 딸려 들어갑니다.** 데이터 파트가 09-03 에 업종 칸
셋을 더했고, 실제로 종목 파일의 숫자 아닌 칸이 3개 → **5개**로 늘어 있었습니다(#84).

### 무엇이 됐나

```python
# config/features.py
FEATURE_COLUMNS = [
    "sma_5", "sma_20", "sma_60", "ema_12", "ema_26",
    "rsi_14", "macd", "macd_signal", "macd_hist",
    "bb_mid", "bb_upper", "bb_lower", "bb_bandwidth",
    "true_range", "atr_14", "hv_20", "parkinson_20",
    "vol_sma_20", "vol_ratio_20", "obv", "vwap_20", "vol_roc_5",
]


def get_features(df):
    return [c for c in df.columns if c in FEATURE_COLUMNS]
```

**제외가 아니라 포함**입니다. 세 곳이 이걸 씁니다.

| 파일 | 줄 |
|---|---|
| `evaluation/evaluation_backtest.py` | 20 |
| `evaluation/evaluation_risk.py` | 13 |
| `backtest/collector_5days.py` | 24 |

이 22칸은 반출 쪽 `scripts/export_team_dataset.py:357` 의 `FEATURE_COLUMNS` 와
**같은 목록·같은 순서**입니다. 지수 파일과 종목 파일에 공통입니다.

> ✅ **2026-09-05 재배포에서 바로 효과가 났습니다.** 데이터 파트가 업종 칸 3개를 HF 에
> 올렸는데, 고치지 않았다면 그 문자열 칸 셋이 `X` 에 딸려 들어가 학습이 깨졌을 자리입니다.

## 2. 동적 기준선 6단계 파이프라인 (#117)

`evaluation/threshold_tuning/` · 설계 문서는 같은 폴더의 `threshold_tuning.md`.

### 수식 — 하이브리드 기준선

```
중립 기준선  Base                                   (SMA(종가, 20) 고정 · 튜닝 안 함)
상승 기준선  Base + (α_up   × 변동성) + (β_up   × 거래량조정항)
하락 기준선  Base − (α_down × 변동성) − (β_down × 거래량조정항)
```

**상승과 하락에 서로 다른 계수**를 둡니다 — 시장의 움직임이 대칭이 아니기 때문입니다.
튜닝 대상은 `α_up · α_down · β_up · β_down` 과 변동성·거래량 측정 기간까지 **6개**입니다.

### 단계

| 단계 | 파일 | 무엇 |
|---|---|---|
| 1 | `step1_core_features.py` | 코어 피처 — Base(SMA20) · 변동성(ATR14 또는 수익률 표준편차) · 거래량 조정항 |
| 2 | `step2_optimize.py` | 4파라미터 CMA-ES 워크포워드 |
| 3 | `step3_objective_optimize.py` | 목적 함수 — `Sharpe − λ×MDD` (과적합 방지 패널티) |
| 4 | `step4_walkforward_official.py` | 정식 워크포워드 (학습 구간 이동) |
| 5 | `step5_optimize_6params.py` | 6파라미터 전체 탐색 |
| 6 | `step6_live_signal.py` | 실전 신호 생성 · 클래스 비율(`ratio_up`/`ratio_neutral`/`ratio_down`)과 `balanced_accuracy` |
| — | `run_full_pipeline.py` | 1~6 을 한 번에 |

### 탐색 범위

| 파라미터 | 범위 |
|---|---|
| `α_up` · `α_down` | 0.5 ~ 3.0 (변동성 배수) |
| `β_up` · `β_down` | −1.5 ~ 1.5 (거래량 영향도) |
| 변동성 기간 · 거래량 SMA 기간 | 10 ~ 30일 |

6차원이라 그리드 서치가 비효율적이어서 **CMA-ES** 를 씁니다.

### 🔴 `balanced_accuracy` 를 쓰는 것이 이슈 #33 과 맞물립니다

`step6` 이 `balanced_accuracy_score` 와 클래스별 비율을 함께 봅니다. 이건
[이슈 #33](https://github.com/devlee328288/Alpha_Stack/issues/33)이 지적한
*"`hit_rate` 가 중립 38.69% 를 분모에서 뺀다"* 를 우회하는 방향입니다.

다만 **`evaluation/metrics.py:112` 의 `hit_rate` 자체는 아직 그대로입니다**
(`mask = a != 0`). 두 지표가 공존하고 있으니, 무엇을 보고할지 정해 두는 편이 좋습니다.
