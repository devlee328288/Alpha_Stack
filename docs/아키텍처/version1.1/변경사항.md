# 아키텍처 v1.0 → v1.1 변경사항

> 2026-08-29 · 킥오프(9/1) 계획서 작성 세션

---

## 왜 올렸나

v1.0 은 2026-08-25 에 썼습니다. 그 뒤 PR 7건이 들어오면서 **그림이 코드와 어긋났습니다.**
가장 큰 것은 **`supply/` as_of 정문이 그림에 아예 없다**는 점입니다. 이 저장소에서 가장
중요한 구조인데 v1.0 에는 존재하지 않습니다.

계획서에 아키텍처 그림을 넣으려고 v1.0 을 열었다가, 그대로 쓰면 안 되는 상태라 올렸습니다.

---

## 무엇이 바뀌었나

### ① `supply/` as_of 정문을 그림과 의존 사슬에 넣었다 ★

v1.0: `ingest` → `features` (직행)
v1.1: `ingest`(internal) → **`supply`** → `features`

그리고 **"지켜야 할 규칙"을 둘에서 셋으로** 늘렸습니다. 새 ③은
*"소비 계층은 `ingest` 를 직접 import 하지 않는다"* 입니다.
`tests/test_supply_boundary.py` 16개가 이걸 강제합니다.

> ⚠️ 함께 적어 둔 것: **이 테스트가 막는 것은 `ingest` 문자열 하나뿐입니다.**
> `import sqlite3` + `common.paths.krx_db_path()` 로 생 SQL 을 던지면 통과합니다.
> 알고 있는 구멍이라 문서에 남깁니다.

### ② Postgres 를 그림에서 뺐다

v1.0 의 `store/` 설명이 "Postgres·SQLite 에 넣고 꺼낸다" 였습니다.
**SQLite 하나**로 정해졌고 Postgres 경로 약 1,524줄은 죽은 코드입니다.

> ⚠️ **그래도 지우면 안 됩니다.** `ingest/store/krx_store.py:595` 가 postgres 분기
> **밖에서** `krx_pg.CODE_PATTERN` 을 씁니다. 정리하다 종목명 검색이 조용히 죽습니다.
> 이 경고를 §7 에 넣었습니다.

### ③ 마지막 층을 `api/` 에서 Streamlit 으로 바꿨다

v1.0 은 `api/` 가 "최소 HTTP 계약 + Swagger" 로 끝이었습니다. 팀이 **배포를 안 하기로**
했고 화면은 **산출 파일(JSON·parquet)을 읽는 Streamlit** 으로 방향을 잡았습니다.
화면이 모델을 부르지 않아 **발표 시연이 안정적**입니다.

### ④ "조용히 틀리는 곳" 을 셋에서 여섯으로 늘리고 실측을 붙였다

v1.0 은 세 곳을 말로만 적었습니다. v1.1 은 **잰 값**을 붙였습니다.

| 새로 넣은 것 | 실측 |
|---|---|
| 레이블을 시가(t)→시가(t+5) 로 정렬 | 상관이 **정확히 10.0배** (+0.1709 대 +0.0171) |
| 종목의 거래정지를 행 번호로 건너뜀 | E\|5일수익\| **4.781% → 4.489%** |
| `as_of` 를 안 넘김 | `AsOfRequired` 로 **멈춤** — 여섯 중 유일하게 예외가 나는 곳 |

재현: `python scripts/measure_horizon.py` · `python scripts/measure_stock_horizon.py`

### ⑤ §7 "아직 정해지지 않은 것" 넷 중 셋이 닫혔다

v1.0 이 물었던 것 중 Supabase · SQLite/Postgres 이중경로 · 대시보드 호출 방식이
닫혔습니다. 닫힌 것은 **결론과 함께 §7 에 남기고**, 남은 것은 §8 로 옮겼습니다.
지우지 않은 이유는 *"무엇을 왜 그렇게 정했는가"* 가 발표에서 쓰이기 때문입니다.

§8 에 새로 들어온 미정 둘:
- 산업 분류 기준 (수업 `06-data-crawling/7` 이 KRX 업종분류·WICS 를 이미 수집합니다)
- 뉴스 제목·요약의 SQLite 영속 저장 — 네이버 약관 7.3 ③ 이 "저장(캐시 포함)" 을
  금지합니다. **법적 판단이라 단독 결론을 내지 않습니다**

### ⑥ 다이어그램 3장을 넣었다

mermaid 원문(`.mmd`)이 정본이고 `.png` 는 거기서 굽습니다. 원문이 git 에 남아 있어
누구나 다시 구울 수 있습니다.

| 파일 | 무엇 |
|---|---|
| [계층아키텍처.mmd](계층아키텍처.mmd) | `supply/` 정문을 강조한 계층 그림. 경계를 넘는 import 를 테스트가 막는 것도 그렸습니다 |
| [역할파이프라인.mmd](역할파이프라인.mmd) | 역할별 워커와 오케스트레이션. 2·3차의 RAG·에이전트 승격은 점선 |
| [일정간트.mmd](일정간트.mmd) | 2주 일정. 인수(9/7) · 중간점검(9/8) · 홀드아웃 개봉(9/13) |

```bash
mmdc -i 계층아키텍처.mmd -o 계층아키텍처.png -b white -s 2
```

> ⚠️ mermaid 파일에 **내용 없는 `%%` 줄을 넣으면 파서가 앞뒤 줄과 합쳐 깨집니다.**
> 주석은 항상 내용을 붙여 씁니다.

## 역할파이프라인 그림에 대해 — 이름을 정확히 썼다

팀원 제안은 *"LLM 없이 역할별 AI Agent 로 나눠 RAG 및 ML/DL 을 융합"* 이었습니다.

**1차에는 LLM 이 없습니다.** 그래서 통상적 의미의 '에이전트' 가 아니라 **역할별 워커와
오케스트레이션**이고, 우리 구조가 **이미** 그렇습니다. 그림에 "AI Agent" 라고 적으면
사실과 어긋나므로 **"LLM 없는 역할 분리 파이프라인"** 으로 적고, RAG·에이전트 승격은
**2·3차 영역으로 점선 처리**했습니다.

아이디어를 버린 것이 아니라 **1차에서 참인 형태로 옮긴 것**입니다.
AGENTS.md 의 절대 제약 *"LLM 유료 API 0원"* 과도 맞습니다.
