# 외부 API 실측 — 네이버 이관과 KRX 한도

> 측정 2026-08-27 · 재현 `python scripts/probe_naver_paging.py`
>
> **여기 있는 것은 공식 문서와 실제가 어긋났거나, 우리가 "미확인" 으로 미뤄 뒀던 값들입니다.**

---

## 1. 🔴 우리 팀 네이버 키는 개발자센터 것이 아닙니다

개발자센터(`developers.naver.com`)는 **2026-07-30 로 신규 발급이 끊겼습니다.** 우리 키는
그 뒤 **NAVER Cloud Platform 의 API HUB** 에서 재발급받은 것입니다.
그래서 **호스트·경로·인증 헤더·한도가 전부 다릅니다.**

| | 개발자센터 (구) | **API HUB (우리)** |
|---|---|---|
| 호스트 | `openapi.naver.com` | **`naverapihub.apigw.ntruss.com`** |
| 경로 | `/v1/search/news.json` | **`/search/v1/news`** |
| 헤더 | `X-Naver-Client-Id`<br>`X-Naver-Client-Secret` | **`X-NCP-APIGW-API-KEY-ID`**<br>**`X-NCP-APIGW-API-KEY`** |
| 한도 | 일 25,000 | **월 775,000 (월 단위 관리)** |
| 종료 | **2027-06-30 24:00** | — |

```bash
curl -G "https://naverapihub.apigw.ntruss.com/search/v1/news" \
  -H "X-NCP-APIGW-API-KEY-ID: <CLIENT_ID>" \
  -H "X-NCP-APIGW-API-KEY: <CLIENT_SECRET>" \
  --data-urlencode "query=삼성전자" --data "display=5"
```

응답 형태는 개발자센터와 같습니다 — `lastBuildDate` · `total` · `start` · `display` ·
`items[]`, 항목은 `title` · `originallink` · `link` · `description` · `pubDate`.
**뉴스에는 `pubDate` 가 옵니다** (카페글에는 없습니다).

> 📌 **우리 예산 모듈은 일 단위로 셉니다.** HUB 는 월 단위인데 일 단위로 세면 보수적이라
> 한도를 넘길 위험은 없습니다. 다만 **표기가 사실과 다르다는 것을 알고 씁니다.**

## 2. 🔴 함정 — 호스트를 잘못 잡으면 HTTP 200 이 온다

이걸 찾는 데 실호출 7콜을 썼습니다. 값어치가 있었습니다.

| 호스트 | 경로 | 인증 | 결과 |
|---|---|---|---|
| `naverapihub.apigw.ntruss.com` | `/search/v1/news` | 올바름 | **HTTP 200** · 정상 |
| `naverapihub.apigw.ntruss.com` | `/search/v1/news` | 틀림 | **HTTP 401** · `{"error":{"errorCode":"200",…}}` — 제대로 거절 |
| **`openapi.naver.com`** | `/search/v1/news` | 올바름 | 🔴 **HTTP 200** · `{"error_code":"052", "message":"Partner does not exists"}` |
| `openapi.naver.com` | `/v1/search/news.json` | HUB 키 | HTTP 401 · `024` |

**세 번째 줄이 위험합니다.** 호스트만 틀렸는데 HTTP 는 **200** 이고 오류는 본문에만
실립니다. `raise_for_status()` 만 믿는 수집기는 이걸 **성공으로 읽고 빈 결과를 매일
조용히 적재**합니다. 그리고 `total` 도 `items` 도 없으니 *"오늘은 뉴스가 없었나 보다"* 로
보입니다.

**DART 가 한도 초과를 `HTTP 200 + status="020"` 으로 주는 것과 같은 종류**입니다.

> ⚠️ **키 이름도 다릅니다** — HUB 게이트웨이는 `{"error": {"errorCode": …}}` 로 중첩하고,
> 개발자센터의 HUB 경로 응답은 평평한 `error_code` 를 씁니다. **둘 다 봐야 합니다.**

### 그래서 수집기가 지켜야 할 것

1. **HTTP 상태와 본문 오류코드를 둘 다 본다.** 하나만 보면 반쪽이다
2. 인증 실패를 **0건과 구별한다.** 대장에 `error` 로 남기고 `empty` 로 남기지 않는다
3. 호스트를 **상수로 분리**한다. 2027-06-30 이관도 같은 자리에서 한 줄로 끝나야 한다

## 3. ✅ `start + display - 1 <= 1000` 부등식은 존재하지 않습니다

우리 문서가 오래 *"합이 1000 을 넘으면 400"* 이라고 적어 왔습니다. **공식 명세에 그
부등식이 없어서** 실호출로 확인했습니다.

| start | display | 합 | 결과 |
|---|---|---|---|
| 1 | 10 | 10 | HTTP 200 · 9건 |
| 901 | 100 | 1000 | HTTP 200 · 100건 |
| **1000** | **100** | **1099** | **HTTP 200 · 100건** ✅ |
| 1000 | 1 | 1000 | HTTP 200 · 1건 |
| **1001** | 1 | 1001 | **HTTP 400 · `SE03` Invalid start value** |

**명세대로 두 독립 범위가 맞습니다** — `display 1~100` · `start 1~1000`.

→ 한 검색어로 도달 가능한 총량은 **1,000건이 아니라 1,099건**입니다.
문서의 *"안전측 가정"* 표시를 뗍니다.

> 📌 그래도 **뉴스는 백필이 아니라 누적**이라는 결론은 그대로입니다. 1,099건도
> 인기 종목이면 며칠치입니다.

### 오류코드

`SE03` 이 실제로 확인됐습니다. 공식 코드는 `SE01`~`SE06`·`SE99` 7종이고,
**v1.0 문서가 적은 `errorCode 010` 은 존재하지 않습니다.**

## 4. ✅ KRX 일일 한도가 약관에 명문으로 있습니다

> *"④ 하나의 키당 1일(매일 0시~24시) **10,000회 이하**의 요청으로 제한하며, 이를 초과할
> 경우 서비스가 중지될 수 있다."*
> — KRX OPEN API 이용약관 **제8조(제공중단) ④** · `openapi.krx.co.kr`

가정값이 아니라 **약관 명문**이었습니다. 우리 예산 모듈의 `10,000` 은 맞습니다.

**다만 두 가지를 함께 적어야 합니다.**

| ⚠️ | 왜 |
|---|---|
| 단위가 계정이 아니라 **키** | 팀원 4명이 각자 키를 받으면 총량은 40,000 이지만, **한 사람이 백필을 몰아 돌리면 그 사람 키만 막힙니다.** 예산 모듈이 출처 단위로만 세면 *"팀 전체 예산"* 처럼 착각하기 쉽습니다 |
| 제8조 ① 이 거래소에 **횟수 재지정 재량**을 준다 | 10,000 을 하드코딩하고 *"약관에 있으니 안전"* 이라고 믿으면, 거래소가 낮췄을 때 **우리 카운터는 여유가 있다고 보고하는데 서버는 거절합니다** |

> 📌 **DART 20,000 은 여전히 미확인입니다.** 이번 조사 대상이 아니었고, 공식 문구가
> *"요청 제한이 다르게 설정된 경우"* 단서를 답니다. 로그인 후 이용현황에서만 확인됩니다.

## 5. ⚠️ 약관에서 우리가 잘못 인용하던 것

| 우리가 적던 것 | 실제 |
|---|---|
| 쿼터 초과 = `errorCode 010` | ❌ **그런 코드 없음.** `SE01`~`SE06`·`SE99` 7종뿐 |
| `start+display-1 ≤ 1000` | ❌ **부등식 없음** (§3 실측) |
| 약관 7.3 ③ *"복제, 저장, 가공, 배포"* | ⚠️ 원문은 **`저장(캐시 행위 포함)`** — 괄호를 빠뜨리면 *"캐시는 저장이 아니다"* 로 읽힐 여지가 생깁니다 |

> 🔴 **7.3 ③ 의 '캐시 행위 포함' 은 우리 설계에 직접 걸립니다.** 뉴스 수집기가 제목·요약을
> SQLite 에 영속 저장하려는데, *"본문 전문은 저장 안 함"* 으로는 방어가 안 됩니다.
> 조항이 *"일체의 데이터"* 라고 씁니다. **법적 판단이라 단독 결론을 내지 않고
> 킥오프 안건으로 올립니다.**
