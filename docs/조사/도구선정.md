## 1. SQLite 마이그레이션 — `PRAGMA user_version` + 자작 30줄

### 왜 라이브러리를 안 썼나

`alembic` · `yoyo` · `sqlite-utils` **전부 기각**했습니다.

alembic 이 SQLite 에 주는 것은 batch(move-and-copy) 모드인데, **실측상 그 급의 전면
재작성은 19초짜리**이고 정작 우리가 필요한 `ADD COLUMN` 은 **0.16ms 로 공짜**입니다.
**필요 없는 비싼 경로를 위한 의존성**입니다.

### 900만 행 실측 (SQLite 3.53.2 · 727MB · WAL)

| 연산 | 시간 |
|---|---|
| `ADD COLUMN` (DEFAULT 없음) | **0.72ms** |
| `ADD COLUMN NOT NULL DEFAULT 0` | **0.16ms** |
| `RENAME COLUMN` | 1.00ms |
| `ADD COLUMN` + **CHECK 제약** | **5,088ms** (약 3만 배) |
| `DROP COLUMN` | **19,163ms** (900만 행 전체 UPDATE 와 동급) |

### 🔴 규약 4개 — 타협 불가

1. **`BEGIN IMMEDIATE` 를 명시한다.** 파이썬 `sqlite3` 기본 모드는 DDL 을 암묵
   트랜잭션에 넣지 않습니다. 빼면 마이그레이션이 원자적이지 않습니다
2. **`executescript()` 를 쓰지 않는다.** 열린 트랜잭션을 먼저 커밋해 롤백이
   불가능해집니다 — 실측: ROLLBACK 이 *"no transaction is active"* 로 실패하고
   **반쪽 스키마가 남았습니다**
3. **`PRAGMA user_version=N` 을 스키마 변경과 같은 트랜잭션에 넣는다.**
   *"헤더라서 트랜잭션 밖"* 이라는 통설은 **실측으로 반증**됐습니다 (ROLLBACK 시 복귀)
4. **`PRAGMA user_version` 만 쓴다.** `schema_version` 은 SQLite 내부용이고 공식 문서가
   **DB 손상을 경고**합니다

### 스키마 규칙

- 새 컬럼에 **CHECK 제약 금지** (3만 배)
- **`DROP COLUMN` 금지** (19초)
- `DEFAULT CURRENT_TIMESTAMP`·`UNIQUE`·`PRIMARY KEY` 는 `ADD COLUMN` 에서 거부됨 (상수만)
- 반대로 **`NOT NULL DEFAULT <상수>` 는 마음껏** 써도 됩니다 (오히려 더 빨랐습니다)

## 2. `robots.txt` 파서 — `protego==0.6.2`

### 표준 라이브러리는 탈락입니다 — 판단이 아니라 실측입니다

`urllib.robotparser` 의 `RuleLine.applies_to` 는 `filename.startswith(self.path)`
접두사 매칭이 전부이고, 규칙 경로에 `quote()` 를 적용해 `*` 가 `%2A` 리터럴이 됩니다.
결과적으로 **명시적 `Disallow` 인 URL 에 `can_fetch()` 가 `True` 를 반환**합니다.

> 🔴 **차단 가드가 반대 방향으로 틀리면 가드가 없는 것보다 나쁩니다.**
> 안전하다는 착각을 주기 때문입니다.

| 후보 | 판정 |
|---|---|
| `urllib.robotparser` | ❌ fail-open. 와일드카드·`$` 미지원 |
| **`protego`** | ✅ 전 케이스 정답. `$`·최장일치·쿼리스트링·비표준 라인(`Disallow : `)까지 |
| `reppy` | ❌ PyPI 최신 2019년(0.4.14), 지원 파이썬 ~3.7 |
| `robotexclusionrulesparser` | ❌ 같은 케이스 fail-open. 우선순위가 순서 의존적. 최종 릴리스 2016년 |

### 왜 `0.6.2` 로 못 박았나

`<=0.6.1` 에 ReDoS 취약점
[GHSA-wjmf-p669-5m5p / CVE-2026-55520](https://github.com/scrapy/protego/security/advisories/GHSA-wjmf-p669-5m5p)
(severity **High**)이 있습니다. **외부가 주는 파일을 파싱하는 코드는 정면 노출입니다.**

> 📌 GHSA API 가 `cvss` 를 `null` 로 반환해 **구체 점수는 확인되지 않았습니다.**
> `severity=high` 까지만 확정입니다.

### 직접 만들어야 했던 것

`protego` 는 파서 전용이라 fetch 를 안 합니다.

- **HTTP 상태 분기를 RFC 9309 대로**: `4xx`(404 포함) → **전면 허용**(MAY access) /
  `5xx`·네트워크 오류 → **전면 차단**(MUST assume complete disallow)
  ⚠️ **흔한 실수가 5xx 를 허용으로 처리하는 것**인데 RFC 는 **MUST 로 금지**합니다
- 24시간 캐시 (RFC 문구와 일치). 단 *"unless unreachable"* 단서를 살려
  5xx 로 갱신 실패 시 **직전 캐시를 계속 씁니다**
- ⚠️ 응답이 **`charset=euc-kr`** 입니다. UTF-8 로 가정하지 않습니다

## 3. 화면 스택 — `streamlit==1.62.0` · Pretendard v1.3.9

### 버전 호환성 실측

기존 핀과 **충돌 없음**: `numpy 2.5.1 ⊂ <3,>=1.23` · `pandas 3.0.5 ⊂ <4,>=1.4.0` ·
`pyarrow 25.0.1 ⊂ !=25.0.0,<26,>=7.0` (25.0.0 만 콕 집어 제외인데 우리는 25.0.1).

pandas 3 정식 지원은 **1.56.0 (2026-03-31)** 부터라 5개월 숙성됐습니다.

> ⚠️ **`1.61.x` 이하는 `pyarrow<25` 를 요구해 우리 핀과 설치 자체가 실패합니다.**

### 테마는 CSS 주입이 아니라 토큰으로

1.62.0 기준 **53개 키**를 지원합니다. `[theme]` 공통 + `[theme.light]`/`[theme.dark]` 오버라이드.

- ⚠️ 7개 키(`base`·`fontFaces`·`baseFontSize`·`baseFontWeight`·`metricValueFontSize`·
  `metricValueFontWeight`·`showSidebarBorder`)는 **최상위 `[theme]` 전용**입니다
- ⚠️ **중첩 순서 고정**: `[theme.dark.sidebar]` 는 유효, `[theme.sidebar.dark]` 는 **무효**

### 폰트 — Pretendard v1.3.9 (SIL OFL 1.1)

`woff2` Regular 765,892 B / Bold 791,156 B. **OFL 은 임베딩·재배포·상업 이용을 명시
허용하고 산출물에 전파되지 않습니다.**

→ 외부 CDN 을 안 쓰므로 정적 HTML 의 *"외부 네트워크 요청 없이 렌더"* 요구와도 맞습니다.

### 커스텀 컴포넌트는 `st.components.v2` (1.51.0~)

iframe 없는 구조라 앱 테마가 상속되고 **`--st-*` CSS 커스텀 프로퍼티**를 그대로
참조할 수 있습니다 (`theme.primaryColor` → `var(--st-primary-color)`).

→ **정적 HTML 이 같은 토큰을 쓸 수 있는 근거**입니다. 화면 스택이 어느 쪽으로 닫히든
디자인 토큰은 한 벌로 갑니다.

## 4. ⚠️ 라이선스가 불명한 것은 1차에 넣지 않습니다

**HuggingFace 한국어 금융 모델(KR-FinBert-SC 등)** 은 다운로드 220만 회로 실사용은
많지만 **라이선스 태그가 없습니다** (HF API `cardData` 에 `license` 부재 확인).

PUBLIC 포트폴리오 저장소에 **재배포 조건이 불명인 가중치**를 전제로 한 파이프라인을
넣는 것은, 네이버 약관의 저장 제약을 엄격히 본 것과 앞뒤가 맞지 않습니다.

→ **2차로 미루고, 쓸 거면 라이선스가 명시된 모델을 고릅니다.**
