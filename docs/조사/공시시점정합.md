# 공시 시점 정합 — DART 접수일을 어떻게 얻는가

> 측정 2026-08-26 · 원본은 데이터파트 변경노트 §4 (v2.0 승격 시 이리로 옮김)
>
> **왜 이 문서가 있나.** Point-in-Time 위반은 이 프로젝트에서 **가장 조용하고 가장
> 치명적인 오류**입니다. 그리고 그 오류로 가는 지름길이 하나 널리 쓰이고 있습니다.

---

## 1. 문제 — 재무제표 응답에 접수일이 없습니다

DART `fnlttSinglAcntAll`(재무제표) 응답에는 **`rcept_dt` 가 없습니다.** `rcept_no`(접수번호)만
옵니다. 공식 필드 목록으로 확인했고, 삼성전자 FY2023 실호출 **176행의 키 합집합**에
`dt`·`date` 를 포함하는 키가 **0개**임을 실측했습니다.

그런데 우리 요구사항은 *"접수일이 없는 응답은 **적재 거부**"* 입니다.
**문자 그대로 적용하면 재무제표가 전량 거부되어 재무 피처를 쓰려는 팀원이 멈춥니다.**

---

## 2. 🚫 널리 쓰이는 편법 — `rcept_no[:8]` 슬라이싱

접수번호 앞 8자리가 접수일자라는 것은 **공식 문서에 없는 관행**입니다.
그럼에도 널리 쓰여서, **정기공시 4,800건을 실측 검증**했습니다.

### 결과: 3건(0.062%)이 깨졌고, **방향이 나쁩니다**

| `rcept_no` | 앞 8자리 | 실제 `rcept_dt` | 문제 |
|---|---|---|---|
| `20180330004096` (엠피씨플러스) | 2018-03-30 | **2018-04-02** | 접수일을 **3일 앞당겨** 읽음 → 🔴 **lookahead** |
| `20180330004046` (씨제이이앤엠) | 2018-03-30 | **2018-04-02** | 〃 |
| `20250401000004` (DH오토넥스) | 2025-04-01 | 2025-03-31 | 하루 늦음 (보수적 방향이라 무해) |

**앞 두 건은 아직 공개되지 않은 정보를 사흘 먼저 아는 것**입니다 — 우리가 막으려는
오류 그 자체입니다. 전체 공시로 넓히면 오차율이 **1.2%** 로 올라갑니다.

> 💡 0.062% 는 작아 보입니다. 하지만 **틀리는 방향이 전부 우리에게 유리한 쪽**이면
> 그건 잡음이 아니라 **편향**입니다. 그리고 **에러는 나지 않습니다.**

→ **슬라이싱은 채택하지 않습니다.** 조인 결과를 교차검증하는 **경보용으로만** 씁니다
(불일치 시 로그).

## 3. ✅ 채택 — `list.json` 조인

```
list.json(corp_code, pblntf_ty="A", bgn_de="20150101", end_de=오늘, page_count=100)
   → rcept_no → rcept_dt 맵
   → 재무제표 행의 rcept_no 로 조인
```

| 항목 | 값 |
|---|---|
| **실측 검증** | 삼성전자 `rcept_no=20240312000736` → `list.json` 에서 `total_count=1`, `rcept_dt='20240312'` **1:1 매칭 성공** |
| **비용** | 회사당 1콜 (대형주 47~56건이 1페이지). 2,700사 ≈ **2,700콜** |
| **재수집 비용** | **0** — 접수일은 불변이라 영구 캐시 가능 |

⚠️ **조회 구간을 넓게 잡습니다.** 에너토크 FY2021 의 실제 문서는 **2024-05-28** 접수라
좁은 창으로는 안 잡힙니다. `total_page > 1` 이면 페이지를 순회합니다.

## 4. 부수 결정

### 4.1 `known_at` 은 접수일, 유효는 그 **다음 거래일**부터

`rcept_dt` 는 `YYYYMMDD`(KST 날짜)이고 **시각 정보가 없습니다.** 장중에 접수됐는지
장 마감 뒤인지 알 수 없으므로 **당일 장중 사용은 근거가 없습니다.**

→ **`known_at` 다음 거래일부터 유효**로 잡습니다.

### 4.2 정정공시 식별 수단 3종 (전부 공식)

| 수단 | 뜻 |
|---|---|
| `report_nm` 접두어 | `[기재정정]` 등 |
| `rm` 에 `'정'` 포함 | 이 문서는 **뒤에 정정되어 대체됨** |
| `last_reprt_at=Y` | 최종본만 |

### 4.3 ⚠️ 한계로 명시할 것

**`fnlttSinglAcntAll` 은 vintage 를 고를 수 없습니다.** 사업연도 + 보고서코드만 받습니다.
**원본 시점 숫자가 필요하면 이 API 로는 불가능**하고 XBRL 원문 파싱이 필요합니다.
→ **1차 범위 밖으로 두고 문서에 적습니다.**

### 4.4 ⚠️ 커버리지 손실을 **지표로 남깁니다**

정정본만 반환되는 종목(에너토크 FY2021 → `known_at` 2024-05-28)은 **과거 구간
백테스트에서 통째로 빠집니다.**

**버리지 말고 셉니다.** 얼마나 빠졌는지가 결론의 신뢰도에 직결됩니다.

## 5. 🔴 DART 는 한도 초과를 HTTP 오류로 주지 않습니다

| 상황 | 응답 |
|---|---|
| 한도 초과 | **HTTP 200** + 본문 `status="020"` |
| 잘못된 키 | **HTTP 200** + 본문 `status="010"` (실측) |

**HTTP 예외만 잡는 코드는 한도 초과를 놓칩니다.** 본문 `status` 를 반드시 봅니다.

> ⚠️ **DART 일 20,000콜 한도는 검증되지 않았습니다.** 공식 문구가 *"일반적으로는
> 20,000건 이상"* 이라며 스스로 *"요청 제한이 다르게 설정된 경우"* 단서를 답니다.
> 2차출처 두 곳은 10,000 이라고 적어 상충합니다.
> → **가정값으로 다루고, 실제 값은 로그인 후 "오픈API 이용현황" 페이지에서 확인합니다.**
