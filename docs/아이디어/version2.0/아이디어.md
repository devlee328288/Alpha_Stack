## 0. 30초 요약

**KOSPI200 이 5거래일 뒤 오를지 내릴지를 맞히는 모델**을 만듭니다. 그런데 이 프로젝트의
진짜 산출물은 모델이 아니라 **그 모델이 진짜인지 판정하는 검증 엔진**입니다.

| 알아 둘 숫자 넷 | | 왜 중요한가 |
|---|---|---|
| **52.64%** | "항상 오른다"고 찍었을 때의 적중률 (개발구간 실측) | 이걸 못 넘으면 모델이 없느니만 못하다 |
| **54.99%** | 홀드아웃 1,217일에서 **유의하게** 이기려면 필요한 적중률 | 53%로 이겼다고 말하면 운과 구별되지 않는다 |
| **51.43%** | 5거래일·왕복 0.05% 의 손익분기 정확도 | 이 아래면 맞혀도 돈을 잃는다 |
| **65.03%** | **1거래일**·왕복 0.23% 의 손익분기 정확도 | 문헌 상한이 55%대다 — **1일은 맞혀도 진다** ([§4](#4-검토했다가-버린-것)) |

즉 **"정확도 62% 달성"** 같은 문장을 우리는 쓸 수 없게 만들어 두는 것이 목표입니다.

## 1. 무엇을 만드는가 — 한 문장

> **KOSPI200 5거래일 방향(상승/횡보/하락)을 예측하고, 그 예측이 우연보다 나은지를
> 거래비용까지 반영해 판정하는 파이프라인.**

예측 대상과 레이블은 닫혀 있습니다 — **시가(t+1) → 시가(t+6), ±1.0% 3분류**
([ADR-AS-0002](../../decisions/0002-예측대상과-레이블.md)).

## 2. 왜 이 문제인가

### 문제: "정확도 62%" 는 아무 말도 하지 않는다

주가 예측 프로젝트는 흔합니다. 그리고 대부분 **정확도 숫자 하나**로 끝납니다.
그 숫자가 답하지 않는 것이 최소 넷입니다.

1. **기준선이 뭔가?** 한국 시장은 상승일이 더 많습니다. 실측으로 "항상 상승"이
   **52.64%** 입니다. 62% 라면 +9.4%p 인데, 유의한지는 별개 문제입니다.
2. **어느 구간인가?** 2020년 3월을 포함했는지로 숫자가 크게 달라집니다.
3. **미래를 봤는가?** 5일 뒤를 맞히는 레이블은 **검증 구간에 5일이 겹칩니다.**
4. **거래비용을 뺐는가?** 5일마다 왕복 0.05%면 연 2.45%입니다.

### 그래서 우리가 하려는 것

**숫자를 내는 것보다, 그 숫자가 거짓말을 못 하게 만드는 것**을 먼저 합니다.
팀 이름이 **적층(Alpha**Stack**)** 인 이유입니다 — 검증 층을 아래에 먼저 깔고
그 위에 모델을 올립니다.

> 💡 취향이 아니라 방어입니다. 데이터 누수는 ML 재현성 실패의 대표 원인이고,
> 한 문헌조사는 **17개 분야 294편**이 누수의 영향을 받았다고 보고합니다.
> **시계열은 그중에서도 특히 취약합니다.**

## 3. 우리가 남과 다른 한 가지

같은 주제와 비교했을 때 우리만 하는 것은 **"먼저 선언하고 나중에 확인하는"** 순서입니다.

| 흔한 순서 | 우리 순서 |
|---|---|
| 모델을 여러 개 돌린다 → 제일 좋은 걸 고른다 → 그 숫자를 보고한다 | **판정 기준을 먼저 적고 봉인한다** → 모델을 만든다 → 봉인을 열어 한 번만 잰다 |

홀드아웃 기간과 성공 기준을 **모델을 만들기 전에** 문서로 박아 커밋했습니다
([ADR-AS-0004](../../decisions/0004-사전등록.md), 커밋 `b2ece0c` — 개봉 로그보다 앞선 시각).
데이터에는 **지문**을 남겼습니다 — 4,097거래일 스냅샷 SHA-256 `885ea3d3…`.

> 🎯 *"그 정확도, 미래 안 봤어요?"* 에 *"이 커밋 시각을 보세요"* 로 답할 수 있는 구조입니다.

## 4. 검토했다가 버린 것

> 이 절이 이 문서의 핵심입니다. **무엇을 했는가보다 왜 이것만 했는가**가 판단의 근거입니다.

| 검토한 것 | 버린 이유 |
|---|---|
| **1거래일 이진 분류** ★ | **손익분기가 65.03%** 인데 문헌 상한이 55%대다. 맞혀도 비용에 진다. 표본이 5배라 검정력은 유리한데, *"유의하지만 돈은 잃는다"* 는 우리가 피하려는 결론이다 → [조사](../../조사/예측지평.md) |
| 개별 종목 예측 | 종목마다 사연이 다르고 상장폐지·유상증자가 섞인다. 지수는 그 잡음이 평균으로 씻기고 **기준선을 명확히 정의할 수 있다** |
| 회귀(수익률 예측) | 방향만 맞혀도 매매 판단이 되고, 회귀는 평가가 어려워진다. ±1.0% 3분류로 **애매한 구간을 명시적으로 분리** |
| 딥러닝 우선 | 4,097 표본에 파라미터 수백만 개는 과적합 기계다. 트리 계열로 기준선을 세운 뒤 **2차 선택 범위**로 |
| 실시간 틱·호가 | 5일 지평에 과잉이고, 저장·처리 비용이 2주를 통째로 먹는다 |
| 클라우드 배포 | 발표에 필요한 것은 도는 화면이지 URL 이 아니다 |
| 감성분석 모델 학습 | 뉴스·커뮤니티는 **과거 데이터를 못 구한다.** 백테스트에 못 쓴다 |

### ★ 1거래일 안을 왜 따로 적나 — 팀원 제안이었습니다

4번째 팀원이 저장소를 이틀 검토하고 **"다음 거래일 상승/하락 이진 분류"** 를 제안했습니다.
**방법론은 거의 전부 채택했습니다.** 갈린 것은 레이블 하나뿐입니다.

| 제안한 것 | 채택 |
|---|---|
| 피처: 1일·5일 수익률, 5일·20일 이동평균 이격, 최근 변동성 | ✅ 그대로 |
| Logistic Regression · RandomForest 기준선 → 확장 | ✅ 그대로 |
| ARIMA 와 같은 워크포워드로 검증 | ✅ 그대로 |
| 정확도 + **F1** | ✅ **채택** — F1 이 요구사항에 없었습니다 |
| **확률보행·ARIMA 와 동기간 방향 적중률 비교** | ✅ **채택** — 기준선 목록에 ARIMA 를 추가합니다 |
| 레이블: 다음 거래일 상승=1 / 하락·보합=0 | ❌ 5거래일 3분류 유지 (위 표) |

> 💡 **제안 덕분에 문서가 나아졌습니다.** F1 과 ARIMA 대조는 우리 요구사항에 없던
> 항목이고, 둘 다 들어갔습니다.

## 5. 무엇을 성공이라 부를 것인가

**이 절은 결과를 보기 전에 쓰였습니다.** 나중에 고치면 그건 다른 문서입니다.

| 판정 | 기준 |
|---|---|
| ✅ **성공** | 홀드아웃 적중률이 **54.99% 이상** — 기준선 52.64%를 유의수준 5%에서 넘는다 |
| ⚠️ **기각 실패** | 52.64% ~ 54.99% — *"이겼다"고 말하지 않는다.* 운과 구별되지 않는 구간 |
| ❌ **실패** | 52.64% 미만 — "항상 상승"보다 못하다 |

> 🔴 **기각 실패도 정직한 결과입니다.** 금융 시계열에서 5일 방향을 유의하게 맞히는 건
> 원래 어렵습니다. 못 이겼을 때 **"왜 못 이겼는지를 잰 것"** 이 산출물이 되도록
> 설계했습니다. 보고 방식은 [강사님께 Q-6](#11-강사님께-여쭙습니다) 으로 여쭙니다.

⚠️ **위 임계는 개발구간 기준선으로 낸 추정치입니다.** 홀드아웃의 실제 "항상 상승"
적중률은 **개봉 시점에 계산**합니다. 봉인 구간의 값을 미리 보고 기준을 맞추면
사전등록이 하는 일이 없어집니다.

## 6. 1차 범위 — 2주에 무엇을 하고 무엇을 미루나

> **v2.0 에서 새로 그은 선입니다.** v1.0 은 기능 30건을 늘어놓았는데, 2주에 다 못 합니다.

### 1차에 하는 것 — Must 18건

```
① 데이터 3건        지수 백필 · 스냅샷 지문 · 품질 게이트
② 검증 엔진 7건 ★   봉인 로더 · 사전등록 · gap 잠금 · 정확도 API · 비용 민감도
                     · 시도 횟수 계측 · 홀드아웃 1회 개봉
③ 피처·레이블 3건   기술적 지표 · 레이블 생성기 · 학습 데이터셋
④ 모델 3건          포지션 변환 · 로지스틱 기준선 · 모델 4종 비교
⑤ 리포트 2건        정적 HTML 5화면 · 단일 명령 재현
```

★ **②가 이 프로젝트의 척추입니다.** 다른 걸 다 못 해도 이건 남깁니다.

### 2차·3차로 미룬 것

| 미룬 것 | 왜 지금이 아닌가 |
|---|---|
| 누수 시연 · 음성 대조군 · 지표 기여도 (Should 5건) | 있으면 발표가 세지지만, 없어도 결론이 선다 |
| [시장 균열 스코어](../../조사/시장균열스코어.md) (F-30) | 조사는 끝났는데 구현이 **2.5~3 인일**. 모델링을 밀어낸다 |
| 딥러닝 비교 · 삼중배리어 · Deflated Sharpe | 기준선이 서기 전에는 비교 대상이 없다 |
| 인터랙티브 대시보드 · 감성 피처 · 350종목 횡단면 | 각각 새 함정을 연다 |

> 📌 **미룬 것도 근거를 남겼습니다.** F-30 은 [조사 문서](../../조사/시장균열스코어.md)에
> 전문이 있고, 거기서 찾은 **라벨 정렬 규칙은 1차에 그대로 적용**됩니다.

## 8. 조사하다 뒤집힌 것

계획대로 안 된 것을 숨기지 않는 편이 낫다고 판단해 적습니다. **넷 다 실제로 확인했고,
넷 다 계획을 바꿨습니다.**

| # | 무엇이 뒤집혔나 | 결과 |
|---|---|---|
| ① | 네이버 **종목토론방**을 쓸 수 있다고 읽었다 | `robots.txt` 원문 확인 — 허용 규칙이 전부 `User-agent: yeti`(네이버 자체 크롤러) 그룹이었다. 제3자 봇은 `Disallow: /` **전면 불허** → 토론방을 접고 카페글 API 만 |
| ② | 네이버 검색 API 를 새로 발급받으면 된다 | **2026-07-30 신규 발급 중단.** 팀에 이전 발급 키가 있어 쓸 수 있지만 **2027-06-30 이 하드 데드라인** → 주소·헤더를 상수로 분리 |
| ③ | 공시 접수일을 접수번호 앞 8자리로 구하면 된다 | 정기공시 **4,800건 중 3건이 어긋났고 그중 둘은 실제보다 3일 이른 방향**이었다. 아직 공개 안 된 정보를 사흘 먼저 아는 셈 → 공시목록 API 조인으로 |
| ④ | 기준선은 **52.72%** 다 | KRX 가 **반올림**해 준 등락률로 센 값이었다. 원값으로 세면 **52.89%**(전구간)·**52.64%**(개발구간). 반올림 기준은 기준선을 낮춰 **우리가 이기기 쉬워지는 방향**이라 바꿨다 |

> 💡 **이 넷이 이 프로젝트에서 제일 값진 부분일 수 있습니다.** 넷 다 *"코드가 도느냐"* 가
> 아니라 *"결론이 진짜냐"* 를 건드렸고, 안 봤으면 그대로 틀린 채 발표했을 것들입니다.

## 10. 팀에 묻습니다

**킥오프에서 한 줄씩만 정해 주시면 됩니다.**

| # | 물음 | 제 의견 |
|---|---|---|
| **T-1** | **팀장**을 누구로 하나 | 제가 정할 수 없는 것입니다 |
| **T-2** | 화면을 **Streamlit** 으로 갈까요, **정적 HTML** 로 갈까요 | 팀 문서는 정적 HTML 로 닫혀 있는데, 수집 현황·버튼 수집은 정적으로 **원리적으로 불가능**합니다. 데이터 파트만 Streamlit 예외를 제안합니다. **대시보드 담당이 강민석이라 같이 정해야 합니다** |
| **T-3** | 뉴스·카페글을 **어느 종목까지** 모을까요 | 한도는 넉넉합니다. 개수가 아니라 **의미**로 정할 문제입니다 |
