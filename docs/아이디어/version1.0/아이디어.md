## 0. 30초 요약

**KOSPI200 이 5거래일 뒤 오를지 내릴지를 맞히는 모델**을 만듭니다. 그런데 이 프로젝트의
진짜 산출물은 모델이 아니라 **그 모델이 진짜인지 판정하는 검증 엔진**입니다.

| 알아 둘 숫자 셋 | | 왜 중요한가 |
|---|---|---|
| **52.72%** | "항상 오른다"고 찍었을 때의 정확도 (실측) | 이걸 못 넘으면 모델이 없느니만 못하다 |
| **55.07%** | 홀드아웃 1,230일에서 **유의하게** 이기려면 필요한 정확도 | 53% 로 이겼다고 말하면 운과 구별되지 않는다 |
| **0.904%** | 하루 등락폭 평균 (실측) | 왕복 거래비용 0.05% 를 넘길 수 있는지의 근거 |

즉 **"정확도 62% 달성"** 같은 문장을 우리는 쓸 수 없게 만들어 두는 것이 목표입니다.

## 1. 무엇을 만드는가 — 한 문장

> **KOSPI200 5거래일 방향(상승/횡보/하락)을 예측하고, 그 예측이 우연보다 나은지를
> 거래비용까지 반영해 판정하는 파이프라인.**

예측 대상과 레이블은 이미 닫혔습니다 — **시가→시가 5거래일, ±1.0% 3분류**
([ADR-AS-0002](../../decisions/0002-예측대상과-레이블.md)).

## 2. 왜 이 문제인가

### 문제: "정확도 62%" 는 아무 말도 하지 않는다

주가 예측 프로젝트는 흔합니다. 그리고 대부분 **정확도 숫자 하나**로 끝납니다.
그 숫자가 답하지 않는 것이 최소 넷입니다.

1. **기준선이 뭔가?** 한국 시장은 상승일이 더 많습니다. 우리 실측으로 "항상 상승"이
   **52.72%** 입니다. 62% 라면 기준선 대비 +9.3%p 인데, 그게 유의한지는 별개 문제입니다.
2. **어느 구간인가?** 2020년 3월을 포함했는지 아닌지로 숫자가 크게 달라집니다.
3. **미래를 봤는가?** 5일 뒤를 맞히는 레이블은 **검증 구간에 5일이 겹칩니다.**
   그 겹침을 안 막으면 정확도가 저절로 올라갑니다.
4. **거래비용을 뺐는가?** 왕복 0.05% 를 5일마다 내면 연 2.5% 입니다.

### 그래서 우리가 하려는 것

**숫자를 내는 것보다, 그 숫자가 거짓말을 못 하게 만드는 것**을 먼저 합니다.
팀 이름이 **적층(Alpha**Stack**)** 인 이유입니다 — 검증 층을 아래에 먼저 깔고
그 위에 모델을 올립니다.

> 💡 이건 취향이 아니라 방어입니다. 데이터 누수는 ML 재현성 실패의 대표 원인이고,
> 한 문헌조사는 **17개 분야 294편**의 논문이 누수의 영향을 받았다고 보고합니다.
> **시계열은 그중에서도 특히 취약합니다.**

## 3. 우리가 남과 다른 한 가지

같은 주제의 프로젝트와 비교했을 때 우리만 하는 것은 **"먼저 선언하고 나중에 확인하는"**
순서입니다.

| 흔한 순서 | 우리 순서 |
|---|---|
| 모델을 여러 개 돌린다 → 제일 좋은 걸 고른다 → 그 숫자를 보고한다 | **판정 기준을 먼저 적고 봉인한다** → 모델을 만든다 → 봉인을 열어 한 번만 잰다 |

홀드아웃 기간과 성공 기준을 **모델을 만들기 전에** 문서로 박아 커밋했습니다
([ADR-AS-0004](../../decisions/0004-사전등록.md), 커밋 `b2ece0c` — 홀드아웃 개봉
로그보다 앞선 시각). 나중에 기준을 옮겨 이겼다고 말할 수 없게 하는 장치입니다.

또 데이터에 **지문**을 남겼습니다 — 4,097거래일 스냅샷의 SHA-256 이
`885ea3d3…` 입니다. 어떤 자료로 낸 결론인지가 파일 하나로 고정됩니다.

> 🎯 **심사자·면접관이 물을 법한 것에 미리 답해 두는 구조**입니다.
> *"그 정확도, 미래 안 봤어요?"* 에 *"이 커밋 시각을 보세요"* 로 답할 수 있습니다.

## 4. 검토했다가 버린 것 — 그리고 왜 버렸나

> 이 절이 이 문서의 핵심입니다. **무엇을 했는가보다 왜 이것만 했는가**가
> 판단의 근거가 되기 때문입니다.

| 검토한 것 | 버린 이유 |
|---|---|
| **개별 종목 예측** (삼성전자 등) | 종목마다 사연이 다르고 상장폐지·유상증자가 섞인다. 지수는 그 잡음이 평균으로 씻긴다. 그리고 **기준선을 명확히 정의할 수 있다** |
| **일간(1일) 예측** | 하루 등락은 0.904% 인데 왕복 비용 0.05% 를 매일 내면 비용이 신호를 먹는다. 5일이면 비용 비중이 1/5 |
| **회귀(수익률 예측)** | 방향만 맞혀도 매매 판단이 되고, 회귀는 평가가 어려워진다. ±1.0% 3분류로 **"애매한 구간"을 명시적으로 분리** |
| **딥러닝 우선 (LSTM/Transformer)** | 4,097개 표본에 파라미터 수백만 개는 과적합 기계다. 트리 계열로 기준선을 세운 뒤 **선택 범위**로 둔다 |
| **실시간 틱·호가 데이터** | 5일 지평에 과잉이고, 저장·처리 비용이 2주 일정을 통째로 먹는다 |
| **클라우드 배포** | 발표에 필요한 것은 도는 화면이지 URL 이 아니다. 로컬로 끝낸다 |
| **감성분석 모델 학습** | 뉴스·커뮤니티는 **과거 데이터를 못 구한다**(§6). 백테스트에 못 쓰므로 1차에서 학습까지 가는 건 낭비 |

## 5. 무엇을 성공이라 부를 것인가 — 미리 못 박습니다

**이 절은 결과를 보기 전에 쓰였습니다.** 나중에 고치면 그건 다른 문서입니다.

| 판정 | 기준 |
|---|---|
| ✅ **성공** | 홀드아웃 정확도가 **55.07% 이상** — 기준선 52.72% 를 유의수준 5%에서 넘는다 |
| ⚠️ **기각 실패** | 52.72% ~ 55.07% — *"이겼다"고 말하지 않는다.* 운과 구별되지 않는 구간 |
| ❌ **실패** | 52.72% 미만 — "항상 상승"보다 못하다 |

> 🔴 **기각 실패도 정직한 결과입니다.** 금융 시계열에서 5일 방향을 유의하게 맞히는 건
> 원래 어렵습니다. 못 이겼을 때 **"왜 못 이겼는지를 잰 것"** 이 이 프로젝트의 산출물이
> 되도록 설계했습니다. 억지로 이긴 척하는 것보다 이쪽이 신뢰를 얻습니다.
>
> 어떻게 보고할지는 [회의안건 C-4](../../회의안건/2026-09-01-킥오프.md)에 열어 뒀습니다.

## 6. 범위 — 하는 것과 안 하는 것

### 하는 것

```

```

| 안 함 | 이유 |
|---|---|
| 클라우드 배포 · 외부 DB 상시 운영 | 로컬 파일로 마무리. 2주에 인프라를 넣으면 본질이 밀린다 |

| 기사 본문 전문 저장 | 저작권. 제목·요약까지만 |
| **종목토론방 수집** | **`robots.txt` 가 제3자 크롤러에게 사이트 전체를 막고 있다** (§7) |
| 코인 | 주식 먼저. 확장 후보 |

## 7. 조사하다 뒤집힌 것 — 정직하게 적습니다

계획대로 안 된 것을 숨기지 않는 편이 낫다고 판단해 적습니다. **셋 다 실제로 확인한
것이고, 셋 다 계획을 바꿨습니다.**

### ① 종목토론방은 못 씁니다

`finance.naver.com/robots.txt` 를 직접 받아 보니, 우리가 허용이라 읽었던
`/item/board.naver?code=*` 규칙이 **전부 `User-agent: yeti`(네이버 자체 크롤러)
그룹 소속**이었습니다. 제3자 봇이 매칭되는 `User-agent: *` 그룹은 `Disallow: /`
한 줄 — **사이트 전체 불허**입니다.

→ 커뮤니티 수집을 **카페글 검색 API 로만** 하고, 토론방은 접었습니다.

### ② 네이버 검색 API 는 신규 발급이 막혔습니다

약관 부칙 제2조: *"2026년 7월 30일 24:00를 기점으로 (…) 신규 이용 신청 접수를 중단"*.
다행히 팀에 그 이전 발급 키가 있어 쓸 수 있지만, **2027-06-30 이 하드 데드라인**입니다.
→ 인증 헤더와 주소를 상수로 분리해 이관이 한 줄 교체가 되도록 짭니다.

### ③ 공시 접수일을 편법으로 구하면 미래를 봅니다

DART 재무제표 응답에는 접수일이 없고 접수번호만 옵니다. 접수번호 앞 8자리를 날짜로
쓰는 관행이 있어 검증해 봤더니 — **정기공시 4,800건 중 3건(0.062%)이 어긋났고,
그중 둘은 실제 접수일보다 3일 이른 방향**이었습니다. 즉 아직 공개 안 된 정보를
사흘 먼저 아는 셈입니다.

→ 편법을 버리고 공시목록 API 와 조인하는 정공법을 씁니다(회사당 1회 호출).

> 💡 **이 세 건이 이 프로젝트에서 제일 값진 부분일 수 있습니다.** 셋 다
> *"코드가 돌아가느냐"* 가 아니라 *"결론이 진짜냐"* 를 건드리는 문제였고,
> 안 봤으면 그대로 틀린 채 발표했을 것들입니다.

## 9. 팀에 묻습니다 — 합의가 필요한 것

제가 정할 수 없는 것들입니다. **킥오프에서 한 줄씩만 정해 주시면 됩니다.**

| # | 물음 | 제 의견 |
|---|---|---|
| **T-1** | `features/`·`models/` 를 **누가** 맡나 | 가장 급합니다. 9/8부터 이 자리가 비면 일정이 통째로 밀립니다 |
| **T-2** | 화면을 **Streamlit** 으로 갈까요, **정적 HTML** 로 갈까요 | 팀 문서는 정적 HTML 로 닫아 뒀는데, 수집 현황·버튼 수집은 정적으로 **원리적으로 불가능**합니다. 데이터 파트만 Streamlit 예외를 제안합니다 |
| **T-3** | 뉴스·카페글을 **어느 종목까지** 모을까요 | 한도는 넉넉합니다. 개수가 아니라 **의미**로 정할 문제라 팀 판단이 필요합니다 |
| **T-4** | 제 산출물을 **언제 인수**하시겠습니까 | **9/7** 을 목표로 잡고 있습니다. 그날 공급 API 를 열겠습니다 |
| **T-5** | 발표 시연은 **누가** 하나 | 화면을 만든 사람이 하는 게 자연스럽지만, 팀장 정해진 뒤에 |

> 📌 **제 파트는 이미 정해져 있습니다** — 데이터 수집·전처리·정제·크롤링 + 화면.
> 위 다섯은 **제 파트 밖**이라 여쭙는 것입니다.
