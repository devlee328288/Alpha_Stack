## 1. 배당 — v4.1 이 미룬 축을 받았습니다

### 1.1 무엇이 들어왔나

```
python scripts/fetch_data_go_kr.py --dividend      # 72콜 · 71,681행
```

| | |
|---|---|
| 전량 | **71,681행** · 기준일 1985-12-31 ~ 2026-11-23 · ISIN 6,251 |
| 2010년 이후 현금·동시배당 | 25,745행 |
| 그중 우리 종목에 붙은 것 | **21,583 (83.8%)** — KOSPI 12,650 · KOSDAQ 9,196 |
| 배당락일을 계산한 것 | **25,724 (99.9%)** |
| 금액이 있는 것 | 22,421 (87.1%) — **2018년 이후는 98% 넘음** |

**콜이 72 인 이유** — `basDt` 가 이벤트 날짜가 아니라 **적재일**입니다(전량이 `20260908`).
날짜별로 훑으면 같은 자료를 날마다 다시 받습니다. **빼고 부르면 한 번에 전량**입니다.
시세처럼 4,000일을 도는 수집과 자릿수가 다릅니다.

### 1.2 🔴 배당기준일은 거의 거래일이 아닙니다

```
기준일이 거래일인 비율   15.2%
12월 기준일 중 거래일     0.3%
```

12월 결산법인의 기준일은 12월 31일인데 그날은 휴장입니다. 값이 실제로 움직이는 날은
**배당락일**이고, 결제(T+2) 때문에 기준일에서 **거래일 두 걸음** 앞입니다.

```
ex_date = prev_session(prev_session(기준일, inclusive=True))

2023-12-31(기준) → 12-28(폐장) → 12-27 배당락    ← 실제와 일치
2024-06-30(기준) → 06-28       → 06-27 배당락
```

안쪽이 *"기준일까지 마지막으로 열린 날"*, 바깥이 *"그 하루 앞"* 입니다. 두 걸음인 이유는
기준일 주주명부에 오르려면 마지막 거래일까지 **결제가 끝나야** 하기 때문입니다.

`common/trading_calendar.py` 에 `prev_session` 을 더했습니다 — `next_session` 의 거울인데
없었습니다. **날짜 계산으로는 못 맞힙니다**(12-31 − 3일 = 12-28 은 폐장일).

이 값은 **계산값**이므로 행마다 `ex_date_rule` 을 남깁니다. 거시(`macro_series.known_at`)와
같은 성질입니다 — 규칙을 바꾸면 어느 행이 옛 규칙인지 알 수 있어야 합니다.

### 1.3 검증 — 계산이 아니라 **가격**으로

검사와 대상이 같은 계산을 공유하면 초록은 증거가 아닙니다(2026-09-08 TIL). 규칙은 달력만
보고 만들었고, 판정은 가격만 봤습니다. 2010년 이후 · 현금·동시배당 · 금액 있는 20,245건.

| 후보 | 행 | 평균 일간수익률 | 전체(+0.8178%) 대비 |
|---|---:|---:|---:|
| **① 두 걸음 (우리 규칙)** | 20,245 | **−0.6486%** | **−1.4665%p** |
| ② 한 걸음 | 20,248 | +0.1901% | −0.6277%p |
| ③ 기준일 당일 | 2,633 | −0.6369% | −1.4548%p |

**전후 하루씩** 더 보면 우리 날이 가장 깊습니다.

```
배당락 이틀 전   -0.6845%p
배당락 전날      -0.7121%p
배당락일 (우리)  -1.4527%p   ← 가장 깊다
배당락 다음날    -0.6269%p
```

기준일이 거래일인 부분집합 2,631건에서는 더 뚜렷합니다 — 우리 날 **−2.5988%p**,
기준일 당일 −1.4664%p.

**하락 폭이 배당수익률에 비례하는가** — 규칙이 맞다면 그래야 합니다.

```
기울기 -0.7818  (완전 반영이면 -1.0)  ·  R² 0.1654  ·  p ≈ 0  ·  n 20,240
```

| 배당수익률 | 건수 | 배당락일 평균 수익률 | 설명 비율 |
|---|---:|---:|---:|
| ~1% | 5,725 | +0.465% | 57.5% |
| 1~2% | 6,302 | −0.066% | 60.7% |
| 2~3% | 3,735 | −0.799% | 65.7% |
| 3~5% | 3,302 | −2.095% | 76.6% |
| 5~10% | 1,117 | −4.278% | 81.9% |

배당이 클수록 더 정확히 반영됩니다. 완전 반영(−1.0)이 아닌 것은 표준적인 관측입니다 —
배당소득세와 배당락 이후 되돌림 때문입니다.

### 1.6 남은 것 — `adj_close_tr`

이 표가 총수익 축의 **재료**입니다. 아직 만들지 않았습니다.

```
r_t  = (adj_close_t + adj_dividend_t) / adj_close_{t-1} − 1
adj_close_tr = 누적곱
```

배당도 가격과 **같은 배율로 조정**해야 합니다. 그리고 반출 칸이 늘면 따라오는 곳이
**다섯**입니다 — `COLUMN_NOTES` · `EXPORT_DAILY_COLUMNS` · `verify_hf_dataset.
_attach_export_derived` · `run_stock_model_experiment.DAILY_COLUMNS` ·
`PANEL_CACHE_CODE_PATHS`. 한 곳이라도 빠지면 조용히 틀립니다(09-05·09-08·09-09 세 번
겪었습니다). 그래서 다음 세션의 독립 작업으로 둡니다.

**`adj_close_tr` 은 성과 축(라벨용)이지 피처가 아닙니다.** 배당 확정 시점(주총)이
배당락일보다 뒤라, 피처로 쓰면 미래참조입니다.

## 2. 전처리 — 후보 다섯을 돌려 **전부 기각**했습니다

[전처리 v1.2](../../전처리/version1.2/전처리-설계-명세서.md) 가 설계한 넷에, 사전 등록된
조건부 후보 A′ 가 걸려 다섯이 됐습니다.

### 2.1 결과 (조합 K · LogisticRegression · 12폴드 · 공통 표본 151,555행)

| 조건 | 칸 | 기준선 대비 | 원값 대비 | 이긴 폴드 | p |
|---|---:|---:|---:|---:|---:|
| D 변동성 축 원값 | 14 | **+1.47%p** | +0.15%p | 7/12 | 0.535 |
| **raw** | 14 | +1.32%p | — | — | — |
| A′ winsorize (변동성 제외) | 14 | +1.32%p | +0.00%p | 5/12 | 0.985 |

### 2.2 🔴 두 번 틀렸습니다

**① B 가 표본을 줄입니다.** v1.2 에 *"준비구간 60 은 `hv_regime` 269 안이라 표본이 안
줄어든다"* 라고 적었는데 틀렸습니다. 이 패널은 전 종목 일별 표가 아니라 **후보군 패널**이라
종목마다 행이 드문드문 있고, `rolling` 창은 달력이 아니라 **행**을 셉니다 — 8,345행(5.22%)이
빕니다.

**② "가장 유력" 이라던 B 가 유의하게 가장 나빴습니다.** 종목별 평균 차이를 *"라벨과 무관한
종목 고정효과"* 라고 이름 붙이고 확인하지 않았습니다.

```
종목 평균 hv_20 ↔ 그 종목의 비중립 비율    Spearman rho = 0.9413 · p = 6.5e-50 (104종)
```

**종목 수준도 라벨과 이어져 있었습니다.**

### 2.3 🆕 표본 5% 가 원값의 우위를 절반으로 만듭니다

공통 표본을 쓰면서 드러난 것입니다.

고 말할 때 그 여유가 얼마나 얇은지**를 보여줍니다. 전처리와 무관하게 기록해 둘 값이 있습니다.

## 4. README 구성도 — GitLab 에서만 깨지던 것

GitLab 미러에서만 시스템 구성도가 깨졌습니다. 원인은 한글 경로도 파일 누락도 아니었습니다.

> **GitLab 은 마크다운 이미지·링크 문법의 상대경로만 저장소 경로로 리라이트하고, raw HTML
> `<img src="상대경로">` 는 손대지 않은 채 이미지 프록시로 넘깁니다.** 프록시가 상대경로를
> 해석하지 못해 404 입니다.

렌더 결과는 `/-/blob/main/README.md?format=json&viewer=rich` 로 실제 HTML 을 받아
확인했습니다(프로젝트 페이지 HTML 은 Vue 라 `<img>` 가 안 들어 있습니다).

**결정 — GitHub raw 절대 URL** (실측 200 OK · image/png · 501,556 bytes).
