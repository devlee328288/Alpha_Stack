[변경사항](변경사항.md)에 있습니다.

## 0. 이 파트가 끝나면 팀원이 할 수 있는 것

| 누가 | 무엇을 | 어떻게 |
|---|---|---|
| 오준영 (모델) | 학습 표를 받아 쓴다 | HF `alphastack-krx-dev` 에서 `hf_hub_download()` 한 줄 |
| 오준영 (모델) | 재무를 시점 정합으로 붙인다 | HF `alphastack-dart` 의 **pit/** 층 (시점은 `rcept_dt`) |
| 강민석 (백테스팅) | 봉인 구간이 반출물에 없음을 믿는다 | `verify_no_holdout` 이 전 파일을 전수 재검사한다 |
| 신장환 (피처) | 지표 함수에 넣을 표의 모양을 안다 | 계약 테스트가 컬럼·정렬·dtype 을 고정한다 |
| 팀 전체 | 손으로 받은 CSV 를 안전하게 들인다 | 반입 엔진이 규격으로 판정하고 보고서를 준다 |
| 팀 전체 | 발표 때 "이 숫자 어디서 났나"에 답한다 | 수집 대장 + 실행 기록 + MANIFEST 해시 |

각 기능의 줄 단위 해설은 **[핵심코드 v1.0](../../핵심코드/version1.0/)** 에
있습니다 (①수집 ②반입 ③공급 ④반출·HF). 이 문서는 전체 지도를 그립니다.

## 1. 하루를 따라가 보기

### 아침 — 어제 자료가 잘 들어왔나

```bash
python scripts/check_db.py        # 표 16개의 행 수·기간 한 장
python scripts/check_data.py      # 시세 품질 게이트 (설명되지 않는 이상치 = exit 1)
```

수집을 다시 돌려도 안전합니다 — 대장(`collect_log`)이 이미 받은 날짜를 건너뛰고,
예산(`call_budget`)이 한도 앞에서 멈춥니다.

### 수집 — 한 명령으로

```bash
python -m ingest                  # 시세·지수·거시를 순서대로, 실행 기록을 남기며
```

실행 하나가 `ingest_run` 한 행이고 출처별 단계가 `ingest_run_stage` 에 남습니다.
**밖에서(화면·API) "지금 도는 중인가"를 볼 수 있게** 만든 표입니다 (v8).

### 오전 — 팀원이 자료를 쓴다

```python
from supply import index_series
df = index_series(as_of="2026-09-01")   # as_of 를 빼면 그 자리에서 터진다
```

모델 학습용 대량 자료는 supply 가 아니라 **HF 배포본**으로 받습니다 —
DB(1,650 MB)는 공유하지 않고, 개발구간만 잘린 반출물을 공유합니다.

### 팀원이 파일을 보내온다

`data/inbox/` 에 넣고 반입 엔진을 돌리면 규격 판정 → 합격/격리 → 사람이 읽는
보고서(`reports/inbox/<날짜>/`)까지 나옵니다. 원본 파일은 **검증이 끝난 뒤에만**
지웁니다. 받는 방법 자체는 가이드 두 벌이 있습니다 —
[자동수집 가이드](../version2.3/자동수집_가이드.md)(API 로 받는 법) ·
[직접수집 가이드](../version2.4/직접수집_가이드.md)(브라우저로 받는 법 · cp949 처리).

## 3. HF 배포 체계 — 파일은 HF 에, 방법은 저장소에

레포 둘, 층 둘입니다 (2026-09-02 실측).

| 레포 | 내용 | 구조 |
|---|---|---|
| `qurious-quant/alphastack-krx-dev` | KRX 시세 개발구간 반출 | 🔴 **반드시 private** (KRX 약관 제11조 ②) |
| `qurious-quant/alphastack-dart` | DART 재무 | **bulk/ 44파일**(접수일 없음 · 학습 금지 · 탐색용) + **pit/ 11파일**(662,933행 · 접수일 포함 · 학습은 이것만) |

- 학습 재무는 **pit/ 만** 씁니다. 시점은 `rcept_dt`(접수일) — 결산기준일로 붙이면
  아직 공시 안 된 값이 붙습니다(미래 누출, 실측: 핵심코드 ② 참조 노트북).
- 재배포는 세 경우뿐 — ①홀드아웃 경계 이동(#63·PR #71) ②개발구간 값 변경(#51)
  ③반출 규격 변경. **새 시세만으로는 안 올립니다.**
- PR #71(홀드아웃 20240901) 머지 시 개발구간이 5,989,308 → 7,888,945행(+31.7%)으로
  늘어 재배포가 필요해집니다. **v9(수정주가) 적재와 묶어 1회로** 올립니다.
- 팀원이 못 받으면 `scripts/check_hf_access.py` — `repo_type` 누락과 경로 접두사
  누락이 둘 다 404 로 같게 보입니다.

## 4. 데이터 사전

**[ERD v2.0](../../erd/version2.0/ERD.md) 으로 옮겼습니다** — 표 16개 전수를
`PRAGMA` 실측으로 그린 판입니다. 여기는 함정 요약만 남깁니다.

- 🔴 `daily_price` 의 가격은 **수정주가가 아닙니다** (#51). `close` 로 수익률을
  계산하면 삼성전자 분할일이 −98% 로 읽힙니다. v9 의 `adj_*` 4칸을 기다리세요.
- `code` 는 여섯 자리 **숫자가 아닙니다** — 5·6번째 자리에 영문 84종 (PR #40).
- `dart_financial` 을 직접 집계할 때 기본키에 `account_detail` 이 필수입니다 —
  빼면 자본변동표 6.4%(22,436행)가 조용히 사라집니다.
- `macro_series.known_at` 은 **계산값**입니다 (ECOS 가 발표일을 안 줌).
- CSV 는 float64 를 온전히 담지 못합니다 — 큰 수(시가총액)는 1 ULP 어긋나고
  빈 문자열이 NaN 이 됩니다. **팀원에게는 parquet 을 권합니다.**

## 8. 용어집

| 말 | 뜻 |
|---|---|
| `as_of` | "언제 시점에서 본 자료인가". 이 값보다 뒤의 자료는 안 준다 |
| `known_at` | 그 자료를 **알 수 있었던 시각**. 시세는 T+1 0시(계산) · 재무는 접수일(기록) · 거시는 발표 규칙(계산) |
| pit / bulk | HF 재무의 두 층 — pit 은 접수일이 있어 학습 가능, bulk 는 없어서 탐색만 |
| 반입 / 반출 | 남이 준 파일을 들이는 것 / 팀원에게 내보내는 것 |
| 봉인 구간 | 최종 검증 전까지 열지 않는 홀드아웃. 경계 정본은 `evaluation/horizon.py` |
| 1 ULP | float64 의 마지막 비트 하나. CSV 왕복 표기 한계의 단위 |
