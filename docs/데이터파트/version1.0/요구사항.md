## 0. 읽는 법

| 표시 | 뜻 |
|---|---|
| **Must** | 2주 안에 반드시. 이게 없으면 뒤 순번 팀원이 못 움직인다 |
| **Should** | 있으면 확실히 좋아진다. Must 가 닫힌 뒤 착수 |
| **Could** | 여유가 있으면. 9/8 중간 점검에서 한 번만 채택 여부를 정한다 |
| **Won't** | 1차에서 안 한다 |

**수용 기준은 전부 검증 가능해야 합니다.** *"잘 수집된다"* 는 기준이 아닙니다.

## 1. 🔴 모든 수집에 공통으로 적용되는 규칙

> **이 절이 개별 기능보다 먼저 옵니다.** 여기서 어긋나면 아래를 아무리 잘 만들어도
> 뒤 순번 팀원의 결론이 틀어집니다.

### D-00 · Point-in-Time 원칙 — **Must**

모든 저장 테이블은 **두 개의 시각**을 갖습니다.

| 칸 | 뜻 | 예 |
|---|---|---|
| `event_at` | 그 일이 **일어난** 시각 | 사업연도 종료 `2020-12-31` |
| `known_at` | 우리가 그것을 **알 수 있게 된** 시각 | 공시 접수 `2021-03-20` |

**모든 조회 API 는 `known_at` 기준으로 자릅니다.**

```python
# ✅ 이렇게만 꺼낼 수 있다
fetch(as_of="2021-01-15")   # known_at <= 2021-01-15 인 행만
# ❌ 이런 함수는 만들지 않는다
fetch_all()                 # 미래를 섞어 돌려준다
```

**수용 기준**
- 공시·보고서 계열 테이블에 `known_at` 이 `NULL` 인 행이 **0건**. 적재 시 거부하고 예외
- 조회 함수에 `as_of` 인자가 **없는 공개 함수가 하나도 없다** (grep 으로 확인)
- `as_of` 를 과거로 주면 그 시점 이후 적재분이 **결과에서 빠지는 것**을 테스트로 확인

> ⚠️ [F-09](../../요구사항/version1.0/요구사항.md)가 `walk_forward` 에서 막은 누수와
> **같은 오류를 한 계층 아래에서** 저지르는 것을 막는 장치입니다.

### D-01 · 원본 보존 · 정규화 분리 — **Must**

받은 응답을 **손대기 전에 그대로** 남기고, 정규화는 별도 단계로 둡니다.

**수용 기준**: 정규화 로직을 고친 뒤 **원본만으로 재정규화**해 같은 결과가 나온다
(외부 재호출 없이). 즉 `raw → normalized` 가 순수 함수다.

### D-02 · 수집 로그 · 워터마크 — **Must**

*"어디까지 받았나"* 를 코드가 압니다. `watermark` 테이블은 스키마만 있고
**코드가 없는 상태**입니다(알려진 부채) — 이걸 닫습니다.

**수용 기준**
- 대상별 `last_success_at` · `last_attempted_at` · `cursor` 가 기록된다
- 중간에 죽여도 다시 돌리면 **이어서** 받는다 (같은 구간을 다시 받지 않는다)
- **0건 응답과 미수집을 구별한다** — "받아 봤더니 없었다"(휴장)는 공백이 아니다
  (KRX 수집에서 이미 쓰는 방식)

### D-03 · `robots.txt` 실행 시점 확인 — **Must**

크롤링 계열은 **요청 직전에** 허용 여부를 확인하고, 불허면 요청 자체를 하지 않습니다.

**수용 기준**
- 금지 경로(`/item/board.naver?code=*&page=*`)를 요청하면 **네트워크 호출 전에 예외**
- `robots.txt` 는 캐시하되 **24시간 넘으면 다시 받는다**
- 테스트가 금지 경로로 예외를 확인한다 (실제 호출 없이)

### D-04 · 호출 예산 관리 — **Must**

출처별 일 한도를 코드가 알고, 넘기 전에 멈춥니다.

| 출처 | 한도 | 근거 |
|---|---|---|
| KRX | 10,000콜/일 | [시장조사 §1](시장조사.md) |
| 네이버 검색 | 25,000콜/일 (**전 코퍼스 합산**) | [시장조사 §3](시장조사.md) |
| YouTube `search.list` | **100콜/일** | [시장조사 §4](시장조사.md) |
| YouTube 그 외 | 10,000유닛/일 | 〃 |

**수용 기준**
- 예산의 **80% 도달 시 경고 로그**, 100% 도달 시 그날 수집 중단 (예외 아님 — 정상 종료)
- 쿼터 초과 응답(`429`·`errorCode 010`)을 받으면 **재시도하지 않는다.** 재시도 루프 금지
- 하루 사용량이 `reports/quota_usage.json` 에 남는다

> 🔬 **KRX 는 동시 호출 시 `429` 가 아니라 `401` 을 반환합니다**(실측).
> 인증 실패로 위장돼 오므로 재시도 로직이 오판하기 쉽습니다. 지수 수집 워커는 **1 고정**.

| ID | 기능 | 수용 기준 |

> 🔴 **D-20~D-23 은 백테스트에 쓸 수 없습니다.** 네이버 API 는 1,000건 창,

> **수용 기준에 포함**: 이 4종 테이블을 조회하는 함수가 `2026-09-01` 이전 구간을
> 요청받으면 **빈 결과와 함께 경고**를 남긴다. 조용히 빈 배열을 주지 않는다.

## 8. 품질 게이트 — `reports/data_quality.json` 의 항목

> 팀 요구사항 F-03 이 *"리포트의 항목이 정의돼 있지 않다"* 고 지적한 것을 여기서 못 박습니다.

| 항목 | 내용 |
|---|---|
| `coverage` | 출처별 (시작일, 종료일, 거래일 수, 기대 거래일 수) |
| `missing_dates` | **날짜 배열.** 개수만 적지 않는다 |
| `zero_row_days` | "받아 봤더니 0건"인 날 — 공백이 아니다 |
| `duplicates` | (테이블, 키, 건수) |
| `null_violations` | `known_at` 이 비어 적재 거부된 건수 |
| `ohlc_violations` | `low <= open,close <= high` 위반 행 |
| `outliers` | 일 변동 ±30% 초과 등. **버리지 않고 열거만** 한다 |
| `quota_usage` | 출처별 (사용, 한도, 비율) |
| `generated_at_kst` | 생성 시각 |

**`exit 1` 조건**: `missing_dates` 가 비어 있지 않은데 **열거되지 않은 경우**,
또는 `null_violations > 0`.

> ⚠️ **이상치를 자동으로 버리지 않습니다.** 2020-03 코로나 급락은 이상치처럼 보이지만
> 실제 사건입니다. 버리면 우리가 만든 자료가 현실과 달라집니다. **열거하고 사람이 봅니다.**
