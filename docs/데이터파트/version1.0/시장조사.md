## 2. 크롤링 대상의 `robots.txt` — 원문 그대로

> **2차 자료를 믿지 않고 직접 받았습니다.** 아래는 2026-08-26 응답 원문입니다.

### 2.1 `finance.naver.com/robots.txt` (HTTP 200)

```
User-agent: *
Disallow: /
User-agent: yeti
Disallow: /
Allow: /sise/
Allow: /research/
Allow: /marketindex/
Allow: /fund/
Allow: /template/head_js.naver
Allow: /world/
Allow: /item/board.naver?code=*
Disallow: /item/board.naver?code=*&page=*
Disallow : /fund/news/
Disallow : /marketindex/news/
```

**읽는 법**

| 경로 | 판정 | 뜻 |
|---|---|---|
| `/item/board.naver?code=005930` | ✅ **허용** | 종목토론방 **첫 페이지** |
| `/item/board.naver?code=005930&page=2` | ❌ **금지** | **페이지 넘기기 금지** |
| `/sise/`, `/research/`, `/marketindex/`, `/world/` | ✅ 허용 | 시세 · 리서치 · 시장지표 |
| `/fund/news/`, `/marketindex/news/` | ❌ 금지 | 뉴스 하위 |
| 그 외 전부 | ❌ 금지 | `Disallow: /` 가 기본값 |

### 2.2 `m.stock.naver.com/robots.txt` (HTTP 200)

```
User-agent: *
Disallow: /
User-agent: yeti
Disallow: /
Allow: /$
Allow: /domestic/stock/*/discussion$
Allow: /domestic/fund/
```

`$` 는 **경로 끝 일치**입니다. `/domestic/stock/005930/discussion` 은 허용,
그 뒤에 쿼리나 하위 경로가 붙으면 허용 범위 밖입니다.

### 2.3 🔴 이 두 파일이 설계를 정한다

> **과거를 소급해 긁는 길은 막혀 있고, 오늘 것을 쌓는 길은 열려 있다.**

그래서 커뮤니티 데이터는 **백필하지 않고 누적**합니다.

```
✅ 하는 것   매일 1회, 종목별 토론방 1페이지를 떠서 새 글만 적재 (앞으로 쌓기)
❌ 안 하는 것 page=2..N 을 돌며 과거를 소급 (robots.txt 금지)
```

**부작용을 정직하게 적습니다** — 이 방식은 **수집 시작일 이전 데이터가 영원히 없습니다.**
9/1에 시작하면 8월 이전 토론방 자료는 못 씁니다. 즉 커뮤니티 피처는
**1차 프로젝트의 백테스트 구간(2010~2026)에 쓸 수 없습니다.**
쓸 수 있는 것은 *"지금부터 앞으로"* 뿐이고, 그건 **시연용이지 검증용이 아닙니다.**

이 사실을 숨기지 않고 요구사항의 수용 기준에 못 박습니다.

### 2.4 기타

| 대상 | 확인 결과 |
|---|---|
| `opendart.fss.or.kr/robots.txt` | `robots.txt` 가 아니라 **HTML 페이지**를 반환 (404 대신 안내문). 공식 API 를 쓰므로 무관 |
| `data.krx.co.kr/robots.txt` | **HTTP 404**. 공식 Open API 를 쓰므로 무관 |

## 3. 뉴스 · 커뮤니티 — 네이버 검색 API

**출처**: [developers.naver.com 검색 > 뉴스](https://developers.naver.com/docs/serviceapi/search/news/news.md)

| 항목 | 값 |
|---|---|
| 일 호출 한도 | **25,000회** — ⚠️ **뉴스·카페글·블로그 등 전 코퍼스 합산** |
| 인증 | 비로그인 방식. `X-Naver-Client-Id` · `X-Naver-Client-Secret` 헤더 |
| 한 번에 | `display` 최대 100건 |
| 페이징 | `start` 최대 1,000 — **`start + display - 1 > 1000` 이면 400** |
| 정렬 | `sim`(관련도) · `date`(최신) |
| 쿼터 초과 | `429` + `errorCode: 010`. **재시도 루프 금지** |
| 권한 오류 | `403` — 개발자 센터에서 "검색" API 를 애플리케이션에 추가하지 않은 경우 |

### 3.1 🔴 1,000건 창(window)이 뜻하는 것

**검색어 하나로 과거를 무한정 거슬러 갈 수 없습니다.** 최대 1,000건입니다.
인기 종목의 뉴스는 며칠이면 1,000건을 넘습니다 → **뉴스도 백필이 아니라 누적**입니다.

커뮤니티(카페글)도 같은 API·같은 쿼터·같은 1,000건 창을 씁니다.

### 3.2 호출 수 계산 — D-1(대상 종목 범위)의 근거

`display=100` 기준, 종목당 하루 1페이지만 받는다고 하면:

| 대상 범위 | 뉴스 | 카페글 | 합계/일 | 25,000 대비 |
|---|---|---|---|---|
| KOSPI200 **전체 200종목** | 200 | 200 | **400콜** | 1.6% |
| 200종목 × 각 3페이지 | 600 | 600 | **1,200콜** | 4.8% |
| 200종목 × 각 10페이지 | 2,000 | 2,000 | **4,000콜** | 16% |

**여유가 큽니다.** 한도가 병목이 아니라 **1,000건 창과 저장·정제 비용**이 병목입니다.
따라서 D-1 은 "한도 때문에" 줄일 이유가 없고, **의미 있는 종목을 고르는 문제**입니다.

### 3.3 지켜야 할 것

- 기사 **제목·요약·링크·발행시각**만 저장합니다. **본문 전문은 저장·재배포하지 않습니다.**
- 응답의 `<b>` 하이라이트 태그와 HTML entity 를 제거해 저장합니다.
- 실패 응답을 캐시하지 않습니다 (다음 요청이 온전히 다시 타야 합니다).

## 4. 동영상 — YouTube Data API v3

**출처**: [Google 공식 — Quota and Compliance Audits](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits)

> "Projects that enable the YouTube Data API have a default quota allocation of
> **100 `search.list` calls, 100 `videos.insert` calls, and 10,000 units per day**
> combined for all other endpoints."

### 4.1 2026-06-01 개편으로 병목이 바뀌었습니다

| | 개편 전 | **개편 후 (현재)** |
|---|---|---|
| `search.list` | 100유닛 × 공용 10,000풀 → 하루 100콜 | **전용 버킷, 하루 100콜** |
| 그 외 (`videos.list`·`playlistItems.list` 등) | 공용 풀 | **공용 10,000유닛** |

숫자는 비슷해 보이지만 **의미가 다릅니다** — 이제 검색을 안 쓰면 나머지 1만 유닛이
통째로 남습니다.

### 4.2 🔬 그래서 검색을 쓰지 않는 설계로 갑니다

```
❌ 나쁜 설계   search.list 로 매일 키워드 검색      → 하루 100콜에서 즉사
✅ 좋은 설계   채널 → uploads 재생목록 → playlistItems.list
               playlistItems.list = 1유닛 · 50건/페이지
```

| 방식 | 하루 가능량 |
|---|---|
| `search.list` | **100콜** (≈ 100 키워드) |
| `playlistItems.list` | **≈10,000콜** → 채널 수백 개를 매일 훑고도 남는다 |

**대신 채널 목록을 사람이 정해야 합니다** → 문제정의 **D-3**.

⚠️ **잘못된 요청도 쿼터를 씁니다** (최소 1유닛). 재시도 루프를 돌리지 않습니다.
⚠️ `part` 를 늘리면 비용이 올라갑니다. 필요한 part 만 요청합니다.

## 6. 대시보드 벤치마킹

### 6.1 무엇을 베낄 것인가

| 참고 | 베낄 것 | 안 베낄 것 |
|---|---|---|
| 네이버 금융 종목 화면 | 지수 요약 → 차트 → 종목표 **한 화면 3단** 구성 | 광고 · 과밀한 정보 밀도 |
| TradingView | 캔들 + 거래량 **이중 축**, 기간 토글 | 지표 수십 개 |
| Airflow / dbt 의 상태 화면 | **"무엇이 언제 성공/실패했나"** 를 표 하나로 | 스케줄러 자체 |

> 🔴 **우리 화면의 1순위는 예쁜 차트가 아니라 "수집 현황과 공백"입니다.**
> 팀 합의가 *"외관보다 내부 로직"* 이므로, 화면도 **내부 로직을 드러내는 화면**이어야
> 일관됩니다. 코스피 차트는 그다음입니다.

### 6.2 Streamlit 으로 "안 예쁜" 문제 풀기

**우려는 타당합니다.** 기본 Streamlit 은 한눈에 Streamlit 인 게 보입니다.
다만 지금 Streamlit 의 테마 시스템은 예전보다 훨씬 넓습니다
([공식 문서 — config.toml](https://docs.streamlit.io/develop/api-reference/configuration/config.toml)).

| 손댈 수 있는 것 | 설정 키 |
|---|---|
| 색 | `primaryColor` · `backgroundColor` · `secondaryBackgroundColor` · `textColor` · `linkColor` |
| **글꼴** | `font` · **`headingFont`** · `codeFont` — **폰트 파일을 `static/` 에 넣어 직접 지정 가능** |
| **모서리** | **`baseRadius`** · `buttonRadius` |
| **테두리** | **`borderColor`** · **`showWidgetBorder`** |
| 글자 크기·굵기 | `baseFontSize` · `headingFontSizes` · `headingFontWeights` |
| **사이드바 별도 테마** | **`[theme.sidebar]`** 블록 |

그리고 컴포넌트가 `--st-primary-color` 같은 **CSS 커스텀 프로퍼티**를 노출하므로,
주입한 CSS 가 테마와 따로 놀지 않습니다.

**우리 계획**

1. `.streamlit/config.toml` 에 팔레트·글꼴·라운드·테두리를 **디자인 토큰처럼** 정의
2. 한글 본문용 웹폰트(Pretendard 계열)를 `static/` 에 넣어 `font` 로 지정
   — 기본 산세리프의 한글 렌더링이 이 화면의 "싸 보임" 원인 중 큰 몫입니다
3. 숫자는 **탭ular(고정폭) 숫자**로 — 표에서 자릿수가 흔들리면 즉시 아마추어로 보입니다
4. 차트는 기본 `st.line_chart` 대신 색·축·툴팁을 지정한 Plotly/Altair
5. 상승 빨강 / 하락 파랑 — **한국 관행**을 따릅니다 (미국과 반대)

> 📌 구현 시점에는 `developing-with-streamlit` 스킬을 씁니다 — 설치된 Streamlit 버전에
> 맞는 레퍼런스를 불러오므로 문서와 실제 버전이 어긋나지 않습니다.

## 7. 이 조사가 요구사항에 미치는 결론

| # | 결론 | 근거 |
|---|---|---|
| 1 | 시세·통계·공시는 **클라이언트가 이미 있다.** 새로 만들 것은 스케줄러·품질 게이트·공급 API | §1 |
| 2 | 뉴스·커뮤니티·동영상은 **과거 소급이 불가능**하다. 백필이 아니라 **누적** | §2.3 · §3.1 |
| 3 | 그래서 이 3종은 **1차 백테스트에 쓸 수 없다.** 시연·2차 확장용이라고 못 박는다 | §2.3 |
| 4 | 종목토론방은 **1페이지만** 허용된다. 코드가 실행 시점에 `robots.txt` 를 확인한다 | §2.1 |
| 5 | 동영상은 **`search.list` 를 쓰지 않는다.** 채널 고정 + `playlistItems.list` | §4.2 |
| 6 | 네이버 API 한도는 병목이 아니다. 대상 범위는 **의미로** 정한다 | §3.2 |
| 7 | 빅카인즈는 신청만 해 두고 1차 범위 밖 | §5 |
