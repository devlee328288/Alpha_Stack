## 0. 공공데이터포털 v10 — 다리를 실제로 놓았다

저장소 · CLI · 검증기 · 테스트. 전문은 [공공데이터포털 수집 설계](공공데이터포털_수집_설계.md).

|---|---|

| 클라이언트 (키 하나 · 페이지 순회 · 결과코드 해석) | `ingest/clients/data_go_kr.py` |

### 0.1 설계가 실측에 부딪힌 자리 — 세 군데가 틀렸다

| v3.1 설계 | 실제 |
|---|---|
| 과거 구간을 2010년부터로 봤다 | **2020-01-02 부터**다. 2019 이전은 `totalCount=0` |
| `corp_profile` 기본키를 `crno` 하나로 봤다 | **`(crno, fst_opeg_dt)`** 다. 법인 하나가 이력 여러 줄을 준다 |
| 칸 이름을 문서 표기대로 봤다 | 응답의 실제 칸 이름이 달랐다. **응답 본문을 열어 맞췄다** |

### 0.2 🔴 `basDt` 목록은 그 시점의 상장 목록이 아니다

`basDt=20200102` 로 받은 2,334종 안에 **그날 이후에야 상장된 종목이 33종** 있었습니다.
가장 늦은 것은 듀켐바이오(176750)로 첫 시세가 **2024-12-20**, 4년 뒤입니다.
포털은 최신에 가까운 목록에 기준일 딱지만 붙여 주는 것으로 보입니다.

그래서 이 표로 유니버스를 그대로 만들면 **아직 없던 종목이 섞입니다.** 미래참조이고
에러가 나지 않아 성능만 좋아집니다. 반드시 `daily_price` 와 **교집합**을 내서 씁니다.
`verify_identity.py` 가 이 항목을 매번 셉니다.

### 0.3 포털이 안 주는 것 — 우선주와 외국기업

표본 구간에서 시세 2,324종 중 **못 이은 141종 = 우선주 120 + 외국기업 21 + 그 밖 0**.
포털의 한계이지 우리 조인의 결함이 아닙니다. 그래서 검증기는 이 둘을 **따로 세고**,
*"그 밖"* 이 5% 를 넘을 때만 경보합니다 — 우선주 때문에 매번 빨간불이 켜지면
사람이 검증기를 무시하게 됩니다.

### 0.4 두 자리 연도

포털이 상장일·설립일을 두 자리로 주는 경우가 있습니다. **56~99 → 1900대**로 풉니다.
KRX 개장이 1956-03 이라 그보다 이른 상장일은 있을 수 없다는 것이 근거입니다.
검증기가 "1956-03 보다 이른 상장일" 과 "2030년보다 미래인 상장일" 을 양쪽에서 셉니다.

### 0.5 `known_at` — 계산값과 관측값을 섞지 않는다

| 표 | 규칙 | 왜 |
|---|---|---|
| `stock_identity` | `basDt` 의 **다음 거래일** (계산값) | 그날 장중에는 그 목록을 볼 수 없었다 |
| `corp_profile` | `fstOpegDt` (**관측값**) | 포털이 유효시작일을 직접 준다 |

검증기가 규칙 분포를 찍어 **한 가지인지** 확인합니다. 섞여 있으면 어느 행이 옛 규칙인지
갈라내야 하기 때문입니다.

## 2. 실측이 설계를 어떻게 바꿨나

### 2.1 첨부의 라이선스 표기 8/18건이 모델 카드와 달랐다

| 모델 | 첨부 | 카드 |
|---|---|---|
| ProsusAI/finbert · yiyanghkust/finbert-tone · jhgan/ko-sroberta-multitask · snunlp/KR-FinBert-SC · rbehzadan/ReaderLM-v2 | MIT / Apache / NC | **미표기** |
| knowledgator/gliner-relex-large | Apache-2.0 | **카드 자체가 없다 (404)** |
| facebook/nougat-base | MIT | **cc-by-nc-4.0** |
| openai/whisper-large-v3 | MIT | apache-2.0 |

원칙(조사/도구선정 §4 · 모델벤치마킹 §5)대로 **카드 값만** 믿습니다. 그 결과 첨부가
1순위로 꼽은 한국어 금융 감성 모델(`KR-FinBert-SC`)은 쓸 수 없고, 세 제약(생성형 금지 ·
라이선스 명시 · 원격 제공)을 다 통과하는 후보는 **6종**입니다.

### 2.2 🔴 HF 토큰에 원격 추론 권한이 없다

호출한 인코더 14종이 전부 `403` 이었고 본문은 하나였습니다 — *"This authentication method
does not have sufficient permissions to call Inference Providers"*. `whoami-v2` 로 본
토큰 권한은 `repo.*`·`discussion.write` 뿐이었습니다. **모델이 아니라 토큰 문제**였고,
팀장이 11:5x 에 "Make calls to Inference Providers" 를 켠 뒤 11:53 재실측에서 **200 이 7종**
(라이선스 명시 5종 + 미표기 2종), `sentence-similarity` 등록 모델은 경로를
`/pipeline/feature-extraction` 으로 바꿔 200(MiniLM 0.3초 · ko-sroberta 5.8초), `bge-m3` 는
2.2GB 콜드 스타트가 120초 게이트웨이 한도를 넘어 504 였습니다. 한국어 제로샷
(`xlm-roberta-large-xnli`)은 "영업이익이 시장 예상을 웃돌았다" 에 **긍정 0.988** 을 줬습니다.
콜드 스타트는 최대 24.9초(`KURE-v1`) — 파이프라인 타임아웃의 근거가 됩니다.
전문은 [고도화 설계 §1.5](고도화_설계.md).

### 2.3 첨부의 "게이트 통과 시 즉시 HF push" 는 우리 규칙과 충돌한다

반출본은 개발구간(~20240831)만 담으므로 새 시세가 들어와도 내용이 바뀌지 않습니다.
그래서 갱신 파이프라인의 업로드 단계는 무조건이 아니라 **`verify_hf_dataset` 이 "재배포
필요(2)" 라 답할 때만** 입니다(D-62 · 재배포 3조건). 첨부와 다른 점을 설계에 명시했습니다.

### 2.4 텍스트 원료가 0행이다

뉴스(D-20)는 미착수, `dart_disclosure` 는 v6 에 표만 있고 **0행**입니다(실측). 모델보다
원료가 먼저라서 1차 원료를 **DART 공시 제목**(접수일 기록값 · 약관 제한 없음)으로
정했습니다. 뉴스는 네이버 약관 7.3 ③ "저장(캐시 행위 포함)" 금지 때문에 팀 판단(계획서
부록 G ④) 뒤로 미룹니다.

### 2.5 강사님 Actions 의 봇 커밋 패턴은 들이지 않는다

10일 동안 커밋 181 · 머지 62 · PR 58건(실측)을 내는 팀에서 push 마다 봇 커밋이 하나씩
더 생기면 자동 생성 콘텐츠가 그만큼 쌓입니다. GitHub 의 계정 제한 기준은 **비공개**
(커뮤니티 토론에서 스태프가 support 로만 안내)라 보수적으로 **검사만 하는 CI**
(`contents: read` · `paths-ignore` · `concurrency`) 로 좁혔고, 도입 전에 `nektos/act` 로
로컬에서 돌려 push 0회로 검증합니다. 한도 실측표(Actions 공개 저장소 무료 · REST
5,000/h · 콘텐츠 생성 500/h)는 [도입 설계 §4.2](강사님저장소_분석과_도입설계.md).

## 이번 판의 교훈

| 무엇 | 배운 것 |
|---|---|
| 첨부의 라이선스는 카드가 아니다 | 검색 결과·저장소 LICENSE 는 가중치 라이선스가 아니다. **카드만 믿는다** |
| "안 된다" 는 셋으로 갈라진다 | 모델이 없다 · 서버가 제공 안 한다 · **내 토큰 권한이 없다** — 겉으론 같은 403 |
| 400 도 둘로 갈라진다 | "제공 안 함" 과 "**경로가 다르다**"(`sentence-similarity` → `/pipeline/feature-extraction`). 400 만 보고 버리면 멀쩡한 모델을 잃는다 |
| 콜드 스타트는 25초 | 타임아웃은 추측이 아니라 이 값으로. 2.2GB 모델은 게이트웨이(120초)를 넘긴다 |
| 제공자 표시는 흔들린다 | 같은 모델이 몇 분 사이 live → error. 한 번 조회한 값에 설계를 걸지 않는다 |
| 원료가 0행이면 모델은 없다 | 모델 표보다 원료 표가 먼저다 |
| 판정 기준이 비공개면 보수적으로 | GitHub flagged 는 "얼마나" 를 증명할 수 없다. 가장 가까운 패턴을 피한다 |
