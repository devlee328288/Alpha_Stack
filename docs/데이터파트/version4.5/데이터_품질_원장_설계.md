## 1. 왜 필요한가 — 네 가지가 흩어져 있다

| 지금 어디에 남나 | 무엇 | 팀원이 볼 수 있나 |
|---|---|---|
| `reports/data_quality.json` (`check_data.py`) | 시세·지수 구조 검사 — OHLC 역전 · 등락률 어긋남 · 설명 안 되는 이상치 · 게이트 판정 | 저장소를 열면. HF 카드에는 없다 |
| `data/outbox/<날짜>/PROFILE.json` (`export_team_dataset.py`) | 칸별 통계 185칸 — 결측률 · 분포 · 희귀값 | 로컬 반출 폴더에만. HF 에 안 올라간다 |
| 검증기 4종 표준출력 (`verify_identity` · `verify_base_info` · `verify_sector` · `verify_text_signal`) | 신원 · 기본정보 · 업종 · 텍스트 신호의 규격 판정 | `upload_to_hf` 가 돌리고 **결과는 화면에만** 흐른다 |
| 🔴 어디에도 없다 | `is_adj_suspect` 가 몇 행인가 · 키 축마다 중복이 있나 · 달력이 시세와 맞나 · 후보군에 의심 행이 있나 | **없다.** 이번 판에 세 번 손으로 쟀다 |

그래서 팀원이 "이 반출본에 의심 행이 몇 개인가", "지난 반출본과 무엇이 달라졌나" 를 물을 곳이
없습니다. 09-07 에 재배포가 두 번 있었는데 두 번의 차이(51종 39,166행 · `industry_ambiguous` 신설)는
변경사항 문서에만 남았습니다. 강사님이 09-04 에 "데이터는 지속 업데이트" 를 말씀하셨으니 갱신마다
**품질이 어떻게 변했는지의 이력**이 필요합니다.

그리고 이번 판에 배운 것 하나 — **행 수는 덮어쓰기를 못 잡습니다.** `index_price` 40,324행이 덮였을
때 합계는 오히려 늘었고, `index_class` 축으로 세고서야 보였습니다. 원장은 합계가 아니라 **키의 축마다**
셉니다.

## 3. 어디에 남나 — 파일 하나 · 카드 절 하나 · 이력 한 줄

```
data/outbox/<날짜>/
├─ MANIFEST.json          ← 이미 있다 (파일·해시·봉인)
├─ PROFILE.json           ← 이미 있다 (칸별 통계 185칸)
└─ QUALITY_LEDGER.json    ← 🆕 §2 의 다섯 축 · run_id · git sha · 반출본 SHA-256 · 잰 시각
```

| 어디 | 무엇 | 왜 |
|---|---|---|
| `QUALITY_LEDGER.json` (반출 폴더) | 다섯 축 전부 · 값 · 붉은 기준 · 판정 | `MANIFEST` 옆이라 반출본과 **같이 움직인다** |
| HF 카드 `README.md` 🆕 "품질 원장" 절 | 다섯 축을 **표로** · 붉은 것은 🔴 · 전 반출본 대비 변화 열 | 팀원이 HF 페이지에서 바로 읽는다 (카드는 파일 바꿀 때 같이 갱신 — 규약) |
| `reports/quality_ledger.jsonl` (저장소 · append-only) | 반출마다 한 줄 — `run_id` · `generated_at` · 다섯 축 요약 수치 | **이력.** 09-07 두 번의 차이가 여기 남았어야 했다 |

스키마 초안 (한 축만):

```json
{
  "generated_at": "2026-09-07T13:29:06+09:00",
  "run_id": "20260907-134654",
  "git_sha": "e4dd849",
  "manifest_sha256": "…",
  "axes": {
    "outlier": {
      "adj_suspect_rows": {"value": 1353, "by_source": {"chain": 119, "fdr": 1234},
                           "red_if": "chain > 0", "status": "red",
                           "note": "chain 119 는 FDR 이 KRX 와 다르게 편 자리 · 다음 실측"},
      "adj_suspect_in_candidates": {"value": 0, "red_if": "> 0", "status": "ok"}
    }
  },
  "status": "red",
  "previous": {"run_id": "20260907-101640", "adj_suspect_rows": 1406}
}
```

⚠️ `status: red` 여도 원장은 업로드를 **막지 않습니다.** 막는 조건은 D-63(검증기 4종)·D-92(게이트)로
이미 정해져 있고, 원장의 붉은 항목은 **카드에 붉게 적혀 나갑니다.** "알면서 내보내는 것" 을 숨기지
않는 것이 이 문서의 목적입니다. 단, 원장 **생성 자체가 실패**하면 그건 `error` 입니다.

## 4. 언제 만드나 — refresh 의 반출 단계 안

```
ingest → calendar → (adj) → gate → verify → export ──┬─→ upload
                                              └─ 🆕 QUALITY_LEDGER.json 을 MANIFEST 옆에
```

- **반출(⑥) 단계 안**에서 만듭니다. 반출본이 실제로 생긴 뒤에 그 파일을 읽어 재야 "반출본의 품질"
  이지 "DB 의 품질" 이 아닙니다. `PROFILE.json` 이 이미 그 자리에서 나옵니다.
- **업로드(⑦)** 가 카드에 절을 붙입니다. `upload_to_hf` 는 이미 `MANIFEST*.json` 을 읽어 카드를 만듭니다.
- 판정(⑤)이 "최신" 이라 반출을 건너뛰면 원장도 안 만듭니다 — 반출본이 안 바뀌었으니 원장도 그대로입니다.
- `--only export` 로도 만들어집니다 (09-07 오후처럼 단계를 골라 돌릴 때).

## 5. 시점 규칙 — 원장은 반출 시점의 사실이다

- 원장은 **그 반출본**에 대한 것입니다. DB 가 나중에 바뀌어도 원장은 안 바뀝니다 (관측 · 정정 블록 방식).
- `run_id` · `git_sha` · `manifest_sha256` 셋을 반드시 적습니다 — "이 숫자 어디서 났나" 에 답하려면
  코드·자료·실행 셋이 다 고정돼야 합니다. §6 빚 "대장에 생성 커밋이 없다" 도 이것으로 같이 닫힙니다.
- 이력(`quality_ledger.jsonl`)은 **append-only** 입니다. 고치지 않고 새 줄을 씁니다.

## 6. 팀원이 어떻게 쓰나

| 누가 | 무엇 | 어떻게 |
|---|---|---|
| 오준영 (모델) | 학습 전에 표본이 깨끗한지 **assert** | `QUALITY_LEDGER.json` 을 받아 `axes.outlier.adj_suspect_in_candidates.value == 0` |
| 신장환 (피처) | 피처 만들 때 `is_adj_suspect` 를 빼야 하는지 | 카드 표의 chain 의심 수 · 🔴 이면 뺀다 |
| 강민석 (백테스팅) | 반출본이 어느 반출본인가 | `run_id` 가 원장 = 대장 = 백테스트 결과에 같이 적힌다 (⑮ 되먹임과 이어진다) |
| 팀 전체 | 지난 반출본과 무엇이 달라졌나 | 카드 표의 "변화" 열 · `quality_ledger.jsonl` |

### 6.1 갈래 하나 — 플래그 4칸을 반출본에 넣을 것인가

지금 `is_adj_suspect` 등은 **공급 층에서만** 붙습니다. HF 로 받아 쓰는 팀원은 같은 함수를 돌려야
같은 표본이 됩니다.

| | (a) `daily_price_dev` 에 4칸을 넣는다 (24 → 28칸) | (b) 별도 `quality_flags_dev.parquet` | (c) 원장에 **수만** 적고 칸은 안 넣는다 |
|---|---|---|---|
| 팀원 코드 | 안 바뀐다 — 칸이 늘 뿐 | `merge` 한 줄 | `supply.adj_quality` 를 각자 돌린다 (지금) |
| 정의의 동일성 | ✅ 파일이 정의다 | ✅ | 🔴 각자 돌리면 버전이 갈릴 수 있다 |
| 재배포 | 반출 규격 변경 ③ → 한 번 재배포 | 새 파일 추가 → 한 번 | 없음 |
| 대가 | 칸 4개 × 7.9M 행 · 약 30MB | 파일 하나 | — |

권고는 **(a)** 입니다. 같은 파일 안의 `adj_close`·`change_rate` 두 칸에서만 계산되는 값이라 파일에
넣는 것이 정의를 한 곳에 두는 길이고, `industry_ambiguous` 를 넣을 때와 같은 판단(품질 플래그를
배포본까지 흘린다)입니다. 다만 반출 규격 변경이라 **팀에 묻고** 넣습니다.

## 8. 안 하는 것

| 안 하는 것 | 왜 |
|---|---|
| 원장이 업로드를 막는 것 | 막는 규칙은 D-63·D-92 로 이미 있다. 규칙을 둘로 나누면 "왜 안 올라갔나" 가 두 곳에 갈린다 |
| 이상치 자동 삭제 · 윈저화 | 규약 §4.2 — 수집·반출은 자르지 않는다. 원장은 **세고 적는다** |
| 칸별 분포 전체를 다시 계산 | `PROFILE.json` 이 이미 185칸을 낸다. 원장은 그것을 **가리키고** 판정만 더한다 |
| 실시간 대시보드 | 화면은 강민석 님 경계. 원장은 화면이 읽을 **JSON 과 카드**까지 |
| 과거 반출본 소급 | 09-05 · 09-07 반출본은 손으로 잰 값을 첫 줄로 적는다. 다시 만들지 않는다 |
