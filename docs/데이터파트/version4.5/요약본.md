## 이번 판 — 넷

### ① 정문 셋 — 규칙은 하나 (D-33 ~ D-35)

**행 T 에 보이는 것은 `known_at <= T` 인 것뿐.**

| 정문 | `known_at` | 🔴 함정 |
|---|---|---|
| `attach_financial` (18칸) | 접수일 **다음 거래일** | 보고서 **26%** 가 정정본 → **정정일 그대로** · "가장 최근" 은 **결산 순서** |
| `attach_macro` (지표마다 값·기간) | 발표 규칙으로 계산한 날 | 순환변동치는 과거 값이 개정돼 **기본 제외** |
| `attach_text` (건수·확률 4칸) | 접수일 다음 거래일 (HF 텍스트 반출과 같은 규칙) | `rm` '정'·'철' 로 **거르지 않는다** — 나중에 붙는 표시 |

정문이 주는 것은 **원값까지**입니다. ROE · 전년비 · 창 합계 같은 피처화는 신장환 님 몫입니다.

### ② 🔴 틀린 구현이 실제로 새는가 — 음성 대조군

같은 팀 유니버스(월말 116일 × 후보 5,703행)에 시점만 틀리게 붙여 봤습니다.

| 붙이는 방법 | 그날 알 수 없던 보고서를 본 행 |
|---|---:|
| 결산기 끝 | **23.2%** (1,324행) |
| 원본 최초 접수일 | **9.1%** (516행) |
| **정문** | **0** |

대조군은 시점만 달라야 대조군입니다 — 모든 보고서가 드러난 마지막 날에는 정문과 결산기 끝이
**98.0%** 같은 보고서를 붙입니다.

### ③ 🔴 하루 누수 — 시점 칸이 있어도 샜다 (D-36)

업종·주권종류는 `known_at` 칸이 **있었습니다.** 그런데 붙이는 코드가 **날짜로** 조인해서 그날 마감
뒤에 나온 표가 그날 행에 붙었습니다.

| 칸 | 새 정보를 하루 먼저 본 행 |
|---|---:|
| 업종 | **5,300** |
| 소속부 | **6,276** |
| 상장 첫날 (주권종류 3칸) | **3,677** |
| 팀 유니버스 — 후보가 바뀐 스냅샷 날 | 15일 중 **12일** · **25종목** |

🔴 **HF 판정기도 반출과 다른 코드로 붙이고 있었습니다.** 반출만 고쳤다면 판정기가 옛 규칙으로 남아
영원히 "다르다" 를 냈을 것입니다. 같은 함수를 부르게 했습니다.

### ④ 홀드아웃은 한 번만 연다 (D-67 · 이슈 #240)

| `reports/unseal.log` | 판정 |
|---:|---|
| 0줄 | 미개봉 |
| 1줄 | 개봉 1회 — 확증 가능 |
| 2줄 이상 | 🔴 **"홀드아웃 {n}회 개봉 — 확증 불가"** |

```
open       사전등록 커밋 · 추적 파일 변경 0 · 데이터 게이트 → 봉인 반출 → 한 줄
authorize  기록 1줄 · 지문 일치 · 개발/홀드아웃 안 섞임 → 승인 JSON (실행기 계약 여섯 칸)
check      사전등록이 개봉보다 앞섬 · 결과 지문 · 산출물에 원자료·시크릿 없음
```

🔴 두 번째 개봉은 **반출하기 전에** 거부합니다. 드라이런 기록은 `reports/dryrun/` 에 따로 둡니다 —
드라이런이 진짜 기록을 채우면 진짜 개봉이 두 번째가 됩니다.
