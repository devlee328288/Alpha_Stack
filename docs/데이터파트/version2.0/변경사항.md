# 데이터 파트 v1.0 → v2.0 변경사항

> 2026-08-27 · [v1.0](../version1.0/) → [v2.0](요구사항.md)
> **Major(+1.0)** 인 이유: **수집 범위가 4종 → 3종으로 줄었고**(약관 위반이 될 뻔했습니다),
> 공통 규칙 D-00~D-04 가 *"만들 것"* 에서 *"이미 선 계약"* 으로 성격이 바뀌었습니다.

> 📌 **`변경노트-v1.1.md` 를 대체합니다.** 그 문서는 *"작업 중에는 버전업하지 않고
> 변경사항을 모은다"* 는 규약에 따른 **임시 누적본**이었습니다. D-00~D-04 가 닫혔으므로
> 여기로 승격하고 원본은 지웁니다. **실측 원문은 [docs/조사/](../../조사/) 에 온전히
> 살아 있습니다** — 요약만 남기고 근거를 버리지 않았습니다.

## 1. 🔴 가장 중요한 것 — 수집 대상 하나를 접었습니다

### D-22 종목토론방: **Must → Won't**

v1.0 [시장조사](../version1.0/시장조사.md)와 [요구사항](../version1.0/요구사항.md)이
*"`/item/board.naver?code=*` 는 Allow, `&page=*` 는 Disallow → 매일 1페이지 누적만"*
이라고 적었습니다.

**1페이지도 안 됩니다.** `robots.txt` 원문을 직접 받아 보니(2026-08-26 KST · HTTP 200 ·
`text/plain; charset=euc-kr` · 295 bytes) 허용 규칙군이 **전부 `User-agent: yeti`
(네이버 자체 크롤러) 그룹 소속**이었습니다. 제3자 봇이 매칭되는 `User-agent: *` 그룹은
**`Disallow: /` 한 줄 — 사이트 전면 불허**입니다.

| 항목 | v1.0 | v2.0 |
|---|---|---|
| **D-22** 종목토론방 수집기 | Must | **Won't** |
| **D-51** 종목토론방 글 수 집계 | Should | **Won't** (원자료가 없다) |
| 수집 범위 | 4종 | **3종** — 시세·통계 / 공시 / 뉴스·동영상 |

**UA 를 `yeti` 로 위장하는 안은 선택지에 올리지 않았습니다.** 사칭입니다.

> 💡 **이것은 손실이 아니라 산출물입니다.** 수집을 안 한 것보다 **안 하기로 정한 근거가
> 문서에 남는 것**이 낫습니다. *"왜 커뮤니티가 없나"* 에 답이 있습니다.

## 3. 외부 사양 정정 — 문서가 사실과 달랐던 곳

### 3.1 네이버 검색 API

| v1.0 | 실제 |
|---|---|
| 쿼터 초과 = `errorCode 010` | ❌ **그런 코드 없음.** 공식 코드는 `SE01`~`SE06`·`SE99` 7종뿐. 쿼터 초과는 **HTTP 429** |
| `start+display-1 ≤ 1000` | ⚠️ **공식 근거 없음.** 명세는 `display 1~100`·`start 1~1000` 두 독립 범위뿐 → **"안전측 가정"으로 강등** |
| 25,000콜/일 | ✅ 맞음. 단 **앱(클라이언트 아이디)별** |

**새로 확인된 것**

- 🔴 **2026-07-30 신규 발급 중단.** 우리는 이전 발급분 보유 → 그대로 사용.
  **2027-06-30 이 하드 데드라인** → 주소·헤더를 상수로 분리
- 약관 7.3 ⑤ 가 **쿼터 증대 목적 다중 키 발급을 금지** → *"팀원마다 키 분산"* 배제
- 약관 7.3 ③ 이 **저장·가공·배포 금지** → 원문 코퍼스를 커밋·배포하지 않는다
- **출처 표기 의무** — 화면에 *"네이버 오픈 API 사용"*
- ⚠️ 쿼터 리셋이 **"0시~1시" 구간** → 배치는 **01:10 KST 이후**
- ⚠️ **카페글 응답에 `pubDate` 가 없다** → 뉴스와 스키마를 따로

### 3.2 YouTube Data API v3

v1.0 의 수치는 맞지만 **구조를 안 적었습니다.** `search.list` 는 이제 **콜당 1유닛 +
자체 버킷**이라, 100콜을 다 써도 공용 10,000 은 그대로입니다.

**실측으로 잡힌 함정 3개**

1. `playlistItems.list` 에 **조회수가 없다** → `videos` 추가 호출 필수
2. `playlistItems.snippet.publishedAt` 은 **"재생목록에 추가된 시각"** —
   영상 게시시각은 `contentDetails.videoPublishedAt`. **틀리면 `known_at` 이 어긋난다**
3. 부분 실패 식별용 `summary` 필드는 **실재하지 않는다** → **요청 id 와 반환 items 를
   차집합**해서 찾는다

### 3.3 🔴 KRX · DART 한도는 **검증되지 않았습니다**

| 값 | 상태 |
|---|---|
| KRX 10,000콜/일 | ⚠️ **확인도 반증도 안 됨** |
| DART 20,000콜/일 | ⚠️ **근거 약함.** 공식 문구가 *"요청 제한이 다르게 설정된 경우"* 단서를 답 |

→ **"기본값(키별 상이 가능)"** 으로 표기를 낮췄습니다. 예산 상한은 보수적으로.

⚠️ **DART 는 한도 초과를 HTTP 오류가 아니라 `HTTP 200` + 본문 `status="020"` 으로 줍니다.**
HTTP 예외만 잡는 코드는 **한도 초과를 놓칩니다.**

## 4. D-12(DART PIT) — 수용 기준 적용 시점을 옮겼습니다

v1.0: *"접수일이 없는 응답은 **적재 거부**"*.
그런데 **재무제표 응답에 `rcept_dt` 가 없습니다.** 문자 그대로 적용하면 **재무제표가
전량 거부**됩니다.

→ **거부 게이트를 "접수일 보강 이후"로 옮기고**, 접수일은 **`list.json` 조인**으로 얻습니다.

`rcept_no[:8]` 슬라이싱 편법은 **4,800건 실측으로 기각**했습니다 — 3건이 어긋났고
**둘은 미래를 3일 먼저 봅니다.**

📎 전문: [조사/공시시점정합](../../조사/공시시점정합.md)

## 6. 팀 배정이 바뀌었습니다

### 6.1 문서가 "팀장 = 이동원" 을 전제하고 있었습니다

초기 문서가 **팀장이 이동원인 것처럼** 쓰여 있었습니다. 사실이 아닙니다.
팀장은 **아직 정해지지 않았고** 킥오프에서 정합니다. 전 문서에서 그 서술을 걷어냈습니다.

### 6.2 팀은 **4명**입니다 (2026-08-27 확정)

| 이름 | 담당 |
|---|---|
| **이동원** | 데이터 수집·저장·정제·전처리 전반 + 수집 현황 화면 |
| **강민석** | 백테스팅 · 성과지표 · **대시보드** |
| **신장환** | **크롤링** · ML |
| **4번째 팀원** | 데이터 **전처리** · ML 기초 모델 |

> ⚠️ **경계가 겹칩니다.** 대시보드가 강민석, 크롤링이 신장환, 전처리가 4번째 팀원과
> 겹칩니다. **누가 어느 파일을 만지는지 킥오프에서 긋습니다** (§7 D-6).
> 이동원이 만드는 화면은 **수집 현황·품질** 쪽입니다.
