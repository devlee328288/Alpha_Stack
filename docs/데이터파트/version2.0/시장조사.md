## 2. 🔴 종목토론방 — 접었습니다

v1.0 은 *"첫 페이지는 허용, 페이지 넘기기는 금지"* 로 읽었습니다. **틀렸습니다.**

허용 규칙들이 **전부 `User-agent: yeti`(네이버 자체 크롤러) 그룹 소속**이고, 제3자 봇이
매칭되는 `User-agent: *` 그룹은 **`Disallow: /` — 사이트 전면 불허**입니다.
[RFC 9309 §2.2.1](https://www.rfc-editor.org/rfc/rfc9309.txt) 상 크롤러는 **자신에게
매칭되는 그룹 하나만** 따릅니다.

→ **수집 범위 4종 → 3종.** 원문과 판단 근거는 [문제정의 §2.4](문제정의.md).

### 2.1 그래서 파서를 직접 고르게 됐습니다

`robots.txt` 를 코드가 실행 시점에 확인해야 하는데, **표준 라이브러리가 위험합니다.**

| 후보 | 판정 |
|---|---|
| `urllib.robotparser` | ❌ **fail-open** — 명시적 `Disallow` 인 URL 에 `can_fetch()` 가 `True` 를 반환. 와일드카드·`$` 미지원 |
| **`protego==0.6.2`** | ✅ 전 케이스 정답. `$`·최장일치·쿼리스트링·비표준 라인까지 |
| `reppy` | ❌ PyPI 최신이 2019년, 지원 파이썬 ~3.7 |
| `robotexclusionrulesparser` | ❌ 같은 케이스 fail-open. 최종 릴리스 2016년 |

> 🔴 **차단 가드가 반대 방향으로 틀리면 가드가 없는 것보다 나쁩니다.** 안전하다는
> 착각을 주기 때문입니다.

**`0.6.2` 로 고정한 이유**: `<=0.6.1` 에 ReDoS 취약점(GHSA-wjmf-p669-5m5p / CVE-2026-55520,
severity **High**)이 있습니다. **외부가 주는 파일을 파싱하는 코드는 정면 노출입니다.**

**직접 만들어야 했던 것** — `protego` 는 파서 전용이라 fetch 를 안 합니다:

- **HTTP 상태 분기를 RFC 9309 대로**: `4xx`(404 포함) → **전면 허용** /
  `5xx`·네트워크 오류 → **전면 차단**. ⚠️ **흔한 실수가 5xx 를 허용으로 처리하는 것**인데
  RFC 는 MUST 로 금지합니다
- 24시간 캐시. 단 5xx 로 갱신 실패 시 **직전 캐시를 계속 씁니다**
- ⚠️ 응답이 **`charset=euc-kr`** 입니다. UTF-8 로 가정하지 않습니다

## 3. 뉴스 · 카페글 — 네이버 검색 API

| 항목 | 값 |
|---|---|
| 일 호출 한도 | **25,000회** — ⚠️ **클라이언트 아이디(앱)별**, 전 코퍼스 합산 |
| 인증 | `X-Naver-Client-Id` · `X-Naver-Client-Secret` 헤더 |
| 한 번에 | `display` 최대 100건 |
| 페이징 | `start` 최대 1,000 |
| 쿼터 초과 | **HTTP 429** — ⚠️ v1.0 이 적은 `errorCode 010` 은 **존재하지 않습니다.** 공식 코드는 `SE01`~`SE06`·`SE99` 7종뿐 |
| 권한 오류 | `403` — 개발자 센터에서 "검색" API 를 앱에 추가하지 않은 경우 |

### 3.1 🔴 신규 발급이 중단됐습니다

약관 부칙 제2조 ①: *"**2026년 7월 30일 24:00** 를 기점으로 (…) 신규 이용 신청 접수를 중단"*.

**우리 팀은 그 이전 발급분을 보유**하고 있어 그대로 씁니다. 다만:

- **2027-06-30 24:00 이 하드 데드라인**입니다. 그 뒤로는 NAVER API HUB 만 남습니다
  → `base_url` 과 인증 헤더를 **상수로 분리**해 전환이 한 줄 교체가 되게 짭니다
- 약관 7.3 ⑤ 가 **쿼터 증대 목적의 다중 키 발급을 금지**합니다
  → *"팀원마다 키를 받아 분산"* 은 설계에서 **명시적으로 배제**합니다
- 약관 7.3 ③ 이 **저장·가공·배포를 금지**합니다
  → **원문 코퍼스를 저장소에 커밋하거나 데이터셋으로 배포하지 않습니다**
- **출처 표기 의무** — 화면에 *"네이버 오픈 API 사용"* 표시가 필요합니다

### 3.2 1,000건 창(window)이 뜻하는 것

**검색어 하나로 과거를 무한정 거슬러 갈 수 없습니다.** 인기 종목의 뉴스는 며칠이면
1,000건을 넘습니다 → **뉴스도 백필이 아니라 누적**입니다.

> ⚠️ **`start + display - 1 ≤ 1000` 은 공식 근거가 없습니다.** 명세에는 `display 1~100` ·
> `start 1~1000` 두 독립 범위만 있습니다. **삭제하지 않고 "안전측 가정"으로 강등**합니다 —
> 지켜서 손해가 없고 어기면 `SE03` 위험이 있습니다.
> **실호출 1회(`start=1000&display=100`)로 확정할 것.**

### 3.3 호출 수 계산 — 대상 범위의 근거

`display=100` 기준, 대상당 하루 1페이지:

| 대상 범위 | 뉴스 | 카페글 | 합계/일 | 25,000 대비 |
|---|---|---|---|---|
| **산업(섹터) 약 30개** | 30 | 30 | **60콜** | 0.2% |
| KOSPI200 전체 200종목 | 200 | 200 | 400콜 | 1.6% |
| 200종목 × 각 10페이지 | 2,000 | 2,000 | 4,000콜 | 16% |

**여유가 큽니다.** 한도가 병목이 아니라 **1,000건 창과 저장·정제 비용**이 병목입니다.

> 📌 **그래서 산업(섹터) 단위로 모읍니다.** 3,677종목 전수는 의미도 없고 정제 비용만
> 큽니다. 종목 지정 검색은 **요청이 들어온 그때** 수집합니다.
> 산업 분류 기준은 킥오프에서 정합니다.

### 3.4 지켜야 할 것

- 기사 **제목·요약·링크·발행시각**만 저장. **본문 전문은 저장·재배포하지 않습니다**
- 응답의 `<b>` 하이라이트 태그와 HTML entity 를 제거해 저장
- 실패 응답을 캐시하지 않습니다 (다음 요청이 온전히 다시 타야 합니다)
- ⚠️ **쿼터 리셋이 자정 정각이 아니라 "0시~1시" 구간**입니다 → 배치는 **01:10 KST 이후**
- ⚠️ **카페글 응답에는 `pubDate` 가 없습니다** (`title`·`link`·`description`·`cafename`·
  `cafeurl`). 뉴스와 같은 시간축 정렬이 **불가능**하므로 **스키마를 따로 잡습니다**
- 뉴스 `pubDate` 는 RFC 1123 (`"Thu, 11 Jun 2026 18:34:00 +0900"`) — **영문 요일·월
  약어라 로케일 의존 파싱에 주의**합니다

## 4. 동영상 — YouTube Data API v3

### 4.1 검색을 쓰지 않는 설계로 갑니다

```
❌ 나쁜 설계   search.list 로 매일 키워드 검색   → 하루 100콜에서 즉사
✅ 좋은 설계   channels.list → uploads 재생목록 → playlistItems.list → videos 통계
```

채널 50개 × 최근 50영상 ≈ **101유닛/일** — 한도의 1% 수준입니다.

### 4.2 실측으로 잡힌 함정 3개

1. **`playlistItems.list` 에 조회수가 없습니다.** `part` 는 `snippet`·`contentDetails`·
   `id`·`status` 4종뿐이고 `statistics` 가 없습니다 → **`videos` 추가 호출이 필수**
2. **`playlistItems.snippet.publishedAt` 은 "재생목록에 추가된 시각"** 입니다.
   영상 게시시각은 **`contentDetails.videoPublishedAt`** — 이걸 틀리면 `known_at` 이
   통째로 어긋납니다
3. **부분 실패를 식별하는 `summary` 필드는 실재하지 않습니다** (discovery 문서 원문 대조).
   → **요청한 id 집합과 반환된 items 를 차집합**해서 찾아야 합니다

⚠️ **잘못된 요청도 쿼터를 씁니다** (최소 1유닛). 재시도 루프를 돌리지 않습니다.
⚠️ 쿼터 리셋은 **태평양시(PT) 자정** = KST 오후 4~5시(서머타임에 따라 이동)입니다.

> 일관됩니다. 코스피 차트는 그다음입니다.

> 📌 **위 셋은 React 기반이라 그대로 못 가져옵니다.** 베끼는 것은 **레이아웃 문법과
> 시각적 기본값**(여백 비율, KPI 카드 구성, 축 라벨 처리, 색 대비)이지 코드가 아닙니다.

⚠️ `1.61.x` 이하는 `pyarrow<25` 를 요구해 우리 핀(`==25.0.1`)과 **설치 자체가 실패**합니다.

> 💡 커스텀 컴포넌트는 **`st.components.v2`** (1.51.0~)를 씁니다. iframe 이 없어 앱 테마가
> 상속되고 **`--st-*` CSS 커스텀 프로퍼티**를 그대로 참조할 수 있습니다.
> → **정적 HTML 이 같은 토큰을 쓸 수 있는 근거**이기도 합니다.

## 7. 이 조사가 요구사항에 미치는 결론

| # | 결론 | 근거 |
|---|---|---|
| 1 | 시세·통계·공시는 **클라이언트가 이미 있다.** 새로 만들 것은 **배치·품질 게이트·공급 API** | §1 |
