# 모델 라이선스 대장 — 우리가 쓰는 HF 모델을 어떻게 밝히나

> 작성 2026-09-03 · 이동원 · 실측 18종 전수 조회 + 관례 조사
> 대상: 팀원 4인 (오준영·강민석·신장환·이동원)

---

## 0. 한 줄

**모델을 내려받아 로컬로 돌리는 것은 무료다.** 돈이 붙는 곳은 원격 추론뿐이고,
우리는 쓰지 않는다. 대신 **라이선스가 없는 모델이 더 많으므로**(HF 전체의 약 70%)
쓰는 모델마다 **버전과 받은 날짜를 적고 인용문을 남긴다.**

---

## 1. 왜 이 문서가 필요한가

우리 프로젝트는 **상업 배포를 하지 않는다.** 그래서 라이선스가 사용을 막는 일은
거의 없다. 그런데도 대장을 두는 이유는 둘이다.

1. **모델은 바뀐다.** 저장소 주인이 라이선스를 바꾸거나 가중치를 갈아 끼울 수 있다.
   "우리가 언제 무엇을 받았는가" 를 안 적으면 나중에 되짚을 수가 없다.
2. **네 명이 각자 다른 모델을 가져온다.** 누가 무엇을 어디에 썼는지 한 곳에 없으면
   발표 때 "이 숫자는 무슨 모델이 냈나" 에 답할 수 없다.

법률 실무 안내도 같은 말을 한다 — *"연구 프로젝트마다 라이선스 인벤토리 문서를
만들어 사용한 모델·라이선스·주요 제약·준수 메모를 적어라. 여러 팀원이 서로 다른
모델을 쓰는 공동 연구에서 특히 중요하다"* (Epstein Becker Green, *Demystifying
Hugging Face Licenses*, 2025).

---

## 2. 🔴 실측 — 라이선스가 없는 게 예외가 아니다

우리 로컬 캐시 18종을 HF API 로 전수 조회했다 (2026-09-03).

| 라이선스 | 종수 | 모델 |
|---|---:|---|
| `mit` | 6 | bge-m3 · KcELECTRA · kobart-summarization · gpt2 · Kronos 3종 |
| `apache-2.0` | 3 | koelectra-sentiment · distilbert-sst2 · MiniLM 2종 |
| `cc-by-sa-4.0` | 1 | klue/bert-base |
| 🔴 `cc-by-nc-sa-4.0` | 1 | **skt/kogpt2-base-v2 — 비상업만** |
| ⚠️ **표시 없음** | 5 | **snunlp/KR-FinBert-SC** · KoSimCSE · bert-conll03 · koelectra-ner · kobert |

**표시 없음이 5/18 이다.** 이건 우리만의 문제가 아니다 — RedMonk 가 2026-05 에
HF 전체를 분석한 결과 **모델의 약 70%가 라이선스를 달지 않았다.** MIT 의 Data
Provenance Initiative 감사도 데이터셋의 70% 이상이 미표기였고, **표시된 것 중
27%는 원저자 의도보다 관대하게 적혀 있었다** (Nature Machine Intelligence, 2024).

> 그러니 "라이선스가 없다" 는 대개 *"허락하지 않는다"* 가 아니라
> **"주인이 안 적었다"** 는 뜻이다. 다만 우리가 그걸 단정할 수는 없다.

---

## 3. 그럼 실제로 쓰는 사람들은 어떻게 하나

arXiv 2502.04484 가 HF 모델 카드를 손으로 분석한 결과가 답이다.

> 라이선스가 없는 모델은 **라이선스 대신 인용(citation)으로 출처 표기를 요구하는
> 경우가 많았다** (84종 중 29종). HF 모델의 11.1%가 태그에 arXiv 링크를 달아
> 인용 경로를 열어 두고 있었다.

즉 **관례는 "라이선스가 없으면 인용한다"** 이다. 실제로 우리가 쓰려는 모델이
그렇다 — `snunlp/KR-FinBert-SC` 는 라이선스가 없는 대신 README 에 BibTeX 을 직접
적어 두었다.

### 3.1 우리가 쓸 표기 (그대로 복사해 쓴다)

```bibtex
@misc{kr-FinBert-SC,
  author = {Kim, Eunhee and Hyopil Shin},
  title = {KR-FinBert: Fine-tuning KR-FinBert for Sentiment Analysis},
  year = {2022},
  publisher = {GitHub},
  journal = {GitHub repository},
  howpublished = {\url{https://huggingface.co/snunlp/KR-FinBert-SC}}
}
```

발표 슬라이드·보고서에는 한 줄로 줄여 쓴다.

> 공시 제목 감성은 **KR-FinBert-SC** (Kim & Shin, 2022, 서울대 NLP) 로 계산했다.
> 모델 리비전 `<커밋 해시>` · 받은 날 2026-09-03 · 라이선스 미표기 · 비상업 연구 용도.

### 3.2 인용문이 없는 모델이면

HF 포럼의 공식 답이 *"모델 URL 을 웹페이지처럼 인용하라"* 이고, 지금은 **DOI 생성
기능**도 있다. 그래도 없으면 `@misc` 에 저장소 URL + 접속일을 적는다.

## 4. 🔴 반드시 같이 적는 두 가지 — 버전과 날짜

법률 실무 안내가 특히 강조하는 대목이다.

> *"모델 이름만이 아니라 **구체적인 버전과 접근 날짜**를 적어라. 라이선스와 모델은
> 시간이 지나며 바뀔 수 있다."* · *"모델을 받는 시점에 라이선스 정보를 문서화하라."*

우리 저장소에서는 **`MANIFEST` 에 남긴다.** 반출물마다 어떤 모델의 어떤 리비전이
그 칸을 만들었는지 적는다. 그래야 나중에 값이 달라졌을 때 "모델이 바뀐 건가
우리 코드가 바뀐 건가" 를 가를 수 있다.

```
text_signal.p_pos / p_neu / p_neg
  모델      snunlp/KR-FinBert-SC
  리비전    <HF 커밋 해시>
  받은 날   2026-09-03
  라이선스  표시 없음 (README 의 BibTeX 인용으로 갈음)
  용도      비상업 학술 프로젝트
```

---

## 5. 팀 규칙 — 새 모델을 가져올 때 세 줄만 하면 된다

1. **받기 전에** HF 모델 카드의 `license` 를 본다. `nc` 가 붙으면 비상업 전용이니
   우리 프로젝트에는 쓸 수 있지만 **대장에 표시**한다.
2. **받은 뒤에** 이 문서의 표에 한 줄 추가한다 — 모델 · 라이선스 · 리비전 · 받은 날 · 용도.
3. **결과를 낼 때** MANIFEST 와 발표 자료에 §3.1 형식으로 한 줄 적는다.

> ⚠️ **저장소의 LICENSE 파일과 모델 카드의 `license` 가 다를 수 있다.**
> 2026-09-02 에 첨부 자료 18종을 재확인했을 때 **8종이 달랐다.** 카드를 정본으로 본다.
> 불분명하면 HF 의 Community 탭으로 저작자에게 직접 물어보는 게 정석이다 —
> 대부분 답해 준다(법률 안내도 이 방법을 권한다).

| 모델 | 어디에 | 걸림 |
|---|---|---|
| `snunlp/KR-FinBert-SC` | 공시 제목 감성 3칸 (v11 text_signal) | 라이선스 미표기 → **인용으로 갈음**. 비상업이라 문제없음 |
| `skt/kogpt2-base-v2` | 지금 안 씀 (캐시에만) | **cc-by-nc-sa-4.0 · 비상업만.** 쓰게 되면 대장에 표시 |

**결론: 지금 계획에 막히는 것은 없다.** 다만 발표 자료에 §3.1 한 줄은 반드시 넣는다.

## 7. 비용 — 왜 0원인가

| 경로 | 비용 | 우리가 쓰나 |
|---|---|---|
| **모델 다운로드 + 로컬 추론** | **0원** | ✅ 이걸 쓴다 |
| HF Inference Providers (원격) | PRO 에 월 $2 크레딧, 이후 종량 | ❌ 안 쓴다 |
| HF Inference Endpoints (전용 GPU) | 시간당 과금 | ❌ 안 쓴다 |

원격을 안 쓰는 이유는 단가다. 일부 제공자는 **요청 크기와 무관하게 건당 $0.01~0.03**
을 뗀다(HF 포럼 다수 보고, 2026-07 까지 이어짐). 공시 제목 10만 건을 배치 64로
보내도 1,563요청 × $0.01 = **$15.63** 이라 월 $2 크레딧을 훨씬 넘는다.

로컬 실측(2026-09-03): CPU 22코어에서 **47건/초**, 완전 오프라인(`HF_HUB_OFFLINE=1`)
으로 동작. 10만 건이면 약 35분이다.

## 8. 팀원은 아무것도 설치할 필요가 없다

추론은 **데이터 파트(이동원)가 로컬에서 돌리고**, 결과인 확률 3칸
(`p_pos`·`p_neu`·`p_neg`)만 HF private 저장소에 parquet 으로 올린다
(`qurious-quant/alphastack-krx-dev`). 받는 쪽은 **pandas 만 있으면 된다** —
`torch`·`transformers` 를 깔 필요도, Docker 를 띄울 필요도 없다.
