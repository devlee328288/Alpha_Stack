## 한 줄로

**v4.0 이 찾아낸 것을 실제로 닫은 판**입니다.

v4.0 은 *"퀀트가 원래 지키는 것 중 우리가 안 지키는 것"* 을 일곱 축으로 재서 **다섯이
못 미친다**고 적었습니다. v4.1 은 그중 **셋을 닫았고**, 닫는 과정에서 **v4.0 이 틀리게
적은 것 하나를 정정**합니다.

| v4.0 이 지적한 것 | v4.1 |
|---|---|
| §3.5 판정을 만들어 두고 파일에 안 싣는다 | ✅ **닫음** — 반출본 28 → **34칸** |
| §3.3 유효성 축이 원장에 없다 | ✅ **닫음** — 원장 5 → **7축** · 위반 0행 |
| §3.4 거래량 급변 검사가 없다 | ✅ **닫음** — **KRX 시장경보 기준**으로 |
| §3.2 현금배당을 안 편다 | ⏳ 다음 (수집 72콜) |
| §3.1 기업행위 이벤트 표가 없다 | ⏳ 다음 |

마이너를 올린 것은 **방향이 바뀌지 않았기 때문**입니다. v4.0 이 세운 로드맵을 그대로
따라 A·C 를 실행했습니다.

## 1. 판정을 파일에 싣는다 — 28 → 34칸

### 1.1 주권종류 3칸 — **판정이 안 바뀌는 것을 먼저 쟀다**

지금까지 개발본에 주권종류가 없어서, 받아 쓰는 쪽이 **종목명이 '우' 로 끝나는지**로
보통주를 추측했습니다. 연우·동우·신우·미래에셋대우처럼 이름이 '우' 인 **보통주**를
우선주로 잘못 뺍니다.

**바꾸기 전에 판정이 달라지는지부터 쟀습니다** — 개발구간 7,888,945행 전량:

| | |
|---|---|
| `stock_base_info` 조인 커버리지 | **100.0000%** (미매칭 0행) |
| 이름 규칙 + 예외 10건 **vs** `kind_stkcert_tp_nm` | **불일치 0행** |

유니버스가 한 종목도 안 달라지므로 `AUDITED_COMMON_EXCEPTIONS`(9건) ·
`AUDITED_NON_COMMON_EXCEPTIONS`(1건) · `_looks_preferred` · `AUDIT_END` 가드를 전부
지웠습니다. **감사 범위(`20260831`) 뒤 날짜를 거부하던 제약도 함께 사라집니다.**

`secugrp_nm`·`sect_tp_nm` 까지 싣는 이유는 우선주만으로는 유니버스를 못 고르기
때문입니다.

| 빼는 것 | KOSPI200 방법론 | CRSP | 우리 칸 |
|---|:--:|:--:|---|
| 우선주 | ✅ | ✅ shrcd 10/11 | `kind_stkcert_tp_nm` |
| 리츠 · 선박투자회사 · 투자회사 | ✅ | ✅ REIT/closed-end | `secugrp_nm` |
| 외국주권 · ADR | — | ✅ | `secugrp_nm`·`sect_tp_nm` |
| SPAC · 관리종목 | ✅ | ✅(SPAC) | `sect_tp_nm` |

🔴 **판정은 대신 하지 않습니다.** KOSPI200 방법론은 "유동주식비율 10% 미만" 도
제외하는데 우리는 그 데이터가 없습니다. 파생 칸 하나로 뭉치면 *"이대로 쓰면 KOSPI200
과 같다"* 는 오해를 부릅니다. **원문 값을 싣고 재현 레시피를 카드에 코드로** 적었습니다.

### 1.2 기업행위 3칸 — 근사가 절반만 잡고 있었다

| | 개발구간 | |
|---|---:|---|
| `is_liquidation` | 17,973 | 0.228% |
| `is_halted` | 231,808 | 2.938% |
| `is_first_listing` | 1,501 | 0.019% |
| **셋 중 하나라도** | **251,282** | **3.185%** (겹침 0) |

v4.0 은 근사값(3.063%)을 적었는데, `flag_series` 정식 판정으로 재니 **정리매매가
2.17배**(8,299 → 17,973)입니다. 근사는 *"소멸 종목의 마지막 10체결일"* 이라,
**상장폐지 절차 중 거래가 재개된 종목**(감마누·인포피아·우양에이치씨)은 정리매매가
이력 한가운데 있어 영원히 못 닿습니다.

`is_halted` 는 `flag.halt_resume` 이 아니라 **`not is_traded(row)`** 입니다 —
`training_frame` 이 덜어내는 기준과 **같은 함수**여야 두 벌이 같은 표본이 됩니다.

🔴 **셋 다 표본 선택용입니다.** `is_liquidation` 은 *"이 뒤로 체결이 끊긴다"* 를 보고
매기므로 피처로 쓰면 미래참조입니다. 카드와 테스트가 그것을 강제합니다.

### 1.3 작은 벌과 큰 벌이 다른 규칙 위에 서 있었다

이것이 [#186](https://github.com/devlee328288/Alpha_Stack/issues/186) ① 의 요점입니다.
`stocks30_train` 은 셋을 덜어낸 표본인데 `full/daily_price_dev.parquet` 은 안 덜어낸
표본이고, **카드는 큰 벌을 "최종 학습용은 이것" 이라 불렀습니다.**

카드에 §표본 절을 새로 넣어 그 차이를 한 줄로 맞출 수 있게 했습니다.

```python
df = df[~(df.is_liquidation | df.is_halted | df.is_first_listing)]
```

## 2. 원장 5축 → 7축

### 2.1 `validity` — 표준 6차원 중 없던 축

**체결이 있던 행만** 잽니다. 정지행을 위반으로 세면 231,808행(2.938%)이 통째로
붉어지는데, 그건 규칙 위반이 아니라 KRX 의 정지 표기입니다.

| 지표 | 값 | 판정 |
|---|---:|:--:|
| `ohlc_order_rows` | 0 | ✅ |
| `market_cap_identity_rows` | 0 | ✅ |
| `negative_value_rows` | 0 | ✅ |
| `nonpositive_open_rows` | 124 | 기록 |

### 2.2 `volume` — 기준을 베끼지 않았다

배수(3배)는 세 표준이 같은데 **무엇에 대한 3배인지가 값을 2배 바꿉니다.**

| 기준선 | 전체 | KOSPI 상위 50 |
|---|---:|---:|
| **KRX 시장경보 (5일 평균)** | **5.426%** | 1.374% |
| qlib (전일) | 7.977% | 1.908% |
| 20일 중앙값 | 10.329% | 2.353% |

**KRX 시장경보 기준**(시장감시규정 시행세칙의 투자주의 지정 요건)을 씁니다 —
규제기관의 정의라 방어가 쉽고 셋 중 가장 보수적입니다.

**붉게 두지 않습니다.** 10배 초과 254행 중 자본변동은 15.0%뿐이고 `is_extreme_return`
과 0.0% 겹칩니다. 열어 보면 전부 설명되는 사건입니다 — 삼성전자 액면분할
재상장(158.7배) · SK바이오팜 보호예수 해제(73.1배) · HMM 인수전(50.0배).

## 3. 작업 중 찾은 결함 셋

### 3.1 v4.0 §3.3 의 설명이 틀렸다

*"`open ≤ 0` 인데 고가·저가는 살아 있다"* 고 적었는데 **고가·저가도 0** 이었습니다.
정규장 체결 없이 **시간외 단일가만 체결된 날**입니다. 숫자 124 는 맞고 문장만
틀렸습니다 → [퀀트기준_대조 §3.3.1](퀀트기준_대조.md) 에서 정정.

### 3.2 카드에 근거가 아예 안 나가고 있었다

원장 표가 `| 축 | 지표 | 값 | 붉은 기준 | 판정 |` 이라 `note` 가 빠졌습니다.
`adj_suspect_rows` 가 1,353 인 것만 보이고 *"gap > 1.0%p · 비교 가능 7,657,261행"*
이라는 근거는 어디에도 없었습니다. **근거 칸**을 더했습니다.

### 3.3 🔴 축을 늘렸는데 읽는 칸을 안 늘려 `validity` 가 통째로 건너뛰어졌다

첫 반출에서 네 지표가 전부 `None` 이었습니다. `_read_export_daily` 가 376MB 를 다 읽지
않으려고 칸을 좁혀 읽는데, 그 목록에 `open`·`high`·`low`·`market_cap`·`listed_shares`
가 없었습니다.

**예외도 경고도 안 납니다** — 원장 파일에는 축 이름이 멀쩡히 있고 판정도 실려 있습니다.
값만 `None` 입니다. 이력 한 줄을 열어 보기 전까지 몰랐습니다.

`volume` 축이 살아남은 것이 오히려 위험했습니다. 그쪽은 `volume` 하나만 쓰는데 그 칸은
목록에 있었으니, 둘 중 하나만 조용히 죽어 *"새 축이 동작한다"* 로 보였습니다.

읽는 칸을 `EXPORT_DAILY_COLUMNS` 상수로 빼고 17칸으로 늘린 뒤 **계약 테스트**로
묶었습니다 — `test_원장이_읽는_칸이_모든_축을_덮는다`.

### 3.4 🔴 같은 모양이 판정기에도 있었다 — **세 번째**

`scripts/verify_hf_dataset.py` 는 반출본과 DB 를 대조하는데, **반출이 `daily_price`
위에 얹는 파생 칸을 모릅니다.** 그래서 *"칸 구성이 다르다 → 재배포가 필요하다"* 는
**거짓 붉은불**을 냅니다.

그 파일에는 이미 이런 주석이 있었습니다.

> 🔴 업종 세 칸은 `daily_price` 에 없다 … **2026-09-05 에 실제로 겪었다**: 업종 칸을
> 올리고 나서도 재배포 필요가 나왔는데, 원인은 배포본이 아니라 **판정기가 반출을
> 안 따라간 것**이었다.

**주석까지 있는데 반복됐습니다.** 09-05 업종 3칸 → 09-08 품질 4칸 → 09-09 주권종류·
기업행위 6칸. 붙이는 자리가 반출 스크립트에만 있고 판정기가 그것을 참조하지 않으니,
칸이 늘 때마다 같은 일이 납니다.

`_attach_export_derived` 한 함수에 넷을 모아 **다음에 칸이 늘면 그 한 곳만** 고치게
했습니다.
