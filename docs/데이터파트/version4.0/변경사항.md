> 2026-09-08 밤 · 이동원 · 이전 판 [v3.9](../version3.9/변경사항.md)
> 실측 기준 커밋 `703ccab` (PR #184 머지 직후) · 환경 anaconda 3.12.13 · 반출본 `2026-09-08`

## 한 줄로

**밖을 보고 우리 자리를 잰 판**입니다. v3.9 까지는 *"우리가 무엇을 했나"* 를 적었는데,
이 판은 *"퀀트가 원래 지키는 것 중 우리가 안 지키는 것은 무엇인가"* 를 묻습니다.

계기는 재배포 직전의 판단 보류였습니다. 품질 플래그 4칸을 실은 반출본을 만들어 검사까지
전부 통과시켜 놓고, 팀장이 *"데이터 쪽에서 부족한 부분이 많은 것 같은데 퀀트 측면에서
확인해보고"* 라고 해서 올리지 않았습니다. **그 판단이 맞았습니다** — 일곱 축을 재 보니
표준에 못 미치는 것이 다섯 나왔고, 그중 둘은 라벨에 직접 닿습니다.

메이저를 올린 것은 새 문서 [퀀트기준_대조](퀀트기준_대조.md) 가 **이 파트의 방향을
바꾸기 때문**입니다. 지금까지의 로드맵은 "수집을 넓힌다" 였는데, 이제
**"이미 아는 것을 파일에 싣는다"** 와 **"총수익 축을 만든다"** 가 앞에 섭니다.

## 1. 🆕 퀀트기준_대조 — 이 판의 본체

[전문](퀀트기준_대조.md) 을 보시고, 여기서는 결론만 옮깁니다.

### 1.1 참고할 국내 사례가 없다

`gh search repos` 로 훑은 결과 국내 최대가 `FinanceDataReader` ★1,539 ·
`pykrx` ★1,088 입니다. **둘 다 값을 가져다주는 도구**이지 *"언제부터 알 수 있었나"* ·
*"이 값이 성한가"* 를 답하지 않습니다. 그래서 해외(qlib ★48,408 · zipline ★20,082 ·
CRSP)와 맞댔습니다.

### 1.2 우리가 이미 표준을 넘은 것 셋

| | 표준 | 우리 |
|---|---|---|
| 생존 편향 | 국내 튜토리얼 대부분이 "오늘 상장 종목"으로 과거를 본다 | 개발구간 중 끊긴 종목 **750개 보존** |
| 시점 정합성 | qlib 에도 `as_of` 강제가 없다 | 기본값 없는 키워드 인자 · `known_at` 4축 |
| 품질 원장 | qlib 건강검사 **4개** | **5축 17지표** + 이력 + 카드 게시 |

### 1.3 표준에 못 미치는 것 다섯

| # | 무엇 | 실측 |
|---|---|---|
| ① | 기업행위 **이벤트 표**가 없다 (zipline 은 세 표) | 결과·출처만 남기고 사건은 가격에서 역산 |
| ② | **현금배당을 안 편다** — 우리 수익률은 CRSP `RETX` | 배당락일 **−0.455%p** · 15년 중 11년 음수 |
| ③ | **유효성(Validity)** 축이 원장에 없다 | `open ≤ 0` 인데 고가·저가는 살아 있는 행 **124** |
| ④ | 거래량 급변 검사가 없다 | qlib `large_step_threshold_volume=3` |
| ⑤ | **판정을 만들어 두고 파일에 안 싣는다** | 큰 벌에 남은 비정상 거래일 **3.063%** |

### 1.4 그대로 베끼면 안 된다

qlib 의 거래량 급변 기준(3배)을 켜면 **전체의 7.953%** 가 붉어집니다. 우리 유니버스
(KOSPI 상위 50)에서는 1.889%, 10배 기준으로는 0.088%(154행)입니다. 한국 소형주
거래량 분포에 3배는 너무 촘촘합니다 — **기준은 유니버스에 맞춰 우리가 정합니다.**

## 2. ⑤가 가장 자주 반복되는 결함이다

품질 플래그 4칸을 실은 것(#168)이 이 결함을 **한 번 고친 것**인데, 같은 자리가
더 있습니다.

| 공급 층에 있는 판정 | 반출본에 | 결과 |
|---|---|---|
| 업종 4칸 | ✅ | — |
| 수정주가 품질 4칸 | ✅ **09-08 실음** | — |
| **주권종류** | ❌ | `stock_training_universe.py` 가 **이름 규칙 + 감사 예외 10건**으로 재구성 |
| **증권그룹**(리츠·SIB·DR) | ❌ | 유니버스에서 못 거른다 |
| **정리매매·거래정지·신규상장** | ❌ | 큰 벌에 3.063% 그대로 |

특히 마지막이 뼈아픕니다. `supply.training.training_frame` 이 이 셋을 떨어내므로
**작은 벌(`stocks30_train`)은 걸러진 표본**(89,424 → 82,852행)인데, **큰 벌은 안
걸러집니다.** 그런데 카드가 큰 벌을 **"최종 학습용은 이것"** 이라고 부릅니다.
둘로 학습하면 결과가 갈리는데 칸 구성만 보고는 알 수 없습니다.

## 3. HF 재배포 — 만들어 두고 보류했다

반출본 `data/outbox/2026-09-08` 은 **완성돼 있습니다.**

```
칸 24 → 28 (품질 플래그 4칸)      · 행 7,888,945 그대로
MANIFEST 파일 8개 중 7개가 SHA-256 까지 동일
   → 팀원이 다시 받을 파일은 full/daily_price_dev.parquet 하나
검증기 4종 ✅ · 홀드아웃 누수 검사 8개 파일 전수 ✅ · private ✅
품질 원장 판정 red (붉은 항목 1개 · outlier.adj_suspect_rows · chain 117행)
```

**기존 24칸의 값은 한 행도 안 바뀌었습니다** — 7,888,945행을 칸마다 맞대 확인했습니다.
새 4칸도 `flag_adjustment_quality` 를 부르지 않고 **정의에서 독립 재계산**해
검산했습니다(값 차이 0 · 결측 엇갈림 0 · 두 플래그 겹침 0).

올리지 않은 이유는 §1 입니다. **§7 의 A 를 함께 넣어 한 번에 올리는 쪽이 낫습니다** —
지금 올리면 주권종류 세 칸 때문에 곧 또 올려야 합니다.

## 5. 배포 경로에서 찾은 결함 셋 (PR #183 · #184)

올리기 전에 **나갈 것을 실제로 그려 보고** 찾았습니다.

| 결함 | 왜 못 봤나 | 실측 |
|---|---|---|
| 카드 칸 설명 다섯이 빈칸 | **없는 것을 안 재서** | `industry_ambiguous` 가 세 번의 배포에서 비어 나감 |
| 판정기가 거짓 🔴 | **자기와 맞대서** | 낡은 스냅샷으로 "재배포 필요" · 자료는 이미 최신이었다 |
| 경고가 한쪽 칸에만 | **이름으로만 걸려서** | `change_rate` 에는 있고 `adj_return_1d` 에는 없었다 |

셋 다 **"바깥에 기준이 없었다"** 입니다. 거짓 🔴 을 그대로 믿었으면 안 해도 될
`adj_*` 재생성을 하면서 — 다시 만들면 옛 행이 나빠지는데 — 자료를 나쁘게 만들
뻔했습니다.

## 7. 다음 — 순서와 "무엇을 만들면 끝인가"

[퀀트기준_대조 §7](퀀트기준_대조.md) 에 자세히 적었습니다. 요약하면:

| 순서 | 무엇 | 만들면 끝나는 것 | 비용 |
|---|---|---|---|
| **A** | 판정을 파일에 싣는다 | 주권종류·증권그룹·소속부 3칸 + 정리매매·정지·신규상장 3칸 · `AUDITED_COMMON_EXCEPTIONS` **삭제** | 낮음 |
| **B** | 배당 → 총수익 축 | `dividend` 표(71,674행·72콜) + `adj_close_tr` 칸 + 라벨 두 벌 | 중간 |
| **C** | 원장에 두 축 | `validity` 축 · 거래량 급변(기준은 우리가) | 낮음 |
| **D** | 기업행위 이벤트 표 | `corporate_action` 표 · 역산이 아니라 이벤트에서 | 높음 |
| **E** | 이상치 처리 기준 문서화 | 규약에 윈저라이즈·스케일링 한 절 | 낮음 |

**A + C 를 먼저 하고 그때 재배포합니다.** B 는 팀 합의가 필요합니다 — 라벨 축이
바뀌면 모델·백테스트 결과가 전부 움직입니다.
