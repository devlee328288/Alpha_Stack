## 0. 한 줄로

`features/` 는 **원자 함수 층**과 **조립 층** 두 개로 나뉩니다. 조립 층이 원자 함수를
직접 다시 짜면 같은 공식이 두 곳에 생기고, 한쪽만 고쳐질 때 조용히 갈라집니다.
그 갈라짐을 찾아 이었고(#107 → #114), 비어 있던 **월간 수익률**을 채웠습니다(#116).

| 층 | 파일 | 무엇 |

조립 층은 **원자 함수를 부르기만 합니다.** 공식을 직접 쓰지 않습니다.

## 2. 🔴 이슈 #107 — 조립 층이 원자 함수를 다시 짜고 있었다

`model_dataset.py::_add_derived_features` 가 `indicators.py` 에 이미 있는 공식을
손으로 다시 쓰고 있었습니다.

| 피처 | 조립 층이 쓰던 것 | 원자 함수 |
|---|---|---|
| `sma_gap_5_20` | `out["sma_5"] / out["sma_20"] - 1.0` | `sma_gap(close, 5, 20)` |
| `sma_gap_20_60` | `out["sma_20"] / out["sma_60"] - 1.0` | `sma_gap(close, 20, 60)` |
| `macd_hist_ratio` | `out["macd_hist"] / close` | `macd_hist_ratio(close)` |
| `bb_position` | `(close - bb_lower) / (bb_upper - bb_lower)` | `percent_b(close, 20)` |

**값은 같았습니다.** 문제는 값이 아니라 **앞으로**입니다 — 원자 함수 쪽에 결측 방어나
분모 0 방어가 들어가면 조립 층은 그 수정을 못 받습니다. PR #114 가 넷을 전부 원자 함수
호출로 바꿨습니다.

> 신장환 님 주석: *"원자 함수가 나중에 고쳐지면 여기도 자동으로 같이 고쳐진다."*

이건 데이터 파트에서 겪은 것과 같은 모양입니다 — 반출 경로가 원가격을 보고 있어
피처를 고쳐도 반출본이 안 고쳐졌던 자리(#83)와 같은 종류의 빚입니다.

## 3. ⑭ 중기·장기 피처 — 이미 하나는 있었고, 하나를 더했다

데이터 파트가 "주간·월간 수익률이 통째로 없다" 고 적었는데(#111), 다시 재 보니
**주간은 이미 있었습니다.**

| 지평 | 피처 | 창 | 상태 |
|---|---|---:|---|
| 단기 | `daily_return` | 1거래일 | 기존 |
| **중기(주간)** | `five_day_return` | 5거래일 | **기존** — 데이터 파트가 못 보고 있었다 |
| **장기(월간)** | `monthly_return` | **20거래일** | 🆕 **PR #116** |

```python
RETURN_FEATURES = {"daily_return", "five_day_return", "monthly_return"}

out["daily_return"] = n_day_return(close, 1)
out["five_day_return"] = n_day_return(close, 5)
# 월간 = 20거래일. 새 숫자를 고른 게 아니라 이 파일이 이미 쓰는 관례
# (sma_20 · hv_20 등)를 그대로 따른다.
out["monthly_return"] = n_day_return(close, 20)
```

### 왜 20거래일인가

**새 숫자를 고른 것이 아닙니다.** 이 파일이 이미 `sma_20` · `hv_20` · `vol_sma_20` ·
`vwap_20` 에서 "한 달 = 20거래일" 을 쓰고 있어 그 관례를 따랐습니다. 달력 한 달(30일)이
아니라 **거래일 20일**입니다.

### 미래를 안 본다

`n_day_return` 은 `close_t / close_{t-window} - 1` 이라 **과거만 봅니다.** 앞쪽
`window` 자리는 `nan` 이고, 분모가 0 이하이면 `nan` 으로 막습니다(`inf` 가 조용히
흐르지 않도록).

## 4. 피처 조합 A~F (2026-09-05 실측)

`COMBINATION_FEATURES` 에 여섯 조합이 있고, 수익률 피처는 **선택해서 얹습니다**
(`build_model_dataset(..., return_features=("monthly_return",))`).

| 조합 | 피처 | 수 |
|---|---|---:|
| A | `rsi_14` · `bb_bandwidth` · `hv_20` · `vol_ratio_20` | 4 |
| B | `sma_gap_5_20` · `macd_hist_ratio` · `rsi_14` · `hv_20` | 4 |
| C | B + `bb_position` · `vol_ratio_20` | 6 |
| D | `sma_gap_20_60` · `rsi_14` · `atr_ratio` · `bb_bandwidth` · `hv_regime` · `obv_slope_20` | 6 |
| E | `atr_ratio` · `bb_bandwidth` · `hv_regime` | 3 |
| F | D + `sma_gap_5_20` · `macd_hist_atr` | 8 |

> ⚠️ 조합 A·B 는 [이슈 #37](https://github.com/devlee328288/Alpha_Stack/issues/37)에서
> **둘 다 기준선(42.50%) 아래**로 나왔습니다. 조합 선택은 모델 파트(오준영) 결정입니다.
