# 전처리 v1.0 → v1.1 변경사항 (2026-09-09)

> 정본은 [전처리 설계 명세서 v1.1](전처리-설계-명세서.md). 이 문서는 **무엇이 왜 바뀌었는지**만
> 적습니다.

## 한 줄

v1.0(2026-09-02)은 **세로축**(시계열 정리·시점 정합)을 설계했고 대부분 구현됐습니다. v1.1 은
**가로축**(그날 종목들끼리의 횡단면 전처리)을 새로 만들고, v1.0 의 전제 셋이 바뀐 것을 정정합니다.

## 1. 전제가 바뀐 것 셋 — 정정

| | v1.0 | v1.1 | 근거 |
|---|---|---|---|
| 1차 모델 | LightGBM + **Kronos** | LogReg·RF·XGBoost·LightGBM (+ARIMA) | Kronos 는 채택되지 않았습니다. 조합 A~J × 4모델로 정리됐고 1위는 **조합 J LogisticRegression**([PR #188](https://github.com/devlee328288/Alpha_Stack/pull/188)) |
| 홀드아웃 | `20210901` | **`20240901`** | [ADR 0005](../../decisions/0005-홀드아웃-2년.md) · [#63](https://github.com/devlee328288/Alpha_Stack/issues/63) |
| 수정주가 | "FDR 검증 예정" | **완료** — FDR + 감자 직접 보정 · 품질 플래그 4칸 반출 | [데이터 품질 규약 §6](../../데이터파트/version4.1/데이터_품질_규약.md) |

**512봉 연속 격자**(Kronos 입력용)는 쓰는 모델이 없어 보류했습니다. 딥러닝 계열을 다시 볼 때
되살립니다. **분수 차분**도 같은 이유로 미채택입니다.

## 2. 새로 만든 것 — 가로축 네 단계

[`features/preprocessing.py`](../../../features/preprocessing.py) ([PR #196](https://github.com/devlee328288/Alpha_Stack/pull/196)).
전부 순수 함수이고 **날짜 안에서 끝납니다.**

| 단계 | 기본값 | 왜 그 기본값인가 |
|---|---|---|
| ① winsorize | **MAD 3배 · 1.4826** | 분위는 꼬리 길이와 무관하게 늘 4.18%(횡단면 49종 → 1% = 0.49종) · 3σ 는 극단값에 끌려 꼬리가 길수록 덜 잡는다 · MAD 만 첨도 순서를 따라간다 |
| ② z-score | 날짜 안 · ddof=1 | 그날 σ 가 최대/최소 13.5배 흔들린다 · 전 구간 값과 2배 넘게 다른 날 3.1% |
| ③ 중립화 | 업종 (**기본 꺼짐**) | ICIR 0.1050 → 0.1144 · 시총까지 더하면 0.1085 로 도로 내려감 |
| ④ rank | gaussian (**기본 꺼짐**) | uniform·signed 도 제공 |

🔴 **③④ 를 기본에서 끈 이유** — 조합 G + RandomForest 에서 정확도가 0.3938 → 0.3731 로
떨어졌습니다. 라벨이 **절대 ±2% 밴드**라 횡단면 상대값과 축이 어긋나는 것이 유력한 설명이고,
같은 방향이 **조합 F**(횡단면 순위 6칸 · 기준선 대비 −0.24%p)에 이미 있었습니다. 검증 방법과
선택지는 [이슈 #197](https://github.com/devlee328288/Alpha_Stack/issues/197) 로 올렸고 **결정은
모델 파트**입니다.

## 3. 함께 확인된 것

- **전 표본 단조 변환은 트리에 사실상 무의미합니다** — 로그 0.02% · 전 표본 z 0.59% 만 예측이
  바뀝니다. "트리에 `StandardScaler` 가 필요 없다" 는 통념이 우리 자료에서도 맞습니다.
  반면 **횡단면 변환은 27~33%** 를 바꿉니다 — 날짜가 다른 두 행의 순서를 바꾸기 때문입니다.
- **IC 로는 winsorize 효과를 잴 수 없습니다.** IC 는 순위상관이고 ①② 는 순서를 보존합니다.
- **업종은 수익률 구조에는 뚜렷하고 피처 분산에는 흐릿합니다**
  ([노트북 02/06](../../../notebooks/02-품질·전처리/06.군집은-업종을-얼마나-따라가나.ipynb)) —
  ARI 0.363(무작위 0.000) vs 업종 R² 0.25~0.32(잡음 기대치 0.18). 우리 피처가 이미 정규화된
  비율·순위라 업종 성분이 지표 단계에서 빠지기 때문입니다.

## 4. 시험

47건 신설 — 손계산 대조, **누수 가드**(*"다른 날짜의 값을 바꿔도 오늘 결과는 같다"* 를 네 함수
전부에), 보호 칸 거부, 트리 불변성. **일부러 틀린 구현**(전 표본 z-score)을 같은 시험에 넣어
그 시험이 실제로 붉어지는지도 확인합니다.
