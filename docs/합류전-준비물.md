## ① KRX OpenAPI 인증키 — 각자 발급받습니다 ★

### 왜 각자인가

[이용약관 제7조 ⑤](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp)가 **인증키의 양도·증여를 금지**합니다.
팀장 키 하나를 넷이 돌려쓰면 약관 위반이고, 위반 시 제11조 ④에 따라 이용승인이 철회됩니다.
그러면 **팀 전체가 데이터를 못 받습니다.**

추가로 제8조 ④가 **인증키당 1일 10,000회**로 제한합니다. 넷이 한 키를 쓰면 한 사람이
백필을 돌리는 순간 나머지 셋이 막힙니다. 각자 키를 가지면 이 문제가 원천적으로 없습니다.

### 신청 절차 — 2단계입니다 (헷갈리기 쉬움)

인증키를 받았다고 바로 되는 게 아닙니다. **서비스별로 따로 신청**해야 합니다.

```
STEP 1. 회원가입 · 인증키 신청       → 관리자 승인 대기 (~1일)
STEP 2. 인증키 확인
STEP 3. 쓸 API 서비스마다 이용신청    → 또 관리자 승인 대기
STEP 4. 호출
```

**STEP 3 을 빠뜨리면** 코드가 아니라 서버가 거절합니다 — `401 Unauthorized API Call`.
이건 "키가 틀렸다"가 아니라 "그 API 를 신청 안 했다"는 뜻입니다.
(우리 코드는 이 둘을 구분해서 알려줍니다 — [`krx_data.py`](../ingest/clients/krx_data.py) 참고)

### 신청할 것

1. https://openapi.krx.co.kr 회원가입
2. **인증키 신청** (마이페이지)
3. 아래 **두 서비스**에 이용신청 — 1차 프로젝트에 필요한 전부입니다

   | 서비스 | API ID | 왜 필요한가 |
   |---|---|---|
   | 유가증권 일별매매정보 | `sto/stk_bydd_trd` | KOSPI 시세 |
   | 코스닥 일별매매정보 | `sto/ksq_bydd_trd` | KOSDAQ 시세 |

4. 승인되면 인증키를 저장소 루트의 `.env` 에 넣습니다

```bash
cp .env.example .env      # 견본을 복사하고
# .env 를 열어 KRX_API_KEY= 뒤에 받은 키를 붙여넣습니다
```

### ⚠️ `.env` 는 절대 커밋하지 않습니다

이 저장소는 **PUBLIC** 입니다. `.gitignore` 가 막고 있지만, push 전에 눈으로 확인하세요.

```bash
git status --short --untracked-files=all
```

목록에 `.env` 가 보이면 **push 하지 않습니다.** 한 번 올라간 키는 이력에 영원히 남고,
지우려면 히스토리 재작성이 필요한데 그건 이 저장소에서 금지입니다.

### 확인

```bash
.venv/Scripts/python.exe -c "from ingest.clients import krx_data; print(krx_data.get_status())"
```

`key_loaded: True` 가 나오면 됩니다. 값은 출력되지 않고 길이만 나옵니다.

## 미리 알아 두면 좋은 것

### 우리가 쓰는 데이터의 성격

| 사실 | 왜 알아야 하나 |
|---|---|
| KRX OpenAPI 는 **2010-01-04 부터** 준다 | 그 이전은 다른 경로가 필요합니다 (실측: 2009년은 0행) |
| **수정주가를 주지 않는다** | 종가를 그냥 이어 붙이면 액면분할일에 -98% 가 찍힙니다 |
| 대신 **등락률(`FLUC_RT`)이 분할 조정돼 있다** | 수익률은 종가 비율이 아니라 등락률 누적으로 만듭니다 |
| **날짜 스냅샷** 방식이다 | 과거 날짜를 부르면 그날 상장돼 있던 종목이 전부 옵니다 — 상장폐지 종목이 공짜로 따라옵니다 |

### 약관이 우리에게 요구하는 것

| 조항 | 우리가 할 일 |
|---|---|
| 제6조 ② 비상업적 이용만 | 교육 프로젝트라 문제없습니다. README 에 명시합니다 |
