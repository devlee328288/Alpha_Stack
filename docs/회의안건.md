## 🔴 A. 먼저 정해야 코드가 나아간다

### A-1. 팀 Supabase — 팔 것인가, 어떻게 팔 것인가

**왜 지금 정해야 하나.** 이게 정해지기 전에는 아무도 실제 데이터로 학습할 수 없다.
현재 이관된 코드는 `STORE_BACKEND` 환경변수로 저장소를 고르는데, 기본값이 `sqlite` 라
로컬에 DB 파일이 없으면 빈 결과가 나온다.

- [ ] 팀 전용 Supabase 프로젝트를 새로 팔 것인가?
      → **개인 프로젝트 DB 를 그대로 쓰지 않는다.** 팀원 4명이 붙고, 실습 중 실수로
        지우는 일이 생길 수 있다. 개인 프로젝트는 계속 굴러가야 한다.
- [ ] 무료 티어 용량으로 충분한가?
      → 참고: 원본은 core 350종목 · 103,663행 · 111.9MB 다. 전종목(2,875)으로 가면
        821,928행이라 무료 한도를 넘길 수 있다. **먼저 재 보고 정한다.**
- [ ] 접근 권한을 어떻게 나눌 것인가? (전원 쓰기 vs 수집 담당만 쓰기)
- [ ] 커넥션 문자열을 어떻게 공유할 것인가? (`.env` 는 커밋 못 한다 — PUBLIC 레포)

### A-2. 예측 대상과 레이블 정의

**왜 지금 정해야 하나.** `features/` 가 이것 없이는 첫 줄도 못 쓴다.

- [ ] **예측 대상**
      - (a) 지수 하나 (KOSPI200) — 가장 단순. 1차 필수범위에 정확히 맞는다
      - (b) 개별 종목 몇 개 — 종목마다 성격이 달라 비교가 어려워진다
      - (c) 350종목 횡단면 랭킹 — 선택범위 ⑧. 데이터가 이미 있다
- [ ] **레이블 정의**
      - 다음날 **종가** 대비인가, **시가** 대비인가?
        → 종가 기준은 "종가에 사서 다음 종가에 판다"는 뜻인데 실제로 그렇게 못 산다
      - 보합 임계값을 둘 것인가? (예: ±0.1% 미만은 제외)
        → 두면 2분류가 아니라 **3분류**가 되고, 평가 지표도 바뀐다
- [ ] **예측 지평(horizon)**: 1일인가, 5일인가?
      → 5일이면 `evaluation.walk_forward` 의 `gap=5` 를 반드시 켜야 한다
        (안 켜면 학습이 검증 답을 미리 본다 — 성능이 조용히 부풀어 오른다)

### A-3. 데이터 백필 범위

현재 원본이 가진 것은 **297거래일**(2025-06-09 ~ 2026-08-24)이다. 학습에는 얇다.

- [ ] 몇 년치를 채울 것인가? (수집 스크립트 `scripts/fetch_krx.py` 는 이미 있다)
- [ ] 누가 언제 돌릴 것인가? (250거래일 수집에 약 7분)
- [ ] 상장폐지 종목을 포함할 것인가?
      → **포함해야 한다.** 빼면 생존 편향이 생겨 백테스트가 실제보다 좋게 나온다.
        스키마는 이미 `is_delisted` 로 지원한다 (`sql/init/01-schema.sql:52`)
