## 🔴 A. 먼저 정해야 코드가 나아간다

### A-1. 팀 저장소를 팔 것인가 — Supabase vs parquet 스냅샷

**왜 지금 정해야 하나.** 지금은 로컬 SQLite 하나에 다 들어 있습니다
(`data/krx_cache.db` · 지수 195,864행 + 종목 7,726,776행). 팀원이 합류하면
**각자 자기 로컬에 수집해야 합니다** — 그게 괜찮은지 정해야 합니다.

- [ ] **선택지 셋**
      - (a) 팀 Supabase 를 새로 판다 → 커넥션 문자열을 저장소 밖 채널로 공유
      - (b) **1차는 parquet 스냅샷 + 로컬 SQLite 만** — DB 결정을 2차로 미룬다 ← *조사 권고*
      - (c) 팀장 로컬 Postgres 를 정본으로 두고 스냅샷만 배포
- [ ] (a)라면 무료 티어 용량이 되는가? — **먼저 재 보고 정합니다**
- [ ] 커넥션 문자열을 어떻게 공유할 것인가? (`.env` 는 커밋 못 합니다 — PUBLIC)

> 📌 **(b)를 권하는 이유**: 1차는 **KOSPI200 지수 하나**를 씁니다. 4,097거래일 × 12컬럼이면
> parquet 로 수백 KB입니다. DB 가 필요한 규모가 아닙니다. 그리고 [F-02](요구사항/version1.0/요구사항.md)가
> 요구하는 **스냅샷 SHA-256 고정**은 파일이 오히려 쉽습니다.
>
> ⚠️ 다만 수집한 데이터를 **저장소에 커밋할 수는 없습니다** (약관 제11조 ②).
> 스냅샷을 어디에 두고 어떻게 공유할지가 (b)의 진짜 질문입니다.

**코드 쪽 현황**: `STORE_BACKEND` 기본값을 `sqlite` 로 바꿔 두었습니다
([ADR-AS-0003](decisions/0003-수집-계층.md)). A-1 이 (a)로 정해지면 `postgres` 로 되돌리고
`asyncpg` 를 의존성에 넣으면 됩니다 — 되돌릴 자리를 `common/settings.py` 주석에 남겼습니다.

- [ ] **팀원 제안 — 시장 균열 스코어** ([요구사항 F-30](요구사항/version1.0/요구사항.md))
      지수 가격은 오르는데 상승 종목 수는 줄어드는 **내부 괴리**를 점수화한 피처.
      기존 지표가 전부 **가격 하나**에서 나오는 반면 이건 **시장 내부 구조**라는 다른 정보원을 씁니다 —
      *"지표를 합치면 예측력이 오르는가"* 라는 1차 질문에 정확히 맞습니다.
      재료는 이미 있습니다(개별종목 **7,726,776행 · 3,339거래일 · 3,413종목** · 2013-01-16~).
      **조사 완료 — 조건부 채택.** 방향 예측은 기각(부호가 반대), **크기(변동성) 예측은 채택**.
      → [요구사항 §6](요구사항/version1.0/요구사항.md) · 비용 **2.5~3 인일**이라 인원에 따라 갈린다

> ⚠️ 지표를 많이 넣을수록 **시도 횟수가 늘어 다중검정 문제가 커집니다.**
> Bailey 등의 최소 백테스트 길이: **일간 5년이면 전략 변형 45개까지**가 한계입니다.
> 우리는 16년이라 여유가 있지만, 무한하지는 않습니다.
