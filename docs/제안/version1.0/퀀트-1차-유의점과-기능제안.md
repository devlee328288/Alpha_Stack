## 요약 — 큰 함정 4개는 이미 막혀 있습니다

| 함정 | 우리 상태 |
|---|---|
| 룩어헤드 (미래 참조) | ✅ `as_of` 정문 + 워크포워드 gap 잠금 + 경계 테스트 16개 |

## 1. 🔴 GridSearchCV 가 그 자리에서 누수를 만듭니다

수업(`07-ml/`)에서 배운 `GridSearchCV(cv=5)` 는 **테스트 폴드를 학습 데이터 한가운데**
놓습니다. 우리 라벨은 5일 앞을 보므로 **양쪽으로 샙니다.**

우리 워크포워드 엔진은 이미 gap 잠금이 있어 "학습 → 테스트" 방향은 막혀 있습니다.
구멍은 **하이퍼파라미터 튜닝 단계**입니다. 여기서 기본 CV 를 쓰는 순간, 이미 겪었던
*"라벨 정렬 오류로 상관이 10.0배 부풀려진"* 사고와 같은 종류가 재발합니다.

### 즉시 조치 — 신규 의존성 0

```python
# ❌ 쓰지 마세요
GridSearchCV(model, params, cv=5)

# ✅ sklearn 1.9.0 에 이미 있습니다
from sklearn.model_selection import TimeSeriesSplit
GridSearchCV(model, params, cv=TimeSeriesSplit(n_splits=5, gap=5))
```

라벨 지평이 5거래일이므로 **`gap >= 5`** 입니다.
그다음 단계로 앞뒤 양쪽을 잘라내는 Purged K-Fold 를 40줄쯤 직접 구현합니다.

> 근거: López de Prado, *Advances in Financial Machine Learning* (Wiley 2018)
> 7장 *Cross-Validation in Finance* — §7.3 *Why K-Fold CV Fails in Finance* (p.104),
> §7.4 *A Solution: Purged K-Fold CV* (p.105)

**담당**: 오준영(모델) · 검수 강민석 · **0.5일**

## 2. 🔴 우리 데이터는 수정주가가 아닙니다 — 양쪽 꼬리가 기업 이벤트입니다

이번에 직접 재 봤더니 **극단값의 양쪽 꼬리가 모두 수익률이 아니었습니다.**

### 위쪽 꼬리 — 액면병합·감자

| 날짜 | 종목 | 전일 종가 | 당일 종가 | 등락률 |
|---|---|---:|---:|---:|
| 2013-09-11 | 에스와이코퍼레이션 | **1원** | 67,000원 | **+6,699,900%** |
| 2026-02-09 | 제일바이오 | 2,080원 | 625,000원 | **+29,948%** |
| 2015-07-06 | 아남전자우 | 17,500원 | 128,000원 | +631% |

`change` 와 `close` 로 역산해도 저장값과 정확히 일치합니다 — **파싱 버그가 아니라
액면병합·감자를 조정하지 않은 원주가**입니다.

```
+30.5% 초과   354행
+100% 초과    111행      ← 일간 상한 30% 인데 물리적으로 불가능
```

### 아래쪽 꼬리 — 정리매매

```
-30.5% 이하 1,224행  →  그중 1,197행(97.8%)이 소멸 종목의 마지막 10거래일
-50%   이하   637행  →  그중   625행(98.1%)
최저 -98.41%
```

한국은 일간 등락이 ±30%로 제한되는데 **정리매매 구간만 예외**입니다.
상장폐지 종목을 성실히 포함했기 때문에 **반대 방향의 편향이 새로 생긴** 것입니다.

### 왜 치명적인가

모델은 *"5일에 −90%"* 나 *"하루에 +6,700,000%"* 를 초대형 신호로 배웁니다.
백테스트는 그걸 피하거나 올라타서 **거대한 가짜 수익**을 만듭니다.
실제로는 유동성이 없어 체결되지 않고, 애초에 수익률도 아닙니다.

### 조치

| 무엇 | 어떻게 |
|---|---|
| 정리매매 | 소멸 종목의 **마지막 10거래일 제외** (구현 완료 · `--keep-liquidation` 로 비교 가능) |
| 액면병합·감자 | \|등락률\| > 30.5% 행을 **플래그 테이블**로 분리해 라벨·피처에서 제외 |
| 문서화 | *"원주가를 쓰며 액면 변경은 이렇게 처리했다"* 를 명시 — **안 적으면 그 자체로 감점** |

> 정직하게 덧붙이면, 정리매매 제외는 **평균을 거의 안 바꿉니다**(E\|5일수익\| 4.4890 →
> 4.4832%). 2,940행뿐이라서입니다. **평균이 아니라 꼬리가 문제**이고, 백테스트 손익은
> 꼬리가 만듭니다.

**담당**: 이동원(데이터) · 신장환(품질 리포트) · **1일**

## 3. 🔴 시행 횟수를 지금부터 세지 않으면 나중에 보정할 수 없습니다

우리 사전등록은 stationary block bootstrap(B=10,000)을 봉인했는데, 이건 **전략 하나의**
귀무분포입니다. 몇 개를 시도해서 그중 최고를 골랐는지는 **전혀 반영하지 않습니다.**

### 데이터 길이가 허용하는 시행 횟수에 상한이 있습니다

**Minimum Backtest Length** (Bailey·Borwein·López de Prado·Zhu, *Notices of the AMS* 61(5), 2014)
를 우리 개발구간 11.4년에 적용하면:

```
목표 Sharpe 1.0  →  허용 독립 시행  N ≤ exp(11.4 / 2)      ≈ 300회
목표 Sharpe 0.7  →                   N ≤ exp(11.4·0.49/2)  ≈  16회
목표 Sharpe 0.5  →                                            13회
```

**킥오프에서 이 숫자를 화이트보드에 적읍시다.** 6칸 포지션 매트릭스를 2지선다로만 열어도
64개, 사이징까지 곱하면 256~1,280개입니다 — **예산의 5~100배**입니다.

### 오늘부터 해야 할 것

```
trials.jsonl  (한 줄 = 한 시도)
  {"ts": ..., "who": "오준영", "what": "LightGBM num_leaves 31→63",
   "dataset_sha": "...", "dev_sharpe": 0.41, "why": "..."}
```

`GridSearchCV` 의 조합 수도 **전부 N 에 합산**합니다.
이게 있어야 나중에 **Deflated Sharpe Ratio** (Bailey & López de Prado, *JPM* 40(5), 2014)
를 계산할 수 있습니다 — 필요한 건 시행횟수 N, 시행 Sharpe 들의 분산, 표본 길이, 왜도·첨도뿐이고
`scipy` 만 있으면 40줄입니다.

**담당**: 이동원(스키마 오늘 확정) · 전원(기록) · 강민석(DSR 구현) · **0.5 + 1일**

## 4. 🔴 우리 데이터 기간에 제도 변경이 두 건 들어 있습니다

### ① 가격제한폭 확대 (2015-06-15, ±15% → ±30%) — 개발구간 한가운데

우리 데이터로 직접 확인했습니다:

| 연도 | +15.5% 초과 건수 |
|---|---:|
| 2013 | 31 |
| 2014 | 17 |
| **2015** | **2,072** |
| 2016 | 2,140 |

변동성 기반 피처(σ, ATR, 상하한가 근접도)는 이 날짜에 **구조적 단절**을 갖습니다.
전 구간을 통짜로 정규화하면 2010–2015 와 2015–2021 이 서로 다른 척도로 섞입니다.

→ **조치**: 롤링 표준화(예: 60일 z-score)로 수준 단절을 흡수합니다.

### ② NXT(넥스트레이드) 출범 (2025-03-04) — 검증구간 한가운데

2025년 3월 국내 두 번째 주식시장이 열렸습니다. 거래량의 일부가 그쪽으로 옮겨갔으므로
**KRX 데이터만 보면 "갑자기 거래가 줄었다"로 보이지만 실제로는 이동한 것**입니다.

> ⚠️ 우리 데이터로 KRX 평균 거래량을 봤을 때는 뚜렷한 단절이 **보이지 않았습니다**
> (2024년 560,824 → 2025년 출범 후 507,061 → 2026년 648,668). 조사가 보고한 비중
> (거래량 기준 13.6%)만큼의 충격이 평균에는 안 나타납니다. **확인되지 않았다고 적어 둡니다.**
> 다만 검증구간은 1회 개봉이라 나중에 발견하면 되돌릴 수 없으니, 거래량 피처를 쓸 거라면
> 지금 롤링 표준화를 걸어 두는 편이 안전합니다.

**담당**: 이동원(단절 지점 문서화) · 신장환(정규화 방식) · **0.5일**

## 5. 정확도만 보고하면 안 됩니다

우리 실측이 이 함정을 이미 보여줍니다:

- 지수에서 **"항상 상승"이 52.64%** 입니다. 모델이 53%를 찍으면 기쁘겠지만 아무것도 배운 게 없습니다
- 종목 3분류(30.12/37.90/31.98)에서 **"항상 중립"만 찍으면 37.9%** 로 랜덤(33.3%)을 이깁니다

### 보고 규약 — 지금 못 박읍시다

> **accuracy 단독 보고 금지.** 반드시 함께 냅니다:
> `(기준선 정확도, MCC, balanced accuracy, macro-F1, 혼동행렬)`

**MCC** 는 혼동행렬 네 칸이 모두 맞아야 높게 나옵니다(Chicco & Jurman, *BMC Genomics* 21:6, 2020).
`sklearn` 에 `matthews_corrcoef` · `balanced_accuracy_score` 가 이미 있습니다.

그리고 **최종 판정은 통계 지표가 아니라 경제 지표**로 합니다 — 사전등록이 이미 그렇게 정했습니다.

**담당**: 강민석 · **0.5일**

## 6. 기대치를 먼저 맞춥시다

**Hou·Xue·Zhang, "Replicating Anomalies"** (*RFS* 33(5), 2020): 학계가 발표한
**452개 아노말리 중 65~82%가 재현에 실패**했습니다.

세계 최고 수준의 학자들이 40년간 발표한 것이 그렇습니다. 부트캠프 4명이 2주에 만든
5일 예측 모델이 유의한 초과수익을 낼 확률은 **매우 낮습니다.**

### 그래서 성공 기준을 이렇게 두면 좋겠습니다

> ❌ "수익을 냈다"
> ✅ **"가설을 사전등록하고 정직하게 기각/미기각했다"**

기준선 52.64%를 못 이겼다는 결과가 나와도 그건 실패가 아니라 **이 문헌과 정합적인 결과**
입니다. 그리고 우리는 사전등록·봉인·기준선 3종을 이미 갖췄으므로 *"재현 가능한 절차"*
라는 축에서는 상위권입니다.

> 참고: **Harvey·Liu·Zhu** (*RFS* 29(1), 2016) 는 새 팩터가 t > 2.0 이 아니라 **t > 3.0**
> 을 넘어야 한다고 주장합니다. 발표에서 *"저희는 t>2가 아니라 t>3을 기준으로 봤습니다"*
> 한 문장이 주는 신호가 큽니다.

## 넣으면 좋을 기능 — 비용 대비 효과 순

### ⭐ ① 반증 감사 (합성 데이터 통과 시험) — **가장 값싼 승리**

예측력이 **0인 데이터**에 우리 파이프라인을 통째로 태웁니다.

```
실제 수익률을 종목 내에서 블록 셔플 → 신호를 파괴
→ as_of → 피처 → 라벨 → 워크포워드 → 성과지표  전 경로 통과
→ 결과가 기준선 근처(52.64% 부근, ΔSharpe ≈ 0)여야 통과
```

**예측 불가능한 데이터에서 모델이 52% 이상을 찍으면 그건 능력이 아니라 누수입니다.**
우리가 겪은 *"라벨 정렬 10배"* 같은 배관 버그를 전부 잡습니다.

**담당**: 강민석 · **1.5일** · 발표에서 가장 세게 말할 수 있는 항목

### ② 데이터 품질 게이트 + 리포트

거래일 캘린더 대조 · 결측 · 이상치(위 §2의 양쪽 꼬리) · 중복. 기준 미달이면 **종료코드 1**.
**담당**: 이동원 · **1일**

### ③ 원커맨드 재현 파이프라인

`run_all.py` + `config.yaml` + 시드 고정 + dataset SHA. 발표에서 명령 하나로 돌립니다.
**담당**: 이동원 · **1일**

### ④ 폴드별 성능 분산 시각화

단일 막대 대신 **폴드 12개의 분포**를 보여줍니다. "평균은 좋은데 절반의 폴드에서 졌다"가
보이면 그게 정직한 그림입니다.
**담당**: 강민석 · **0.5일**

### ⑤ 승자의 저주 보정 (축소 추정)

여러 모델 중 최고를 골라 검증구간에 태울 계획이면, **개발구간의 그 최고 Sharpe 를 발표에
그대로 쓰면 안 됩니다.** 후보들의 Sharpe 를 평균 쪽으로 당겨 보고하고 원값과 나란히 놓습니다.
검증구간 Sharpe 는 선택이 개입하지 않았으므로(1회·사전 동결) 축소가 필요 없습니다 —
**이 대비 자체가 좋은 발표 포인트**입니다.
**담당**: 강민석 · **0.5일**

### ⑥ SHAP 피처 중요도

`shap.TreeExplainer` + LightGBM. "지표를 합치면 예측력이 오르는가"라는 우리 질문에
**어느 지표가 실제로 기여했는지**로 답합니다.
**담당**: 신장환 · **0.5일**

## 하지 말자고 제안드리는 것

| 무엇 | 왜 |
|---|---|
| **Keras LSTM/GRU** | 같은 문제에서 실측 **140배 비싸다** — 횡단면 100만행 12폴드에서 LSTM 4.8시간 vs LightGBM 2.1분. 전 종목이면 43.7시간. 시퀀스 텐서가 29.4GB로 RAM 33.9GB를 거의 다 먹는다. TensorFlow 2.10이 네이티브 Windows GPU 마지막 릴리스라 WSL2 세팅에만 1~2일 |
| **삼중 배리어 라벨링** | 라벨링 방법이 아니라 **파이프라인 전체를 바꾸는 결정**. 레이블 수명이 가변이 되면 워크포워드 gap 구조와 충돌하고 AFML 4장·7장이 통째로 딸려 온다. 5일 이상 추가 |
| **CPCV·Thresholdout·Ladder** | 우리는 이미 "봉인 + 1회 개봉"이라는 **가장 강한 방어**를 채택했다. 2주에는 그 규율을 지키는 게 어떤 알고리즘보다 강하다 |
| **quantstats HTML 리포트** | 화면에 "우리 Sharpe"와 "quantstats Sharpe" 두 숫자가 뜨고 "왜 다르냐"에 답을 못 한다. 우리 검증 엔진은 사전등록과 한 몸으로 설계돼 있다 |
| **matplotlib·seaborn** | 5화면 중 matplotlib이 있어야만 그려지는 그림이 **하나도 없다**. Altair 는 브라우저가 렌더링해 **한글 폰트 문제가 아예 발생하지 않는다** — 설치를 안 하는 것만으로 작업 항목 하나가 사라진다 |

> ⚠️ 딥러닝을 **"못 한다"가 아니라 "이번 2주엔 안 쓴다"** 입니다. 표 형태 데이터에서
> 트리 모델이 딥러닝을 이긴다는 벤치마크(Grinsztajn et al., NeurIPS 2022, 45개 데이터셋)가
> 있어서 **방어 논거도 있습니다.** 수업 진도가 9월 중 1D CNN·Transformer 까지 나가므로
> 여유가 생기면 선택 범위로 얹습니다.
