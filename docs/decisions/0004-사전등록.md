## 맥락

우리는 아직 **홀드아웃 구간을 한 번도 보지 않았습니다.** 지금이 이 문서를 쓸 수 있는
마지막 시점입니다.

숫자를 본 뒤에 가설을 쓰면 그것은 가설이 아니라 **관찰의 재진술**입니다. 금융 백테스트에서
이 실패는 이름까지 붙어 있습니다 — HARKing(Hypothesizing After the Results are Known),
그리고 그 결과물인 backtest overfitting.

> Arnott · Harvey · Markowitz (2019), *A Backtesting Protocol in the Era of Machine Learning*:
> "Researchers should be rewarded for good science, not good results."

발표는 9/13이고 킥오프는 9/1입니다. **9/11 저녁에 "0.048이 나왔는데 임계를 0.05로 둘까
0.1로 둘까"를 논의하게 될 확률은 낮지 않습니다.** 그 논의가 불가능하도록 지금 잠급니다.

[요구사항 F-05](../요구사항/version1.0/요구사항.md)의 수용 기준이 이것을 기계적으로 검사합니다 —
**이 파일의 git 커밋 시각이 `reports/unseal.log` 첫 행보다 앞서야 합니다.**
커밋 순서가 증거이므로, 이 ADR은 다른 어떤 `features/` 코드보다 먼저 커밋됩니다.

## 결정

### 1. 봉인 대상 — 무엇을 안 보고 있는가

| 구간 | 날짜 | 거래일 | 상태 |
|---|---|---|---|
| **개발** | 2010-01-04 ~ 2021-08-31 | **2,867** | 자유롭게 본다. 시도 횟수만 계측 |
| **봉인 홀드아웃** | 2021-09-01 ~ 2026-08-25 | **1,230** | **단 한 번** 연다 |
| 전체 | 2010-01-04 ~ 2026-08-25 | 4,097 | KRX Open API 실측 |

- 홀드아웃 개봉은 **1회**입니다. `reports/unseal.log` 행 수가 1이 아니면 실패입니다.
- 개봉 시각 기준으로 모델·피처·임계·비용 가정은 **이미 고정돼 있어야** 합니다(§6).
- 개봉 로그 형식을 여기서 못 박습니다 — F-04 구현은 이 형식을 따릅니다.

```
# reports/unseal.log — 한 줄 = 한 번의 개봉. 행이 2개가 되는 순간 프로젝트는 실패로 보고한다.
unsealed_at_kst | git_commit | snapshot_sha256 | preregistration_commit | requested_by | reason
```

### 2. 귀무가설

> **H₀ — 지표 종합 모델의 거래비용 반영 일간 초과수익(전략 − Buy&Hold)의 모평균은 0이다.**
>
> **H₁ (단측) — 그 모평균은 0보다 크다.**

기호로:

```
d_t = r_strategy_net(t) − r_buyhold_net(t)      (t = 홀드아웃 1,230 거래일)

H₀ : E[d_t] = 0
H₁ : E[d_t] > 0
```

**왜 단측인가.** 우리가 주장하려는 것은 *"이긴다"* 하나뿐입니다. 유의하게 **지는** 경우도
흥미롭지만 그것은 별도의 주장이고, 하나의 검정으로 양쪽을 다 주장하면 사실상 α를 두 배로
쓰는 셈입니다. 지는 방향은 §8의 "기각 실패" 문장이 그대로 받습니다.

**왜 Buy&Hold와의 차분인가.** 지수는 우상향해 왔습니다(223.49 → 1,060.68). 전략 수익률의
절대값을 검정하면 **시장을 들고만 있어도 기각되는** 검정이 됩니다. 우리 질문은
"지표를 합치면 예측력이 오르는가"이지 "주식이 올랐는가"가 아닙니다.

### 3. 주 지표 — 하나만 둡니다

| 구분 | 값 | 정의 |
|---|---|---|
| **주 보고 지표** | **ΔSharpe_net** | `Sharpe(전략_net) − Sharpe(B&H_net)`, 왕복 0.05% 반영, 연율화(252) |
| **주 검정 통계량** | **d̄** | 위 `d_t`의 표본평균 |

⚠️ **둘이 다르다는 점을 일부러 남겨 둡니다.** [문제정의 §2](../문제정의/version1.0/문제정의.md)는 주 지표를
ΔSharpe로 정했고 §3.1 기준 1은 초과수익 평균을 검정합니다. Sharpe는 비율 통계량이라
block bootstrap의 수렴이 평균보다 나쁩니다 — **검정은 평균으로 하고 보고는 Sharpe로**
하는 것이 통계적으로 안전합니다. 대신 둘이 어긋나는 경우를 막기 위해 기각 조건을
**둘 다 요구하는 연언(conjunctive)** 으로 둡니다(§4).

### 4. 기각 임계 — 절차를 전부 명세합니다

> **기각(예측력이 있었다) 조건 — 아래 둘을 모두 만족할 때만.**
>
> **(가) stationary block bootstrap 단측 p < 0.05**
> **(나) ΔSharpe_net > 0**

**검정 절차 (재현 가능하도록 전부 고정)**

| 항목 | 고정값 | 근거 |
|---|---|---|
| 재표본 방법 | **stationary block bootstrap** (Politis & Romano, 1994) | 블록 길이가 기하분포라 고정블록보다 정상성 가정에 덜 민감 |
| 기대 블록 길이 | **10 거래일** | 레이블이 t→t+5를 보므로 `d_t`는 **구조적으로 5일 자기상관**을 갖는다. 그 2배 |
| 재표본 횟수 B | **10,000** | p=0.05 부근 표준오차 ≈ 0.0022 |
| 시드 | **20260901** | 킥오프 날짜. 임의지만 **사전에** 고정한 것이 요점 |
| 유의수준 α | **0.05** | 단측 |
| p 계산식 | `p = (1 + #{b : d̄*_b − d̄ ≥ d̄}) / (B + 1)` | 부트스트랩 분포를 관측값에서 **중심화**. `+1` 보정으로 p=0을 만들지 않는다 |

**중심화를 빠뜨리지 않습니다.** `d̄*_b`를 그대로 0과 비교하면 H₀ 아래 분포가 아니라
관측 분포를 쓰는 것이 되어 p가 체계적으로 작아집니다.

**단 하나의 검정입니다.** 지평·비용·모델·임계를 바꿔 가며 여러 번 검정하지 않습니다.
그래서 다중검정 보정이 필요 없습니다 — 보정이 필요 없도록 **검정 수를 1로 설계**했습니다.

### 5. 보조 지표 — 임계를 걸지 않고 실측치만 보고합니다

아래는 **기각 판정에 쓰지 않습니다.** 그래서 다중검정 대상이 아닙니다.

| 보조 지표 | 형태 |
|---|---|
| 방향 정확도 | **스칼라 금지.** `(값, Wilson 95% CI, 표본수, Pesaran–Timmermann p)` 묶음 (F-10) |
| 기준선 3종 | `always_up` · `majority_class` · `previous_direction` 를 **같은 표에** 인쇄 |
| MDD · Turnover · cost_drag | 비용 전/후 둘 다 |
| 비용 손익분기 | ΔSharpe=0이 되는 왕복비용, 0.01% 간격 이분탐색, 소수점 2자리 |
| 누수 폭 | 무작위 K-fold vs `gap=5` 워크포워드 정확도 차이(pp) |
| MDE | 방향정확도 검출 한계(pp) |
| 시도 횟수 N · E[max] | `trials.jsonl` 행 수와 우연 기대 최고 정확도 |

**왜 여기에 합격선을 걸지 않는가.** 누수 폭에 임계를 걸면 *"누수를 크게 만들어야 통과하는"*
역인센티브가 생깁니다. 수치 게이트는 [문제정의 §3.1](../문제정의/version1.0/문제정의.md) 기준 2
(잡음 전략 100건 중 통과 ≤ 10%)가 맡습니다.

### 6. 홀드아웃 개봉 시점에 이미 고정돼 있어야 하는 것

개봉 **전에** 개발 구간(2010-01-04 ~ 2021-08-31)만으로 확정합니다. 개봉 후 변경은 §9 위반입니다.

- 피처 집합 (F-06 지표 목록과 파라미터)
- 레이블 정의 — 시가(t+1) → 시가(t+6), ±1.0% 3분류 (ADR-AS-0002에서 이미 고정)
- 모델과 하이퍼파라미터 (탐색은 개발 구간 내부 워크포워드로만)
- 신호→포지션 임계 θ (F-12). **폴드 검증 구간으로 θ를 조정하면 예외를 던집니다**
- `walk_forward` 설정 — `gap = horizon = 5` (F-09)
- 거래비용 주 시나리오 — ETF 왕복 **0.05%**
- 스냅샷 SHA-256 (F-02)

**⚠️ 아직 값을 못 정한 항목 — 그러나 "고르는 규칙"은 지금 고정합니다.**

[회의안건 A-3](../회의안건/2026-09-01-킥오프.md)이 *"확장창 vs 롤링창과 폴드 수를 사전등록 시점에 고정하라"*고
요구합니다. 그런데 우리는 **아직 개발 구간에서 아무것도 돌려 보지 않았습니다.** 값을 지금
찍으면 근거 없는 숫자가 되고, 나중에 정하면 사전등록이 아닙니다. 그래서 **값 대신 선택
규칙을 잠급니다** — 규칙이 잠겨 있으면 결과를 보고 유리한 쪽을 고를 수 없습니다.

| 항목 | 후보 | **선택 규칙 (지금 고정)** |
|---|---|---|
| 창 방식 | 확장창 / 롤링창 | 개발 구간에서 **둘 다** 돌려, **폴드별 ΔSharpe_net의 중앙값**이 큰 쪽. 동률이면 **확장창** (가정이 하나 적다) |
| 롤링창 `train_size` | 750 / 1250 / 2000 거래일 | 위에서 롤링창이 뽑혔을 때만. 같은 규칙(중앙값) |
| 폴드 수 | **12** (`DEFAULT_FOLDS`) | 고정. 성적을 보고 바꾸지 않는다 |
| `min_train` | **750** 거래일 (약 3년) | 고정. 기존 `MIN_TRAIN=120`은 ARIMA 기준이라 지표 모델엔 짧다 |

- 평균이 아니라 **중앙값**을 쓰는 이유: 폴드 하나가 코로나 급락 같은 극단 구간에 걸리면
  평균이 그 한 폴드에 끌려갑니다. 우리가 고르려는 것은 "대체로 나은 쪽"입니다.
- 선택이 끝나면 **개봉 전에** 그 결과값을 이 ADR §6에 추가 커밋합니다(§9가 허용).
  그 커밋 역시 `unseal.log`보다 앞서야 합니다.

**모든 `fit` 호출은 `trials.jsonl`에 기록됩니다**(F-13). 개발 구간에서 몇 번 시도했는지가
결론 문장에 그대로 들어가기 때문입니다 — 시도를 숨기면 p값이 거짓말이 됩니다.

### 7. 표본 크기와 검출 한계 — 지금 아는 것과 모르는 것

**아는 것 (KRX 원자료 실측, N=4,097 · 재현 `python scripts/check_index_data.py`)**

| 값 | 실측 |
|---|---|
| 기준선 "항상 상승" | **52.72%** |
| E\|일수익\| | **0.904%** |
| 손익분기 정확도 (5일 · 왕복 0.05%) | **51.24%** |
| 홀드아웃 표본 | **1,230일**, 1SE **1.43%p** |
| 홀드아웃에서 기준선을 유의하게 이기려면 | **55.07%** |

**모르는 것 — 미측정이라고 적습니다**

- **주 지표(ΔSharpe)의 MDE.** 위 55.07%는 *정확도* 기준이고 주 지표가 아닙니다.
  ΔSharpe의 검출 한계는 레이블 확정 후 개발 구간에서 시뮬레이션으로 잽니다.
- **5일 지평 손익분기 51.24%는 √5 근사입니다.** 실제 5일 절대수익 분포로 재측정해야 합니다.
- **슬리피지.** 0.07%p는 0.3%−0.23%의 잔차일 뿐 실측이 아닙니다.
- **중립 클래스 비율.** 세 클래스가 각 15~45%에 드는지 미확인 (F-07 수용 기준).

이 네 줄은 최종 리포트의 `assumptions` 블록에 **그대로** 실립니다.

### 8. 결론 문장 — 지금 둘 다 씁니다

> 최종 리포트 생성기(F-13)는 **이 블록을 읽어 `{}` 자리만 치환합니다.**
> 리포트의 결론 문자열이 이 템플릿과 **문자열 수준으로 일치**해야 합니다 (F-05 수용 기준).
> 문장을 고쳐 쓰는 것이 아니라 **빈칸만 채웁니다.**

**① H₀ 기각 — 예측력이 있었다**

```
지표 종합 모델은 KOSPI200 5거래일 방향에서 왕복 0.05% 반영 후 Buy&Hold 대비
연율 {excess_annual_pct}% 초과수익을 냈다
(ΔSharpe {delta_sharpe}, stationary block bootstrap 단측 p={p_value},
 홀드아웃 {n_holdout}거래일 1회 평가, 개발 구간 시도 {n_trials}회,
 우연 기대 최고 정확도 {expected_max_acc}%).
```

**② H₀ 기각 실패 — 예측력이 없었다**

```
지표 종합 모델은 KOSPI200 5거래일 방향에서 왕복 0.05% 반영 후 Buy&Hold 대비
초과수익을 내지 못했다 (ΔSharpe {delta_sharpe}, 단측 p={p_value}).
결론은 '이 피처·이 지평·이 비용 구간에서는 유효하지 않다'이며,
그것을 편향 없이 확증한 절차 — 누수 제거 폭 {leakage_pp}pp,
검증기 거짓 양성률 {false_positive_rate}%, 시도 횟수 {n_trials}회,
검출 한계 {mde_pp}pp — 가 이 프로젝트의 산출물이다.
```

**②도 성공한 프로젝트입니다.** 이 한 줄을 지금 적어 두지 않으면 9/11에 유리한 구간과
지표를 고르게 됩니다. 효율시장에 가까운 자산에서 **기각 실패가 정상에 가깝습니다.**

### 9. 변경·중지 규칙

| 상황 | 처리 |
|---|---|
| 홀드아웃 개봉 **전** 이 ADR을 고치고 싶다 | 가능. **새 ADR**(0005…)로 남기고 무엇을 왜 바꿨는지 적는다. 이 파일은 남긴다 |
| 홀드아웃 개봉 **후** 고치고 싶다 | **금지.** 고치는 순간 결과는 탐색적(exploratory)이며 확증적(confirmatory)이 아니다. 리포트에 그렇게 적는다 |
| `unseal.log` 행이 2개가 됐다 | 주 검정은 무효. 리포트 표지에 "홀드아웃 {n}회 개봉 — 확증 불가"를 인쇄한다 |
| 데이터 백필로 구간이 바뀌었다 | 개봉 전이면 §1 표를 갱신하고 스냅샷 SHA-256을 재고정. **개봉 후면 금지** |
| 코드 버그로 재실행이 필요하다 | 개봉 후라면 새 행이 남는다. 숨기지 않고 사유를 `reason`에 적는다 |

**이 ADR을 무효로 만드는 것**: 사전등록 커밋 시각이 `unseal.log` 첫 행보다 **뒤일 때.**
그 경우 우리는 사전등록을 했다고 주장할 수 없습니다.
