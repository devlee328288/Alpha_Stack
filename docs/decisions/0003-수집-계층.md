# ADR-AS-0003 — 지수 수집 계층을 세우고, KRX API 의 실제 성질에 맞춘다

| | |
|---|---|

## 맥락

[ADR-AS-0002](0002-예측대상과-레이블.md)가 예측 대상을 **KOSPI200 지수**로 정했습니다.
그런데 이관해 온 수집 클라이언트는 **종목 엔드포인트만** 알고 있었습니다
(`sto/stk_bydd_trd` · `sto/ksq_bydd_trd` · `sto/knx_bydd_trd`).

지수는 다른 문(`idx/kospi_dd_trd`)으로 들어가야 합니다. 그리고 실제로 돌려 보니
**KRX API 는 문서에 없는 성질이 여럿 있었습니다.**

---

## 결정

### ① 지수 수집을 별도 모듈로 세운다

```
ingest/clients/krx_data.py    INDEX_APIS · normalize_index_row · fetch_index_snapshot 추가
ingest/store/krx_index.py     index_price 표 (신규 모듈)
scripts/fetch_index.py        수집 CLI (신규)
scripts/check_index_data.py   품질 검사 + 기준선 측정 (신규)
```

**왜 `krx_store` 에 안 넣었나.** 그 파일은 이미 704줄이고 SQLite·Postgres 이중 읽기 경로를
안고 있습니다. 지수를 얹으면 "종목이냐 지수냐" × "SQLite냐 Postgres냐" 네 갈래가 한 파일에
생깁니다. 지수는 읽기 경로가 하나뿐이라 따로 둡니다.

**DB 파일은 같이 씁니다** — `krx_cache.db` 하나에 표만 나눕니다. 파일이 둘이면
백업·이동·스냅샷 해시가 둘로 갈라집니다.

### ② HTTP 호출부를 종목·지수가 공유한다

`_request_rows()` 하나를 둘이 씁니다. 인증 실패 판정·차단기·본문 오류코드 처리가
두 경로로 갈리면 **한쪽만 고치는 사고**가 납니다.

### ③ 지수 가격은 실수(REAL)로 저장한다

종목 시세는 원 단위 정수지만 **지수는 소수점을 가집니다** (코스피 200 = 1096.25).
`INTEGER` 로 두면 **하루 등락이 통째로 사라지는데 에러가 안 납니다.**

### ④ 지수 수집은 **순차**(`DEFAULT_WORKERS = 1`)로 한다

이게 이번 세션에서 가장 비싸게 배운 것입니다. 아래 §"실측" 참조.

### ⑤ 간헐적 401 을 재시도하고, 차단기는 연속 3회로 바꾼다

## 🔬 실측 — KRX API 가 실제로 어떻게 동작하나

전부 2026-08-26 에 우리 저장소 코드로 직접 잰 것입니다.

### 제공 범위

| 조회 | 결과 |
|---|---|
| `20090102` · `20091230` | **0행** |
| `20100104` | **1,961행** (KOSPI 925 + KOSDAQ 1,036) |

⚠️ **범위 밖이 에러가 아니라 빈 응답입니다.** 백필 스크립트가 0행을 정상으로 적재할 수
있으므로 `DATA_START = "20100104"` 를 코드에 못 박고 그 이전은 **아예 요청하지 않습니다.**

### 지수 엔드포인트의 모양

| 사실 | 값 |
|---|---|
| 한 번 부르면 오는 것 | **그 시장의 지수 전부** (KOSPI 51종 · KOSDAQ 40종) |
| 예측 대상의 정확한 이름 | **`"코스피 200"`** — 띄어쓰기 포함. `"코스피200"` 이 아니다 |
| 가격이 **빈 문자열**로 오는 지수 | `"코스피 (외국주포함)"` — 거래량·시가총액만 온다 |

한 콜에 51종이 다 오므로 **"코스피 200" 하나만 받든 전부 받든 콜 비용이 같습니다.**
그래서 전부 저장합니다. 섹터 지수는 나중에 피처가 됩니다.

### ⚠️ 동시 호출이 401 을 부른다 — 가장 비싼 발견

같은 날, 같은 키로 잰 결과입니다.

| 워커 수 | 결과 |
|---|---|
| 6 | 1,344일 받고 **차단** |
| 4 | 100일 받고 **차단** |
| **1** | **끝까지 진행** (4,343일 완주) |
| 순차 10회 연속 | **10/10 성공** |

**KRX 가 `429 Too Many Requests` 가 아니라 `401 Unauthorized` 로 답합니다.**
그래서 겉보기로는 *"인증키가 틀렸다"* 로 보이고, 키를 아무리 확인해도 답이 안 나옵니다.

이 함정에 **두 번 빠졌습니다** — 처음엔 일일 한도 소진으로, 다음엔 일시적 깜빡임으로
오진했습니다. 원인이 동시성이라는 것은 워커 수를 바꿔 가며 재고 나서야 알았습니다.

> 📌 **종목 엔드포인트는 워커 6으로 잘 돕니다.** 엔드포인트마다 다릅니다.
> 지수는 날짜당 1콜이라(종목은 2콜) 순차로도 16년이 감당됩니다.

### 하루 한도

이용약관 제8조 ④ — **인증키당 1일 10,000회**.

| 백필 | 콜 |
|---|---|
| 지수 16년 (KOSPI) | 4,343 (43%) |
| 종목 16년 (KOSPI+KOSDAQ) | 8,686 (87%) |
| **둘 다** | **13,029 (130%) — 한도 초과** |

👉 **같은 날 둘 다 못 합니다.** 한도는 KST 0시에 리셋되고, `fetch_log` 가 받은 날짜를
기억하므로 중단·재개가 안전합니다.

## 차단기를 어떻게 고쳤나

### 원래 동작 — 401 한 번에 즉시 차단

웹 서버에는 옳습니다. 키가 틀렸는데 사용자 요청마다 KRX 를 두드릴 이유가 없습니다.

**그런데 배치 백필에서는 치명적입니다.** 실측: 4,343콜 백필 도중 401 이 한 번 나자
**남은 3,000일이 45초 만에 전부 실패**했습니다(네트워크를 안 타므로 빨랐습니다).
곧바로 같은 날짜를 재시도하니 48행이 정상으로 왔습니다 — **키는 멀쩡했습니다.**

### 고친 뒤

```
논리적 요청 1회 = 최대 3회 시도 (0.5초 · 1.5초 백오프)
   → 재시도를 전부 쓴 뒤에야 차단기가 1을 센다
   → 연속 3회 실패해야 차단
   → 성공이 하나라도 끼면 카운터가 0 으로 돌아간다
```

| 요구 | 지켜지나 |
|---|---|
| 웹 서버: 틀린 키로 계속 두드리지 않는다 | ✅ 3번 만에 차단 |
| 배치: 깜빡임 하나로 멈추지 않는다 | ✅ 그 요청만 실패하고 계속 간다 |

두 요구를 **각각 테스트로 못 박았습니다** (`tests/test_krx_auth_retry.py` 8개).
한쪽만 보고 고치면 다른 쪽이 조용히 깨지는 자리이기 때문입니다.

## 함께 고친 것 — 조용히 틀리던 것 둘

### `.gitignore` 가 SQLite WAL 파일을 못 막고 있었다

```diff
- data/*.db
+ data/*.db*
```

SQLite 가 WAL 모드로 돌아 `krx_cache.db-wal` 을 만드는데(`PRAGMA journal_mode=WAL`),
`data/*.db` 는 하이픈 뒤가 붙은 이름을 **못 막습니다.**
실측: 수집 5분 만에 그 파일이 **9.6MB**까지 자랐고 내용은 전부 실제 시세입니다.

이 저장소는 **PUBLIC** 이고, KRX 이용약관 제11조 ② 가 제3자 제공을 금지합니다.
누가 수집 중에 `git add -A` 를 했으면 약관 위반이었습니다.

### `STORE_BACKEND` 기본값이 `postgres` 인데 `asyncpg` 가 없었다

```diff
- DEFAULT_STORE_BACKEND_LOCAL = POSTGRES
+ DEFAULT_STORE_BACKEND_LOCAL = SQLITE
```

원본(`data-service`)은 S6 에서 양쪽을 `postgres` 로 뒤집었습니다. Supabase 가 이미
서 있었기 때문입니다. **팀 저장소에는 그 Supabase 가 없습니다** (→ [회의안건 A-1](../회의안건/2026-09-01-킥오프.md)).

`.env.example` 은 이미 *"팀 Supabase 를 파기 전까지는 sqlite 로 둔다"* 고 적어 두었는데
**코드가 반대였습니다.** 팀원이 clone 직후 `fetch_krx.py --status` 하나에
`ModuleNotFoundError: No module named 'asyncpg'` 를 봅니다 —
*"설정을 안 했다"* 가 아니라 *"코드가 깨졌다"* 로 읽히는 실패입니다.

A-1 이 정해지면 되돌릴 자리를 주석에 남겼습니다.
