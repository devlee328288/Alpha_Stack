## 정본은 docx 가 아니라 **코드**입니다

⚠️ 이 폴더의 `.docx` 는 **산출물**입니다. 손으로 고치지 마세요.

내용의 정본은 [`scripts/build_project_plan.py`](../../scripts/build_project_plan.py)
안에 있고, docx 는 거기서 구워 나옵니다.

```bash
python scripts/build_project_plan.py
```

**왜 이렇게 하나.** 계획서는 한 번 쓰고 끝나는 문서가 아닙니다. 킥오프에서 미결이
닫히고 실측이 갱신될 때마다 고쳐야 하는데, Word 에서 손으로 고치면 **무엇이 왜
바뀌었는지 git 이 못 봅니다.** 내용을 코드에 두면 `git diff` 로 읽힙니다.

실제로 v2.0 은 네 번 고쳐졌고, 그 네 번이 전부 커밋으로 남아 있습니다 — 계획서
초판(`94874c2`) · 착수자산 수치 정정(`6123025`) · 종목/지수 결론 정정(`4d64ca5`) ·
유의임계 중첩보정(`e50c75d`).

### 스타일은 v1.0 에서 물려받습니다

`python-docx` 기본 템플릿은 한글 폰트(eastAsia)가 잡혀 있지 않아 Word 에서 글꼴이
어긋납니다. 그래서 스크립트가 **v1.0 docx 를 열어 본문만 비우고 다시 채웁니다.**
`version1.0/프로젝트계획서.docx` 를 지우면 빌드가 멈춥니다.

## 다음 버전을 팔 때

```bash
mkdir docs/계획서/version2.1
# scripts/build_project_plan.py 의 내용을 고치고
python scripts/build_project_plan.py --out docs/계획서/version2.1/프로젝트계획서.docx
# version2.1/변경사항.md 에 무엇이 왜 바뀌었는지 적는다
python scripts/check_doc_links.py    # 상대 경로가 바뀌므로 반드시 돌린다
```

### Major(+1.0) 인가 Minor(+0.1) 인가

| | 언제 | 예 |
|---|---|---|
| **Major** | 본표(9칸)의 값이 바뀐다 | 팀명·프로젝트명 확정 · 목표/분석방법 항목 증감 · 팀원 변동 |
| **Minor** | 부록·수치만 바뀐다 | 실측값 갱신 · 부록 문구 다듬기 · 일정 조정 |

킥오프(9/1)에서 프로젝트명·발표자·합격선이 정해지면 **본표가 바뀌므로 v3.0** 입니다.
