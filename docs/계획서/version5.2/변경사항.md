# 프로젝트 계획서 v5.1 → v5.2 — QFRS-1 에 총수익 축을 적는다

> 2026-09-10 · 이동원 · 정본은 [`scripts/build_project_plan.py`](../../../scripts/build_project_plan.py) ·
> [PR #226](https://github.com/devlee328288/Alpha_Stack/pull/226)

## 한 줄 요약

부록 F 의 QFRS-1(Dataset specification and data handling) 근거 칸에 **가격·총수익 두 축**을
적었습니다. 논문이 요구하는 *"처리 방법을 밝힐 것"* 에 배당 처리가 빠져 있었습니다.

## 왜 Minor 인가

본표(프로젝트 목표·분석 방법)가 바뀌지 않습니다. 부록 F 의 한 칸입니다. 계획서 버전
규칙상 부록 변경은 Minor 이므로 v5.2 입니다.

## 바뀐 것

### 부록 F · QFRS-1 근거 칸

| | v5.1 | **v5.2** |
|---|---|---|
| 기간 | 2010-01-04~**2026-08-25** | 2010-01-04~**2026-09-04** |
| 행 수 | **920만 행** | **923만 행** |
| 처리 방법 | 중도 소멸 910종목 포함 | 중도 소멸 910종목 포함 · 🆕 **가격·총수익 두 축(배당 71,681행)** |

QFRS-1 이 요구하는 것은 *"주식이면 상장폐지 종목 포함 여부와 **처리 방법**을 밝혀
생존편향을 통제할 것"* 입니다. 생존편향은 이미 통제하고 있었지만(중도 소멸 910종목 보존),
**배당을 어떻게 처리하는지는 적혀 있지 않았습니다.**

수정주가만 있으면 그것은 CRSP 로 치면 `RETX`(배당 제외)이고, 그 사실을 밝히지 않으면
읽는 사람이 `RET`(배당 포함)로 오해합니다. 이제 두 축을 다 갖고 있으므로 그렇게 적습니다.

## 무엇이 바뀌지 않았나

- **QFRS-2(Labeling)** — 라벨은 그대로 `시가(t+1) → 시가(t+6)` 3분류입니다. 총수익 축은
  **성과 평가용이지 라벨 축이 아닙니다.**
- 본표 9칸 · 나머지 부록 A~I
