# TIL — HF 두 층 업로드·수정주가 검증·Kronos 스모크 (2026-09-02 오후)

> 병행 세션: 수집 세션이 살아 있는 상태에서 worktree 를 따로 파서 진행했다.
> DB 는 읽기 전용, HF push 는 매번 사용자 확인 후. 그런데도 교차가 실제로 났다(아래 3).

## 오늘 배운 것

### 1. 세션 프롬프트의 스크립트 이름도 실측 대상이다

프롬프트에 적힌 반출 스크립트 이름과 실제 저장소가 달랐다 — 현재 브랜치가 main 보다
뒤라서 머지된 파일(`export_dart_dataset.py` 등)이 로컬에 안 보였던 것. `git ls-tree
origin/main` 으로 확인하고 나서야 전체 그림이 맞았다. **"없다"고 판단하기 전에
어느 기준(브랜치)에서 없는지부터 잰다.**

### 2. 서버 쪽 이동은 공짜다 — CommitOperationCopy

HF 의 벌크 43개(443MB)를 `bulk/` 아래로 옮기는 데 재업로드가 없었다. LFS 포인터만
복사하는 `CommitOperationCopy` 로 커밋 하나에 복사+삭제를 묶으면 끝. 단 **README 같은
non-LFS 파일은 Copy 를 못 쓴다** — 내려받아 `CommitOperationAdd` 로 같은 커밋에 넣었다.

### 3. HF 도 DB 처럼 동시 쓰기 자원이다

이 세션이 pit/ 층을 올린 8분 뒤, 수집 세션이 자기가 올렸던 `v6_with_receipt_date/`
층을 "중복 제거" 커밋으로 지웠다. 결과 구조는 원설계(2층)와 같아졌지만, 내가 방금
올린 루트 README 에는 v6 안내가 남아 **문서가 실제와 어긋나는 창**이 생겼다 — 정정
커밋이 하나 더 들었다. DB 는 `mode=ro` 규칙이 있었지만 HF 는 없었다.
**병행 세션이 같은 원격 저장소를 만질 때는 층 설계를 세션 시작 전에 맞춘다.**

### 4. 수정주가 검증은 세 겹이어야 믿을 수 있다

FDR 수정주가를 "갭이 사라졌으니 됐다"로 끝내지 않고 세 겹으로 쟀다.
① 분할일 FDR 갭 ↔ KRX `change_rate`(이미 조정된 독립 소스) — 3/3 일치 (−2.08%·+0.71%·+7.59%)
② 조정계수 역산 ↔ **DB 주식수 점프**(50.000배) — 50:1·5:1 공지 비율과 일치
③ 음성 대조군(무이벤트 2종) — 원주가/FDR 비율이 2,863일 내내 정확히 1.0000.
③ 이 없으면 ①②가 우연히 맞는 검증식일 가능성을 못 걷어낸다.

### 5. 원본 칸은 덮지 않는다 — 수정주가가 소급 재계산되기 때문

수정주가는 다음 분할이 나는 순간 **과거 전체가 다시 바뀐다.** `close` 를 덮으면
append-only 워터마크 반입과 충돌하고, `market_cap = close × listed_shares` 정합도
깨진다. 그래서 `adj_open/high/low/close` 4칸 신설로 확정 (#51 코멘트, 구현은 v8).

### 6. zero-shot 스모크의 목적은 품질이 아니라 완주다

Kronos-small 이 T4 에서 512봉→30봉을 로드 6.6초·예측 1.5초·VRAM 0.13GB 로 완주했다.
MAE 는 나이브보다 나빴다(109,696원 vs 14,583원) — T=1.0 샘플링 1회니 예상 범위고,
품질 판단은 fine-tune + 다표본에서 한다. **스모크 결과에 품질 결론을 얹지 않는다.**
