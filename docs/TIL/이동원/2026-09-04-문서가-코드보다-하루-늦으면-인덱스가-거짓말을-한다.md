## v3.3 의 명세서는 v3.2 였다

버전업을 시작하며 v3.3 폴더를 열었더니 `명세서.md`·`요약본.md`·`고도화_설계.md`·
`공공데이터포털_수집_설계.md` 가 v3.2 와 **diff 0줄**이었다. v3.3 은 변경사항·품질 규약·
라이선스 대장을 새로 썼지만 본문은 복사만 하고 안 고쳤다. `docs/README.md` 인덱스는 더
뒤였다 — 데이터파트 v3.2 · 기능명세 v1.3 · ERD v2.2 를 "최신" 이라 가리켰고, PR #102·#104 가
인덱스를 안 건드려 **v3.3·v1.4 는 어디에도 등재되지 않았다.**

"최신" 이라는 글자는 링크 검사가 못 잡는다. 링크는 살아 있으니까. 그래서 메모리 규칙대로
문서 ↔ 실상 **대조표를 먼저** 만들었다 — 열여섯 줄이 나왔고, 그게 그대로 v3.4 의 할 일이
됐다. 인덱스 "최신" 은 이제 4개 도메인(데이터파트 3.4 · 기능명세 1.5 · ERD 2.3 · 핵심코드 1.1)을
실제 폴더와 전수 대조했다.

## 정본이 없는 것이 하나 더 있었다 — 감자 보정

v3.3 이 찾은 "FDR 이 조정하지 않은 감자 17자리" 는 09-04 오전에 43,777행이 보정돼 있었다.
`verify_base_info` §9 가 "못 이은 자리 0" 을 낸다. 그런데 **보정한 코드가 저장소에 없다.**
`build_adj_prices.py` 에도 `adj_price.py` 에도 감자 규칙이 없고, 22MB 원장
`reports/fix_capital_reduction_*.json` 만 남아 있다. 스크래치 스크립트로 적용한 것이다.

DB 를 다시 깔면 17자리가 돌아온다. 어제는 반출 스크립트가, 오늘 오전엔 카이제곱 코드가,
오후엔 감자 보정이 같은 모양이었다 — **결과는 맞는데 만든 방법이 없다.** 셋 다 "잘 됐으니
됐다" 에서 멈춘 자리다. 원장은 `.gitignore` 로 커밋만 막고 보관했고, 빚 1순위로 올렸다.
⑬ 극단 32행과 묶어 `build_adj_prices.py` 에 넣는다.

## 설계 문서는 고치지 않고 정정 블록을 덧붙인다

고도화 설계 §2 는 09-03 시점의 설계다 — 원격 제로샷 · 접수번호 단위 · v11 · HF 예산.
실제는 넷 다 달랐다(로컬 · 제목 단위 · v12 · 예산 불필요). 설계 원문을 고치면 "그때 왜
그렇게 생각했나" 가 사라진다. `조사/` 폴더 규칙(관측은 한 시점의 사실 · 정정 블록을
덧붙인다)을 설계 문서에도 썼다 — §2.9 에 설계↔실제 표를 두고 원문은 그대로 뒀다.

포털 설계도 같다. 09-03 의 "못 찾은 것 6개" 문단을 지우지 않고 그 아래 🆕 로 "전부 찾았다 —
틀이 둘이었다" 를 붙였다. 나중에 읽는 사람이 **틀린 추측이 어떻게 고쳐졌는지**를 본다.

## 규칙이 뒤집혔으면 뒤집혔다고 적는다

v3.2 §5 는 "모델 로컬 다운로드 Won't" 였다. text_signal 은 로컬로 돌았다. 조용히 지우는
대신 §5 에 "🆕 개정 — 인코더는 로컬 추론이 기본 · 원격은 예산 안에서만 · 생성형·파인튜닝은
여전히 Won't" 로 적고 변경사항 §5 에 왜(0원 · 7분 · 리비전 고정)를 표로 뒀다. 규칙이 바뀐
흔적이 남아야 다음에 같은 질문이 나올 때 다시 재지 않는다.
