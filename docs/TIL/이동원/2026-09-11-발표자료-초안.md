## 2. 왜 했나

발표는 신장환 · 강민석 님이 하고, 나는 발표에 관여하지 않는다. 데이터 파트 3분은 직접 만들지
않은 사람이 설명해야 하고, 질문이 나오면 그 사람이 답해야 한다. 데이터 파트 숫자는 v2.0 부터
v4.5 까지 문서 여러 판에 흩어져 있어서, 3분 안에 무엇을 고를지부터가 일이었다.

## 3. 어떻게 했나 — 고른 것과 버린 것

셋째가 가장 솔직하지만 3분 안에서는 *"데이터에 문제가 많았다"* 로 들린다. 첫째와 둘째를 합쳐
네 장으로 만들었다.

| 장 | 주장 | 받치는 숫자 |

| 무엇을 모았나 | 명령 하나로 받고 검사해서 나눠 준다 | 일별시세 9,231,938행 · 끊긴 종목 913 · 갱신 8단계 |

### 슬라이드 정본은 통합본 하나

처음에는 데이터 파트 슬라이드와 배경 · 결론 초안을 따로 만들었다. 통합본은 팀장인 내가 큰 틀로
줘야 해서 합쳤고, 같은 슬라이드가 두 파일에 있으면 한쪽만 고쳐 숫자가 갈라지므로 따로 만든 두
파일은 지웠다. 대신 구역마다 `<!-- ═══ 신장환 3 · 피처 · 라벨 설계 ═══ 시작 -->` 주석을 박아,
여럿이 같은 파일을 고쳐도 구역이 다르면 git 이 합치게 했다.

### "AI 스럽지 않게"

이모지 · 아이콘 카드 · 그라데이션 · "혁신적" 같은 수식어를 쓰지 않았다. 한 장에 주장 한 문장,
그 아래에 실측 숫자와 실제 종목 · 날짜(훈영 2011-04-04 · 20.00배)를 둔다. 색은 팀 소개 자료의
토큰을 그대로 쓰고, 전처리 막대는 국내장 관례대로 원값보다 나으면 적색 · 못하면 청색으로 칠했다.
슬라이드는 발표자 노트북이 다크 모드여도 리허설과 같게 보이도록 라이트 한 벌로 고정했다.

### 충돌 없는 PR — checkout 없이 새 파일만

메인 세션과 작업 트리를 같이 쓰고 있었다. 브랜치를 체크아웃하면 메인 세션의 작업 파일이
흔들린다. 그래서 임시 인덱스로 `origin/main` 위에 새 파일만 담은 커밋을 만들어 push 했다.

```bash
export GIT_INDEX_FILE=<scratchpad>/presentation.index   # 진짜 인덱스는 건드리지 않는다
git read-tree origin/main
git update-index --add --cacheinfo "100644,$(git hash-object -w -- <파일>),<파일>"
git commit-tree "$(git write-tree)" -p origin/main -F commit_msg.txt
git push origin <커밋>:refs/heads/docs/presentation-draft-v1.0
```

`docs/README.md` · TIL 인덱스처럼 여러 PR 이 함께 고치는 파일은 이 PR 에서 뺐다. 이 저장소에는
pre-commit 훅이 없어서 이 방법으로 건너뛴 검사는 없다 — 링크 검사는 손으로 돌렸다.

## 6. 배운 것

**발표자가 만든 사람이 아닐 때는 "무엇을 말하지 말까"가 더 쓸모 있다.** *"누수가 전혀 없습니다"* ·
*"이상치를 제거했습니다"* 같은 말은 틀린 말이 아니어도 한 번 더 물으면 무너진다. 그래서 피할 말과
대신 할 말, 그 근거 숫자를 나란히 적었다.

**옮겨 적은 숫자는 옮겨 적은 날의 숫자다.** 이틀 전 문서에서 이미 세 개가 달랐다. 슬라이드
아래 줄마다 잰 날짜를 붙인 이유다.

**렌더러가 멀쩡하다고 파일이 멀쩡한 것은 아니다.** doctype 없는 HTML 이 puppeteer 에서는 잘
나왔지만, 받는 사람의 브라우저는 다를 수 있다.
