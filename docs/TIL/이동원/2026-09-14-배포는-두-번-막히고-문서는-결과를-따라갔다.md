## 1. 무엇을 했나

대시보드를 공개 배포했다. Streamlit Cloud 에서 첫 화면이 멈춘 것을 요구사항 파일 하나로 풀었고(#266), 토큰 이름 함정을 찾아
데이터를 붙였고, CPU 제한에 걸린 뒤 사용자가 옮긴 HF Space 용 Dockerfile 을 로컬 Docker 로 검증해 저장소에 정본으로 올렸다(#272).
팀장 판단으로 대시보드 문제 5건을 토의 이슈로 열었다. 그리고 09-11 홀드아웃 결과와 팀원들의 마지막 작업(#257~#262 · #269 · #270)을
문서 여섯 도메인에 옮기고, 루트 README 와 시스템 구성도를 결과 기준으로 다시 그렸다.

## 2. 왜 했나

발표 뒤 남은 하루에 **보여 줄 화면**과 **믿을 수 있는 문서**가 둘 다 없었다. 화면은 로컬에서만 떴고, README 머리의 구성도는
08-29 계획(점선투성이)이었고, 문서 곳곳에 "미개봉 · unseal.log 0줄" 이 남아 있었다.

## 5. 막힌 것 · 남은 것

- 🔴 대시보드는 **화면 안에서 학습**한다 — 무료 CPU 에서 제한 · 재시작마다 캐시 소실. 시연 전 하드웨어 확정 → rebuild → 예열

- 결과 보고서 6.4(백테스트) · ruff 209 · 논의 이슈 5건 · Space 업로드(팀장)

## 6. 배운 것

- **두 이름을 읽는 곳이 성공하면 한 이름만 읽는 곳의 실패가 가려진다.** 사이드바가 초록이라 토큰이 문제일 리 없다고 볼 뻔했다.
- **요구사항 파일은 가장 가까운 것이 이긴다.** 루트에 다 적어 둔 것이 배포에서는 아무 소용이 없었다.
- **화면이 학습을 부르면 캐시가 곧 운영이다.** 머지 한 번이 시연 준비를 지운다.
- **기준선은 같은 기간 안에서.** 팀원이 같은 날 고친 것을 pull 하지 않았다면 틀린 비교를 결과 보고서에 굳혔을 것이다.
