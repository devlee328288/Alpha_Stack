## 6. 배운 것

- **두 이름을 읽는 곳이 성공하면 한 이름만 읽는 곳의 실패가 가려진다.** 사이드바가 초록이라 토큰이 문제일 리 없다고 볼 뻔했다.
- **요구사항 파일은 가장 가까운 것이 이긴다.** 루트에 다 적어 둔 것이 배포에서는 아무 소용이 없었다.
- **화면이 학습을 부르면 캐시가 곧 운영이다.** 머지 한 번이 시연 준비를 지운다.
- **기준선은 같은 기간 안에서.** 팀원이 같은 날 고친 것을 pull 하지 않았다면 틀린 비교를 결과 보고서에 굳혔을 것이다.

- **번호는 쓰는 사람에게 짧고 읽는 사람에게 길다.** v1.0 빌더에 "ADR" 이 54곳 있었고, 읽는 사람은 그때마다 무슨 결정인지 따로 찾아야 했다. 이름과 날짜로 부르니 번호가 필요한 곳은 부록 B 한 표로 모였다.
- **검사기를 붙였으면 일부러 틀린 입력으로 먼저 돌린다.** 본문 번호 검사가 0 을 냈을 때, 번호 4곳을 심은 블록으로 4곳을 다 잡는지부터 봤다. 0 이 "없어서" 인지 "못 봐서" 인지는 대조군이 가른다.
- **옮겨 싣는 표가 본문과 다른 말을 쓰고 있었다.** 본문은 "기준일 조회 모듈" 로 바꿨는데 계획서에서 가져온 QFRS 표는 여전히 "공급 계층" 이었다. 번호 검사는 초록이었고, PDF 를 쪽마다 넘기다 용어가 두 벌인 것을 봤다 — 검사한 축(번호)과 틀린 축(용어)이 달랐다.
- **가설은 이번 결과에서 출발시킨다.** "딥러닝이 선형 모델의 한계를 넘을 것" 이라고 쓰는 대신, 트리 모델 3종도 로지스틱 회귀를 넘지 못했다는 사실을 주의할 점으로 붙였다. 공시 본문도 제목에 신호가 없었다는 숫자(V 0.026)부터 적었다.
- **"절반을 설명한다" 는 스피어만 1.0 이 말하는 것이 아니었다.** 문장을 다듬다 v1.0 의 표현이 숫자보다 앞서 나간 것을 찾았다 — 순위가 같다는 것과 분산의 절반이라는 것은 다른 주장이다.
- **PR 직전 fetch 가 40분 전 문장을 뒤집었다.** 16:12 에 "아직 합쳐지지 않았다" 고 쓴 문장이 16:52 에는 틀려 있었다. 규칙대로 PR 을 만들기 전에 fetch 했기에 올리기 전에 잡았다. 그리고 "머지됐다" 를 "고쳐졌다" 로 옮기지 않았다 — 코드를 여니 조합은 고쳐졌고 최고 모델을 고르는 기준은 그대로였다. 이슈 제목 하나(#280)에 문제가 둘 들어 있었고, PR 은 그중 하나만 닫았다.
