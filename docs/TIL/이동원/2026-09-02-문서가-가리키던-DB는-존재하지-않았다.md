# 문서가 가리키던 DB 는 존재하지 않았다 — 전 도메인 문서 재정합

> 2026-09-02 · 이동원 · 문서 전면 개정 (데이터파트 v3.0 · ERD v2.0 · 핵심코드 v1.0 신설)

## 오늘 한 것

전 도메인 문서를 코드·DB 실상과 전수 대조하고, 낡은 것을 한 번에 개정했다.

- **ERD v2.0** — v1.0 은 실행된 적 없는 Postgres 설계(`securities`·`ohlcv`·`watermark`)를
  그리고 있었다. 실물(`krx_cache.db` v8 · 표 16개)을 `PRAGMA` 전수로 다시 그렸다
- **데이터파트 v3.0** — 병렬 세션이 남긴 부분판 조각(v2.2 1파일 · v2.3 3파일 ·
  v2.4 3파일)을 전문으로 재통합. 그 사이 코드에 들어온 반입(v5)·재무(v6)·거시(v7)·
  실행기록(v8)·HF 배포 체계를 상태표에 등재
- **핵심코드 v1.0 신설** — 줄 단위 해설 7편. 팀 결정대로 **전 파트**(수집·반입·공급·
  반출 + 피처·모델·평가)를 다루되, 남의 파트 코드는 참고만 하고 건드리지 않았다
- 마스터 인덱스의 낡은 "최신" 표기 6곳 수정 · 미등재 폴더(전처리) 등재
- 링크 검사 687건 ✅ (개정 전 593건)

## 1. 링크 검사는 "낡은 최신"을 못 잡는다

`check_doc_links.py` 는 개정 내내 초록불이었다. 깨진 링크가 없었기 때문이다.
그런데 인덱스는 계획서 v2.0·기능명세 v1.0 을 "최신"이라 적고 있었고(실제 v2.1·v1.3),
ERD 는 **존재하지 않는 DB** 를 가리키고 있었다.

링크가 살아 있다는 것과 내용이 맞다는 것은 다른 명제다. 링크 검사기는 전자만 본다.
후자를 잡는 도구는 결국 **"최신" 표기 ↔ 실제 폴더 전수 대조**라는 사람 절차였다.
이번에 문서 정합 작업의 상시 검증 절차로 못박았다.

## 2. 문서에만 존재하는 코드 — `SealedRangeError`

핵심코드 ③(공급 정문)을 쓰다가 습관처럼 grep 으로 재확인했는데, 요구사항 F-04 와
데이터파트 v2.1 이 말하는 `SealedRangeError` 예외가 **코드 어디에도 없었다.**

실물 봉인은 예외가 아니라 다른 모양이었다 — `training_frame(*, holdout_start=...)`
의 인자가 **키워드 전용 + 기본값 없음**이라 빠뜨리면 터지고, 값을 주면 경계 이후
행을 제거하고 **몇 행을 제거했는지 보고**한다. 막는 힘은 같은데 방식이 다르다.

v2.1 자신도 "`AsOfRequired` 가 문서에만 있다"를 지적해 놓고, 같은 문서 0절에서
`SealedRangeError` 를 사실처럼 적고 있었다. **문서의 거짓말을 지적하는 문서도
거짓말을 한다.** 해설을 쓸 때는 문서가 아니라 코드에서 발췌해야 하는 이유다.

## 3. 부분판의 대가 — 전문을 가진 판이 낡는다

버전 규약은 "폴더 하나 = 그 시점의 완결된 명세"인데, 병렬 세션들은 자기가 만진
파일만 담은 부분판(v2.2~v2.4)을 냈다. 각 판은 옳았지만, **전문(全文)을 가진 마지막
판(v2.1)은 사흘 만에 코드와 크게 어긋난 채로 "명세서"라는 이름을 달고 있었다.**

v3.0 에서 배운 통합 규칙: 부분판을 낼 거면 README 버전 목록에 "부분판"임을 명시하고,
**전문 재통합을 다음 Major 의 명시적 할 일로** 남긴다. 그냥 두면 아무도 안 한다 —
서로 미룬 ruff 30건과 같은 구조고, 병렬 세션을 접은 이유이기도 하다.

## 4. 해설 문서는 코드 주석의 대체물이 아니다

이번 세션 앞부분에서 "주석이 얇다"는 전제가 실측으로 뒤집혔고(별도 TIL), 그럼
쉽고 자세한 설명은 어디로 가야 하나의 답이 핵심코드 폴더다. 코드 주석은 **그 줄이
왜 그런가**를 지키고, 해설 문서는 **기능 하나를 처음부터 끝까지 따라가는 이야기**를
맡는다. 둘은 형태가 달라 서로 대체가 안 된다. 발표 대본이 필요하면 후자를 읽으면 된다.

## 오늘의 한 줄

**링크가 살아 있어도 문서는 죽어 있을 수 있다.** 문서의 생사는 링크 검사기가 아니라
"이 문서가 가리키는 실물이 아직 그 모양인가"를 재는 사람이 판정한다.
