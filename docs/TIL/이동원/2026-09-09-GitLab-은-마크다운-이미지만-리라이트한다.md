# GitLab 은 마크다운 이미지만 리라이트한다 — raw HTML `<img>` 상대경로는 프록시로 그대로 넘어간다

> 2026-09-09 (네 번째 세션) · 이동원 · [#182](https://github.com/devlee328288/Alpha_Stack/issues/182) · README 구성도

## 무슨 일이 있었나

GitHub README 에는 멀쩡히 뜨는 시스템 구성도가 **GitLab 미러에서만** 깨져 보였습니다.
같은 README 489행의 **마크다운 링크**는 바로 그 PNG 파일을 가리키는데 정상으로 뜹니다.
그래서 처음엔 한글 경로나 파일 누락을 의심했습니다. 둘 다 아니었습니다.

## 어떻게 갈랐나

프로젝트 페이지 HTML 은 Vue 라 `<img>` 가 안 들어 있습니다. 렌더 결과를 직접 받았습니다.

```
GET /-/blob/main/README.md?format=json&viewer=rich
```

돌아온 HTML 에서 —

| 문법 | GitLab 이 만든 `src` | 결과 |
|---|---|---|
| 마크다운 이미지·링크 문법 (상대경로) | `/dev-dongwon05253/alpha_stack/-/raw/main/docs/%EC%95%84…` | ✅ 리라이트됨 |
| raw HTML `<img src="docs/…">` | `https://user-content.gitlab-static.net/…` + `data-canonical-src="docs/아키텍처/…"` | 🔴 상대경로 그대로 프록시로 → 404 |

**GitLab 은 마크다운 문법의 상대경로만 저장소 경로로 바꿔 준다.** raw HTML 태그는 sanitizer 가
통과시키되 경로를 손대지 않고, 그 상대경로를 받은 이미지 프록시가 해석하지 못해 깨집니다.
GitHub 은 raw HTML 도 리라이트하므로 거기서는 안 보였습니다.

## 고친 것과 남는 단점

`width="820"` 을 쓰려면 HTML 태그가 필요해서 **GitHub raw 절대 URL** 로 바꿨습니다
(실측 `200 OK` · `image/png` · 501,556 bytes).

단점을 README 주석에 적어 두었습니다 — 그림이 **GitHub 저장소 main 에 매달립니다.**
Private 전환·파일 이동 시 GitLab 이 다시 깨집니다. 그때는 마크다운 문법으로 바꾸면 양쪽 다
뜨고, width 지정만 포기하면 됩니다.

## 배운 것

- **"한쪽만 깨진다"** 는 렌더러 차이다. 파일·경로·인코딩을 의심하기 전에 **렌더 결과 HTML 을 받아**
  두 문법을 나란히 놓으면 한 번에 갈린다.
- 문서에 그림을 넣을 때는 **마크다운 문법이 기본**이다. HTML 태그는 크기 지정이 꼭 필요할 때만,
  그때는 절대 URL 로.
