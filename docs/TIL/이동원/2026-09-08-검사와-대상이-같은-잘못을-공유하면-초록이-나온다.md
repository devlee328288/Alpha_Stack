## 왜 못 봤나 — 초록의 조건이 틀렸다

내 검증기는 원장을 **종가로 다시 계산해** 대조합니다. 그런데 원장도 종가로 적혀 있었습니다.
**둘이 같은 잘못을 공유하니 서로 맞다고 했습니다.** 초록이 떴고, 나는 그 초록을 노트북에
적었습니다.

검사가 대상과 독립이 아닐 때 초록은 아무 뜻이 없습니다. 여기서 필요했던 것은
**바깥에 있는 기준** — ADR, 라벨 코드, 체결 코드 — 과 맞대는 일이었습니다.

더 나쁜 것은 내가 **같은 파일 머리말에 옳은 답을 써 두었다**는 점입니다.

> 3. 시점 — 체결일이 예측일보다 뒤인가 (t 에 예측 · **t+1 시가 체결**)

계약서를 쓴 사람이 그 계약을 어겼고, 그것을 검사하는 코드도 같은 사람이 썼습니다.

## 계약 테스트도 같은 함정에 있었다

시장 픽스처가 이랬습니다.

```python
market = pd.DataFrame({"open": close.shift(1).fillna(close.iloc[0]), "close": close})
```

`open[i] = close[i-1]` 이면

```
open[t+6] / open[t+1]  ==  close[t+5] / close[t]
```

**두 축이 항상 같은 값입니다.** 축이 어긋나도 시험이 못 잡습니다. 통과하던 시험이
아무것도 지키지 않고 있었습니다.

밤사이 갭을 넣어 고쳤습니다. 실제 시장에는 갭이 있으니 현실에 더 가깝기도 합니다.

```python
gap = 1.0 + rng.normal(0, 0.004, len(close))
open_ = close.shift(1).fillna(close.iloc[0]).to_numpy() * gap
```

## 얼마나 다른가 — "간격이 같으니 비슷하겠지" 가 아니었다

코스피200 4,099행(2010-01-04 ~ 2026-09-04):

| 항목 | 값 |
|---|---:|
| 두 축이 정확히 같은 행 | **0건** |
| 상관계수 | 0.9118 |
| 평균 절대차 | 0.8168%p |
| 최대 절대차 | 10.3161%p |
| **±1.0% 3분류 라벨 불일치** | **887행 (21.64%)** |
| 상승↔하락 정반대 전환 | 27행 |

**상관 0.91 을 보고 "거의 같다"고 넘길 뻔했습니다.** 그런데 라벨로 바꾸면 다섯 중 하나가
다릅니다. 우리 모델 정확도가 42%대인데 평가 축이 21.64% 다르면 성과 해석이 통째로 바뀝니다.

연속값의 상관과 이산 라벨의 일치는 다른 이야기입니다. **임계선 근처에서는 작은 차이가
라벨을 바꿉니다.** ±1.0% 밴드 위아래 0.8%p 는 작은 값이 아닙니다.

## 무엇을 바꿨나

- 검증기를 시가축으로. `close=` 를 주면 **막고 무엇을 해야 하는지 알린다**
- 봉인 엿보기 검사도 `t+5 종가` → `t+6 시가`. 결측이 끝에서 한 행 더 생기는 게 맞다
- 계산 기준 세 칸(`return_price_basis`·`entry_offset`·`exit_offset`) 검사 추가 —
  오준영 님 제안. 이게 있으면 **가격을 안 줘도** 축을 잰다
- 계약 테스트 픽스처에 밤사이 갭
- 종단 시험 3개는 `xfail(strict=True)` — 강민석 님이 #176 을 고치면 **xpass 로 알려준다**

## 남는 것

`close=` 를 막을 때 그냥 `TypeError` 만 던지지 않고 이렇게 적었습니다.

```
고치는 법: close=... 를 open_prices=... 로 바꾸고 그 날짜 축의 시가를 준다.
개별 종목 원장이면 adj_open 을 준다(액면분할·감자 보정).
종가로 잰 값이 정말 필요하면 그것은 realized_return_5d 가 아니므로 다른 칸 이름으로 둔다.
```

막다른 길로 만들지 않는다는 규칙을 지켰습니다. 그런데 애초에 이 규칙을 **검사 설계에도**
적용했어야 했습니다 — "무엇을 기준으로 초록이라 하는가" 를 코드 밖에서 한 번 더 물었어야
했습니다.
