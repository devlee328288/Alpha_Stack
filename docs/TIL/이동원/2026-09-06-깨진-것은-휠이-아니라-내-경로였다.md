## 무엇을 했나

팀장(사용자)이 "gs-quant 라는 퀀트 라이브러리가 새로 생겼다는데 벤치마킹 참고용으로 이슈에 정리해 달라, 파트별
활용처와 **우리 프로젝트에 맞게 커스터마이징이 되는지**까지" 요청했다. 링크·숫자는 GitHub API 로, 동작은 설치해서
돌려서 쟀다. 결과는 이슈 #140 에 있고, 여기는 재다가 배운 것만 적는다.

## "새로 생겼다" 는 틀렸고, 왜 그렇게 들렸는지는 맞았다

GitHub 생성일 **2018-12-14**. 7년 된 라이브러리다. 다만 2.1.x 릴리스를 며칠 간격으로 내고(09-04 하루에 셋), 8월에
**MCP 서버와 Claude 스킬**이 붙으면서 다시 회자되고 있었다. 소문의 "새로 생김" 은 라이브러리가 아니라 **에이전트
연동 층**이었다. 전해 들은 말은 무엇이 새것인지까지 재야 한다.

## 휠이 깨졌다고 적을 뻔했다

`import gs_quant.backtests` 가 `ModuleNotFoundError` 로 죽었다. 2.1.7 로 내려도 같았다. "두 버전이 다 깨졌다" 는
결론이 그럴듯해서 이슈 초안에 그렇게 썼다.

그런데 `os.listdir` 은 그 파일을 보여 주는데 `open()` 은 FileNotFoundError 였다. 이 짝은 **Windows MAX_PATH** 의
서명이다. 스크래치 폴더 경로가 길어 site-packages 까지만 179자, 가장 깊은 모듈은 **273자 > 260**. `LongPathsEnabled`
는 미설정. 56자 경로에 다시 깔자 전부 import 됐다.

**라이브러리 결함이라고 적기 전에 내 환경을 한 번 의심한다.** 특히 두 버전이 똑같이 깨지면, 공통 원인은 라이브러리보다
내 쪽에 있을 확률이 높다. 메모리에 남겼다.

## 두 층으로 갈라서 셌다

합성 종가 500일로 35개 호출 → **OK 25 / FAIL 10.** FAIL 10 은 세션 필요 5 · extra 필요 1 · 내가 인자를 잘못 준 4.
인자 오류 넷은 바로잡아 다시 쟀다 — `exponential_moving_average(px, beta)` 의 둘째 인자는 창 길이가 아니라 0~1 계수였고,
`sharpe_ratio` 는 무위험 커브를 서버에서 받아 오프라인으론 안 된다. **FAIL 을 세는 것도 실측이다.** 내 실수를 라이브러리
한계로 세면 표가 거짓이 된다.

## 커스터마이징은 되는데, 되는 값을 손으로 다시 셌다

`DataSource` 를 상속해 우리 프레임을 호출 시점에 읽게 하고, `OrdersGeneratorTrigger` 를 상속해 "신호일 종가 매수 →
5거래일 뒤 종가 매도" 를 발행하고, `OrderCost` 로 비용을 얹었다. 신호 45 → 청산 45, 보유 거래일 고유값 **[5]**,
원장 PnL 합 **84.12 = 손계산 84.12**. 돌아간다는 것과 맞게 돌아간다는 것은 다르다 — 손계산이 있어야 두 번째를 말할 수
있다.

걸린 것도 있었다. naive·aware datetime 을 섞으면 두 군데서 TypeError(정렬·ping), `get_costs()` 는 라이브러리 안에서
죽는다(상류 #374 open · #362 에 이미 있다), OrdersGenerator 경로에선 `performance` 가 0행이다. 그리고 numpy 핀
`<2.4` 는 `--no-deps` 로 2.5.1 위에 얹어도 프로브가 **OK 25 로 동일**했다 — 우리가 쓸 층에 대해선 보수적인 핀이었다.

## 배운 것

- 전해 들은 "새로 생겼다" 는 무엇이 새것인지까지 재야 한다. 이번엔 라이브러리가 아니라 에이전트 층이었다.
- listdir 은 되는데 import·open 이 안 되면 **경로 길이부터** 잰다. 두 버전이 똑같이 깨지면 공통 원인은 내 쪽이다.
- FAIL 도 분류해서 센다. 내 인자 오류를 라이브러리 한계로 세면 표가 거짓이 된다.
- "돌아간다" 는 손계산과 맞을 때만 "맞게 돌아간다" 가 된다.
- 벤치마킹은 저장소 밖에서 한다. 오늘 저장소 코드 변경은 0 이고, 이슈는 질문이다.
