## 1. 무엇을 했나

계획서 부록 I 의 [그림 2] 를 **계층아키텍처**(`supply` 문 하나)에서
**시스템아키텍처**(문 둘)로 바꾸고 계획서 v2.1 을 냈다. `DIAGRAM_DIR` 이 아키텍처
v1.1 을 가리키던 것도 v1.2 로 옮겼다.

## 2. 왜 했나

[PR #10](2026-08-29-시세공급-문을-둘로.md) 이 `supply/` 를 문 하나에서 **문 둘로**
갈랐는데, 계획서가 싣는 그림은 그 이전 것이었다.

```
계층아키텍처.mmd:11
GATE{{"supply/ — as_of 정문 ..."}}      ← 문이 하나
```

이 그림만 보면 **정문이 정리매매 판정까지 하는 것처럼 읽힌다. 정반대다.** 정리매매
판정은 "이 뒤로 체결이 끊긴다" 라서 그 시점에는 알 수 없는 사실이고, `as_of` 정문이
그걸 계산하면 문이 지키려던 경계를 문이 스스로 넘는다.

계획서는 강사님께 내는 문서다. **틀린 그림이 실린 채로 발표까지 가면 되돌릴 수 없다.**

## 3. 어떻게 했나 — 고른 것과 버린 것

### 버린 것 ① — `계층아키텍처.mmd` 를 고쳐서 다시 굽기

가장 먼저 떠오른 방법인데 **규약 위반**이다. 그 파일은 아키텍처 v1.2 폴더의
산출물이고, `docs/` 규약은 **옛 버전을 고치지 않는다.** 고치려면 아키텍처 v1.3 을
새로 파야 하는데, 지금 필요한 것은 계획서 한 장의 그림이지 아키텍처 개정이 아니다.

### 버린 것 ② — 그림 둘을 나란히 싣기

계층(의존 방향)과 시스템(전체 구성)을 함께 두는 안. 그런데 **문 하나로 그린 그림이
그대로 남는다.** 틀린 그림 옆에 맞는 그림을 두면 보는 사람은 둘 다 맞다고 읽는다.

### 고른 것 — 시스템아키텍처로 교체

PR #11 이 발표용으로 만든 그림이 이미 문 둘을 정확히 그리고 있었다. 그것으로
바꾸고, 문이 둘인 **이유**를 설명하는 문단을 함께 넣었다.

부수 효과가 하나 있다 — 발표 자료와 계획서 부록의 그림이 **같은 그림**이 됐다.
"계획서 부록 I 를 보시면" 이라고 말할 때 청중이 보는 것과 손에 든 것이 같다.

### `DIAGRAM_DIR` 은 위생으로만 고쳤다

`version1.1` 을 가리키고 있었다. 그런데 **이것만으로는 산출물이 하나도 안 바뀐다** —
아래 4절 참고. 그래도 옮긴 이유는, 옛 폴더를 가리키면 계획서만 조용히 낡는데
**그림은 아무도 다시 안 보기 때문에 틀린 줄 모른 채 발표까지 가기** 때문이다.

## 4. 어떻게 확인했나

### 🔴 내 첫 진단이 절반 틀렸다

처음에 *"계획서가 낡은 v1.1 그림을 쓰고 있다"* 고 보고했다. 확인해 보니
**v1.1 과 v1.2 의 같은 이름 그림 3장은 `.mmd` · `.png` 모두 바이트까지 같았다.**
PR #11 이 v1.2 폴더로 복사만 한 것이다.

```
계층아키텍처:   동일 (181,606 bytes)
역할파이프라인: 동일 ( 84,349 bytes)
일정간트:       동일 (145,592 bytes)
```

즉 경로는 낡았지만 **산출물 차이는 0** 이었다. 진짜 문제는 폴더가 아니라 그림
**내용**이 PR #10 이전이라는 것이었고, 그건 v1.2 로 옮겨도 안 고쳐진다.

### 의도한 것만 바뀌었나 — 본문을 덤프해 대조했다

docx 는 `git diff` 가 안 읽히므로 `python-docx` 로 본문을 뽑아 비교했다.
**차이가 정확히 2줄**이었다(설명 문단 1 + 캡션 1).

docx 안의 이미지도 확인했다.

```
v2.0:  image1 142.2 KB · image2 177.3 KB · image3  82.4 KB
v2.1:  image1 142.2 KB · image2 489.8 KB · image3  82.4 KB
                          ^^^^^^^^^^^^^^ 계층 → 시스템
```

`image2` 만 교체되고 [그림 1] 일정간트 · [그림 3] 역할파이프라인은 그대로다.
표 8개 유지, 문단 64 → 65, 파일 411KB → 722KB.

### 그림 비율도 재 봤다

| | 크기 | 비율 |
|---|---|---|
| 계층아키텍처 | 1568 × 2382 | 0.66 (세로로 김) |
| 시스템아키텍처 | 3360 × 1972 | 1.70 (가로로 넓음) |

세로 그림은 너비 4.6M EMU 로도 높이가 19.4cm 라 한 페이지를 거의 다 먹었다.
가로 그림은 5.3M EMU 너비에 높이 8.7cm 라 **지면이 오히려 남는다.**

- 문서 링크 검사 **464건 통과**
- ruff 33건 유지(손댄 파일 clean) · pytest 280 통과

## 5. 막힌 것 · 남은 것

- `계층아키텍처.mmd` 자체는 여전히 문 하나로 그려져 있다. 그 그림이 다시 필요해지면
  **아키텍처 v1.3** 에서 고친다.
- [그림 3] 역할파이프라인은 v1.1 그대로다. **킥오프에서 역할이 확정되면** 고친다 —
  지금 고치면 확정 전 추측을 그림으로 굳히는 일이다.
- 계획서가 722KB 가 됐다. 버전마다 새 폴더에 굽는 구조라 고칠 때마다 쌓인다.
  지금은 3판이라 괜찮지만 판이 늘면 다시 볼 일이다.

## 6. 배운 것

**"낡았다" 는 진단도 근거를 대야 한다.** 경로가 옛 폴더를 가리키는 것을 보고
"낡은 그림을 쓴다" 고 단정했는데, 두 폴더의 파일이 바이트까지 같았다. 해시를 재는
데 10초 걸렸다. **재지 않고 보고한 것이 잘못이다.**

**틀린 그림 옆에 맞는 그림을 두면 둘 다 맞다고 읽힌다.** 병기는 타협처럼 보이지만
사실은 틀린 것을 남기는 선택이다.

**바이너리 산출물은 "무엇이 바뀌었나" 를 스스로 증명해야 한다.** docx 는 diff 가
없으니 본문을 뽑아 대조하고 이미지 목록까지 확인했다. 그 절차를
`docs/계획서/README.md` 에 적어 뒀다 — 다음 사람이 같은 확인을 할 수 있게.
