# 빈칸은 오류처럼 보이지 않아서 세 번 나갔다

> 2026-09-08 · 이동원 · 이슈 [#168](https://github.com/devlee328288/Alpha_Stack/issues/168)(신장환 님 제기) ·
> [`scripts/upload_to_hf.py`](../../../scripts/upload_to_hf.py) ·
> [`scripts/verify_hf_dataset.py`](../../../scripts/verify_hf_dataset.py) ·
> [`tests/test_hf_card_notes.py`](../../../tests/test_hf_card_notes.py)

## 무슨 일이 있었나

품질 플래그 넷을 반출본에 실어 재배포하려던 참이었습니다. 올리기 전에 카드가 어떻게
그려지는지 보려고 `upload_to_hf.py` 를 읽다가, 칸 설명이 `COLUMN_NOTES` 라는 **손으로
적는 사전**에서 온다는 것을 봤습니다. 새로 실을 네 칸이 거기 없었습니다.

그래서 이미 나간 카드를 열어 봤습니다. 515번째 줄이 이렇게 되어 있었습니다.

```
| `industry_ambiguous` | bool | **1.89%** | `False` 98.1% · `(빈값)` 1.9% · `True` 0.1% |  |
```

마지막 칸이 비어 있습니다. **09-05·09-07 두 차례, 세 번의 배포에서 그대로 나갔습니다.**

## 왜 못 봤나 — 빈칸은 정상적인 표처럼 보인다

결측이면 카드가 **굵게** 적고, 값이 이상하면 `COLUMN_WARNINGS` 가 🔴 을 붙입니다.
그런데 **설명이 없는 것만은 아무 표시도 없습니다.** 사전에서 못 찾으면 빈 문자열이
들어가고, 마크다운 표는 빈 칸을 그냥 빈 칸으로 그립니다.

```python
뜻 = COLUMN_NOTES.get(c["이름"], "")     # 없으면 조용히 ""
```

행 수가 틀리면 눈에 띕니다. 값이 이상하면 눈에 띕니다. **없는 것은 눈에 띄지 않습니다.**
표가 여덟 개에 칸이 스무 개씩이라, 사람이 훑으면 채워진 칸들 사이에서 빈 칸 하나는
그냥 지나갑니다.

## 왜 이번엔 그러면 안 됐나

`full/daily_price_dev.parquet` 은 카드에서 **접히지 않고 펼쳐지는 두 표 중 하나**입니다
(`CARD_EXPANDED`). 받아서 가장 먼저 마주치는 표입니다.

그리고 새로 싣는 넷 중 하나가 `is_extreme_return` 입니다. 이름만 보면 *"극단값이니
빼라"* 로 읽히지만 실제로는 **"진짜 일어난 사건이니 남겨라"** 입니다. 권리락·거래정지
해제·상한가 연속은 하루 30% 넘게 움직이지만 오류가 아니라 모델이 배워야 할 사건입니다.

신장환 님이 [#168](https://github.com/devlee328288/Alpha_Stack/issues/168) 에서
정확히 이 위험을 짚으셨습니다.

> 이름만 보고 거꾸로 필터링할 위험이 있습니다.

표에서 뜻 없이 마주친 사람은 이름대로 거릅니다. **표본 불일치를 막으려고 넣은 칸이
표본 불일치를 일으킵니다.** 아래에 `FLAG_GUIDE` 절이 따로 있지만, 표를 먼저 만납니다.

## 무엇을 고쳤나

다섯 칸의 설명을 넣었습니다 — 플래그 넷과, 세 번 비어 나갔던 `industry_ambiguous`.

그리고 **임계값을 글자로 박지 않았습니다.**

```python
"is_adj_suspect": "🔴 KRX 등락률과 우리 수정주가가 "
                  f"**{SUSPECT_GAP_TOLERANCE:g}%p 넘게 어긋난** 행. …"
```

카드의 다른 숫자는 전부 `MANIFEST.json`·`PROFILE.json` 에서 읽어 옵니다. 예전에
`adj_source` 분포가 글자로 박혀 있었고, 자료가 바뀌어도 글자는 안 바뀌었기 때문입니다.
임계값도 같은 자리입니다 — `SUSPECT_GAP_TOLERANCE` 를 1.0 에서 바꾸는 날, 카드만
옛말을 하게 둘 수는 없습니다.

## 시험이 진짜로 가르는지 확인했다

시험 여섯을 붙였는데, 통과했다고 바로 믿지 않았습니다. **검사가 대상과 같은 가정을
공유하면 초록은 "맞다" 가 아니라 "둘이 같다" 는 뜻**이라는 것을 이틀 전에 배웠기
때문입니다.

패치를 `git stash` 로 잠깐 되돌리고 다시 돌렸습니다.

```
패치 전 → 6 failed    (`adj_return_1d` 의 '무엇인가' 가 비어 있다)
패치 후 → 6 passed
```

두 갈래가 실제로 갈립니다.

## 남는 것

`COLUMN_NOTES` 는 여전히 손으로 적는 사전이라, **새 칸을 실으면서 여기 안 적는 일**은
또 일어날 수 있습니다. 지금 시험이 잡는 것은 `FLAG_COLUMNS` 와 `INDUSTRY_COLUMNS` —
상수로 선언된 칸 묶음뿐입니다. 반출본의 **모든** 칸을 훑어 빈 설명을 잡으려면
`PROFILE.json` 을 읽어야 하는데, 그건 반출을 한 번 돌려야 생깁니다. 시험이 반출을
기다리게 만들 수는 없어서, 지금은 상수 두 묶음까지만 고정했습니다.

## 같은 점검에서 하나 더 — 거짓 🔴 도 나왔다

올리기 전에 "정말 재배포가 필요한가" 를 판정기로 확인했습니다.

```
python scripts/verify_hf_dataset.py --skip-download
  → 🔴 표본 30종 adj_* 이 6,915행(7.73%) 다르다 · 재배포가 필요하다
```

7.73% 는 표기 한계가 아닙니다. 값이 진짜 다르다는 뜻입니다. 그런데 **바로 위에서
`full/daily_price_dev.parquet` 은 전 연도 24칸이 "완전히 같다"** 고 나왔습니다.
같은 반출에서 나온 두 파일이 한쪽만 어긋날 수는 없습니다.

원인은 손안의 사본이었습니다. `--skip-download` 는 `data/outbox/hf_snapshot` 을
그대로 쓰는데, 그 스냅샷은 09-07 **첫** 배포(10:25 KST)를 받은 것이었고 서버는
**두 번째**(13:29 KST)였습니다. 그 사이에 수정주가 51종이 재생성됐습니다.

**자료는 이미 최신이었고, 다른 것은 제가 들고 있던 사본뿐이었습니다.**

### 왜 기존 검사가 못 잡았나

`verify_manifest` 가 있습니다. 그런데 그것은 스냅샷을 **자기 자신의** `MANIFEST.json`
과 대조합니다. 낡은 배포본은 자기끼리 일관되므로 그냥 통과합니다. 바깥과 맞대는
자리가 없었습니다 — 이틀 전에 배운 것과 정확히 같은 모양입니다.

갈라 준 것은 서버의 LFS SHA-256 이었습니다. 그것과 맞대 보니
`data/outbox/2026-09-07` 이 서버와 **바이트 단위로 같았고**, 그것을 스냅샷으로 주자
`원시 ✅ · 표본 ✅ · 선정 ✅`, 남은 차이는 최대 **2 ULP** 였습니다.

### 무엇을 고쳤나

`--skip-download` 일 때 서버 `MANIFEST.json` **하나(10KB)** 만 받아 `generated_at`
을 맞댑니다. 어긋나면 무엇을 해야 하는지까지 적고 멈춥니다.

```
🔴 중단 — 받아 둔 스냅샷이 서버의 지금 배포본이 아니다.
   스냅샷 2026-09-07T10:25:48+09:00
   서버   2026-09-07T13:29:06+09:00
   이대로 판정하면 **없는 차이**가 보인다. 아래 중 하나를 할 것:
     · --skip-download 를 빼고 다시 받는다
     · 서버와 같은 것이 확실한 반출 폴더를 --snapshot 으로 준다
```

토큰이 없거나 서버를 못 물어보면 **막지 않고 알리기만** 합니다. 확인 못 한 것을
이유로 판정을 통째로 막으면, 쓰던 사람이 갈 곳이 없어집니다.

## 배운 것

**거짓 🔴 은 거짓 ✅ 만큼 나쁩니다.** 한 번 속으면 다음부터 판정을 안 믿게 되고,
그러면 판정기가 있으나 마나입니다. 오늘도 "재배포가 필요하다" 를 그대로 믿고
`adj_*` 를 다시 만들 뻔했습니다 — 메모에 적어 둔 대로 **다시 만들면 옛 행이
나빠집니다.** 안 해도 될 일을 하면서 자료를 나쁘게 만들 뻔한 것입니다.

두 결함이 모양이 같습니다. 카드 쪽은 **없는 것을 안 재서**, 판정기 쪽은 **자기와
맞대서** 놓쳤습니다. 둘 다 "바깥에 기준이 없었다" 입니다.

**없는 것은 오류처럼 보이지 않습니다.** 틀린 값은 눈에 띄지만 빠진 값은 표의 일부처럼
보입니다. "무엇이 틀렸나" 만 재는 검사는 "무엇이 비었나" 를 영영 못 잡습니다.

그리고 **올리기 전에 나갈 것을 읽어 보는 일**이 이것을 잡았습니다. 코드가 초록이고
검증기 넷이 전부 통과해도, 사람이 받아 볼 화면을 한 번 열어 보는 것과는 다릅니다.
