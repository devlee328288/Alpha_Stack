## 2. 배운 것

### ① 두 계층이 각자 초록인데 서로 안 맞을 수 있다

`tests/test_supply_*.py` 는 `features` 를 import 하지 않는다.
`tests/test_features_*.py` 는 import 가 `math`·`pytest`·`features` 뿐이다 — 입력을
손으로 적는다. **둘 다 통과인데 사이가 비어 있었다.**

손으로 적은 `[1, 2, 3, 4, 5]` 로는 안 드러나고 진짜 표를 물렸을 때만 드러나는 것이
실제로 있었다. 빈 표를 넣으면 `supply` 는 `dtype=object` 를 준다. 13개 함수는 길이 0
을 돌려주는데 `rsi` 만 길이 1 을 돌려준다. 두 값을 한 `DataFrame` 에 담으면 길이가
안 맞아 터진다.

그 어긋남은 **예외를 내지 않는다.** 숫자가 조금 달라질 뿐이다. 거래량에 NaN 하나를
넣었더니 `volume_ratio` 의 109행이 0.9005 → 0.9469 로 **5.2% 부풀었다.**

### ② 🔴 주입 시험이 내 검사 자체의 버그를 잡았다

계약 ④를 이렇게 짰다.

```python
첫_유효 = int(np.argmax(~nan))
assert not nan[첫_유효:].any()
```

그럴듯한데 틀렸다. **`np.argmax` 는 참인 값이 하나도 없으면 0 을 돌려준다.**
"0번째가 첫 유효값"이라는 뜻이 아니라 **못 찾았다**는 뜻인데, 그걸 그대로 쓰면
전부 NaN 인 배열에서 `nan[0:].any()` 가 참이 되어 위반으로 읽는다.

지금 표에서는 전부-NaN 이 안 나와서 **105개가 전부 초록이었다.** 창 크기를 잘못
키운 날 오탐이 터졌을 것이고, 그때는 원인이 검사 쪽이라고 의심하지 않았을 것이다.

잡아낸 것은 음성 시험 한 줄이다.

```python
def test_주입_전부_NaN이면_계약4는_통과한다():
    assert _계약_워밍업(np.full(60, np.nan))
```

**검사를 만들면 일부러 틀린 것을 넣어 본다**는 규칙이 이번에 값을 했다. 그런데
값을 한 자리가 예상 밖이었다 — 잡힌 것은 남의 코드가 아니라 **내 검사**였다.

### ③ 알려진 결함은 `xfail(strict=True)` 로 남긴다

계약을 세우니 `features/` 결함 4건(#17~#20)이 그대로 걸렸다. `features/` 는 장환님
파트라 내가 안 고친다. 그렇다고 붉게 두면 330 통과 기준선이 깨진다.

`strict=True` 가 답이었다. **고쳐지면 xpass 로 실패해서 알려 준다.** 실제로 확인했다 —
`rsi` 의 빈 입력 처리를 고쳐 넣었더니 그 테스트가 실패로 바뀌었다. 고친 줄 모르고
지나갈 수가 없다.

### ④ 문서의 숫자는 무엇을 센 것인지까지 봐야 한다

세션 메모에 "신장환 함수 19개" 라고 적혀 있었다. 세어 보니 **공개 함수는 14개**고,
19 는 `_to_array` 3벌 · `_ewm_mean` · `_wilder_smooth` 를 더한 수였다.

계약은 밖에서 부르는 것에만 선다. 19로 알고 짰으면 내부 헬퍼에까지 계약을 걸려다
막혔을 것이다. [지난번 1,428 줄](2026-08-31-진단이-실측과-어긋난-세-번.md) 과 같은
종류다 — **틀린 숫자가 아니라 무엇을 센 것인지가 빠진 숫자.**

이슈 #20 도 같았다. "pandas nullable(Int64) 를 못 받는다" 로 적혀 있는데, 실제로는
`Int64` 자체는 통과한다. **`pd.NA` 가 실제로 들었을 때만** 터진다
(`float() argument must be a string or a real number, not 'NAType'`).
조건이 빠지면 "저장소가 dtype 만 안 바꾸면 안전하다" 로 잘못 읽힌다.

### ⑤ `main` 만 보면 팀원의 일이 안 보인다

파트 경계를 정리하다 `models/` 가 34줄짜리 문서뿐인 것을 보고 "준영님이 아직
시작 안 하셨다" 고 말할 뻔했다. `git fetch` 를 하니 `origin/feat/logistic-baseline` 에
**오늘 날짜로 240줄**이 있었다.

읽어 보니 설계를 정확히 지킨 코드였다 — X 를 스스로 만들지 않고 밖에서 받고,
`StandardScaler` 를 `Pipeline` 안에 넣어 폴드 누수를 막았다. 오히려 **그래서**
F-07·F-08(레이블·데이터셋)이 없으면 못 돌린다. 브랜치가 PR 로 못 가고 머무는
이유였다.

`main` 은 팀의 현재가 아니라 **합의가 끝난 과거**다. 사람 몫을 말하기 전에
`git fetch --prune` 부터 한다.
