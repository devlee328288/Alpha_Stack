# 밖에 기준이 없으면 다 했는지 알 수 없다

> 2026-09-08 · 이동원 · [데이터파트 v4.0 · 퀀트기준 대조](../../데이터파트/version4.0/퀀트기준_대조.md)

## 무슨 일이 있었나

품질 플래그 4칸을 실은 반출본을 만들고 검사를 전부 통과시켰습니다. 검증기 4종 ✅ ·
홀드아웃 누수 8개 파일 전수 ✅ · private ✅ · 기존 24칸 값 변화 0 · 새 4칸은 정의에서
독립 재계산해 검산까지. **올리기만 하면 되는 상태**였습니다.

그런데 팀장이 이렇게 말했습니다.

> 데이터 쪽에서 약간 부족한 부분이 많은 것 같은데 …
> 기준이나 놓치는 부분이 퀀트 측면에서 많은지 확인해보고

명세서를 열어 봤습니다. **상태표 30항목 중 26이 ✅** 였습니다. 우리 문서로는
부족한 곳이 없었습니다.

## 왜 문서가 초록이었나 — 안 하는 것에는 항목이 없다

명세서는 **우리가 하기로 한 것**의 목록입니다. 하기로 한 것을 다 했으니 초록입니다.
그런데 팀장이 물은 것은 다른 것이었습니다 — *"퀀트가 원래 지키는 것 중 우리가
안 지키는 것"*.

**안 하기로 한 적도 없는 것은 목록에 없습니다.** 없으니 세어지지 않고,
세어지지 않으니 초록입니다. 초록은 "다 했다" 가 아니라 **"적어 둔 것은 다 했다"**
였습니다.

그래서 밖을 봤습니다.

## 무엇이 나왔나

일곱 축을 재니 **다섯이 표준에 못 미쳤습니다.**

| 축 | 실측 | |
|---|---|---|
| 생존 편향 | 개발구간 중 끊긴 종목 **750개 보존** | ✅ |
| 우선주 판정 | KRX 주권종류 기반 | ✅ |
| 유니버스 오염 | KOSPI 상위 50 에 0건 | 🟡 |
| 체결 가능성 | 상위 50 은 0.231% · 501위 밖은 7.079% | 🟡 |
| **판정을 파일에 안 실음** | 큰 벌에 남은 비정상 거래일 **3.063%** | 🔴 |
| **현금배당 미조정** | 배당락일 **−0.455%p** · 15년 중 11년 음수 | 🔴 |
| **이상치 집중** | 전체 평균의 **96.1%가 한 행** | 🔴 |

추가로 기업행위 **이벤트 표**가 없고(zipline 은 세 표), 원장에 **유효성 축**이 없고
(위반 124행), **거래량 급변 검사**가 없습니다.

## 가장 뼈아픈 것

`full/daily_price_dev.parquet` 을 카드가 이렇게 부릅니다.

> 개발구간 전 종목 시세 — **최종 학습용은 이것**

그런데 작은 벌(`stocks30_train`)은 정리매매·거래정지·신규상장을 **떨어낸** 표본
(89,424 → 82,852행)이고, **큰 벌은 안 떨어냅니다.** 3.063%가 그대로 있습니다.

**둘로 학습하면 결과가 갈리는데, 칸 구성만 보고는 그것을 알 수 없습니다.**
이틀 전 #168 에서 신장환 님이 짚으신 것과 정확히 같은 모양입니다 — 공급 층에만 있는
판정은 받아 쓰는 사람에게 **없는 것과 같습니다.**

주권종류도 그렇습니다. `stock_base_info` 에 있는데 파일에 안 실어서,
모델 파트 코드가 이렇게 되어 있습니다.

```python
# HF 일별시세에는 주권종류가 없다. 대신 … 어긋난 10개를 전부 남겼다.
AUDITED_COMMON_EXCEPTIONS = frozenset({("115960","연우"), ("088910","동우"), …})
```

**우리가 이미 아는 것을 안 실어 보내서, 받는 쪽이 이름으로 되짚고 있습니다.**

## 그대로 베끼면 안 된다는 것도 실측으로 알았다

qlib(★48,408)의 거래량 급변 기준은 3배입니다. 그대로 켜 봤습니다.

| | 전체 개발구간 | KOSPI 상위 50 |
|---|---:|---:|
| 3배 초과 | **7.953%** | 1.889% |
| 10배 초과 | 1.697% | 0.088% |

**전체의 8%가 붉어집니다.** 한국 소형주는 하루 거래량이 수백 주에서 수만 주로
흔들리는 것이 평범합니다. 붉은 것이 8%면 아무도 안 봅니다.

좋은 사례를 가져오는 것과 **우리 시장에 맞추는 것은 다른 일**입니다.
표준은 "무엇을 재야 하는가" 를 알려주고, **기준값은 우리가 재서 정해야** 합니다.

## 국내에 참고할 것이 없다는 것도 답이었다

`gh search repos` 로 훑으니 국내 최대가 `FinanceDataReader` ★1,539 ·
`pykrx` ★1,088 입니다. 둘 다 **값을 가져다주는** 도구입니다.
*"이 값을 언제부터 알 수 있었나"* · *"이 표본에 살아남은 것만 있는 것 아닌가"* 는
답하지 않습니다.

처음엔 나쁜 소식으로 읽었는데, 다시 보니 아닙니다. **베낄 것이 없다는 것은
우리가 만들면 국내에 흔치 않은 것이 된다는 뜻**이기도 합니다. 이미 생존 편향이
없고 `as_of` 가 강제되는 것은 qlib 에도 없는 것입니다.

## 배운 것

**초록은 기준이 밖에 있을 때만 뜻이 있습니다.** 이틀 전에는 검사가 대상과 같은
잘못을 공유해서 초록이었고, 오늘은 목록이 우리 손으로 쓴 것이라 초록이었습니다.
모양이 같습니다 — **자기가 만든 자로 자기를 재면 항상 맞습니다.**

그리고 **올리기 직전에 멈춘 것이 맞았습니다.** 지금 올렸으면 주권종류 세 칸 때문에
곧 또 올려야 했습니다. 다 만들어 놓고 안 올리는 것이 아깝게 느껴졌지만,
**한 번 더 올리는 비용보다 팀원이 낡은 규칙으로 학습하는 비용이 큽니다.**
