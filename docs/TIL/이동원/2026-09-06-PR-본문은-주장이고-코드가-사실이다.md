## 옮겨 적는 일이라 쉬울 줄 알았다

팀원이 하신 일을 문서로 남기는 것이 내 몫이다. 강민석 님 PR 둘이 머지돼 있었고 본문이
정성스러웠다. ARIMA 를 워크포워드에 넣었고, 폴드 커버리지를 쟀고, 시도 횟수 계측 인프라를
만들었고, 백테스트 원장에 칸 아홉을 뚫어 HF 에 올리는 코드를 넣었다고 적혀 있었다.
체크리스트가 ✅ 로 가득했다. 그대로 표로 옮기면 한 시간이면 끝날 일이었다.

그런데 지난 세션 메모에 이런 줄이 있다 — *"내 메모의 값도 실측으로 재확인한다. 두 번 틀렸다."*
내 메모도 못 믿는데 남의 PR 본문은 믿어도 되나. 그래서 옮겨 적기 전에 하나씩 코드에서 찾았다.

## 여섯 군데가 달랐다

| PR 본문 | 코드 |
|---|---|
| CMA-ES 상한 21,450 = 143폴드 × 150 | `max_evals` 기본값도 정밀 모드도 **300** → 42,900 |
| `log_trial` 함수와 JSONL 파일을 만들어 두었다 | JSONL 은 0바이트로 있는데 **함수는 저장소 어디에도 없다** |
| 원장을 HF 에 업로드하도록 구현 | 코드는 있다. **HF 에는 없다** — 한 번도 돌리지 않았다 |
| 검증 구간 3개월(60일) | `3 × 21 = 63` |
| ARIMA 를 우리 모델과 같은 기준으로 비교 | 예측은 **1일** 수익률, 비교 대상은 **5일** 라벨 |
| 워크포워드 12폴드 · gap 5 · 커버리지 20.3% | 그 숫자는 합의 체계 것이고, ARIMA 행은 **143폴드 sliding · gap 0** 에서 나왔다 |

어느 것도 거짓말이 아니다. 로컬에는 있는데 커밋에 안 들어간 함수, 돌리려고 했는데 안 돌린
스크립트, 설계 문서의 숫자를 코드 실측인 줄 알고 적은 글머리. 다 그럴 수 있는 일이다.
그러나 **내가 그대로 옮겨 적으면 그때부터는 문서가 거짓말을 한다.** 문서를 읽는 사람은
PR 본문이 아니라 "이동원이 정리한 평가파트 v1.1" 을 본다. 틀리면 내 것이 된다.

## 특히 아픈 것 — 표 하나에 근거가 셋

강민석 님이 보고서용으로 만드신 기준선 표는 다섯 행이다. 두 행은 라벨 분포에서, 한 행은
라벨 겹침 실측에서, 두 행은 143폴드 워크포워드에서 나왔다. 그리고 표 아래 글머리는
12폴드 체계를 적었다. 한 표 안에 **폴드 체계가 둘, 라벨 지평이 둘**이다.

심사자가 "이 41.08% 는 무엇에 대한 정확도인가요" 라고 물으면, 지금 답은 "다음 **하루**가
+0.5% 를 넘느냐" 다. 표의 다른 행은 "다음 **닷새**가 ±1.0% 를 넘느냐" 다. 같은 표에 있으면
같은 문제 같아 보인다. 그것이 표가 하는 일이고, 그래서 표가 위험하다.

## 어떻게 적었나

"틀렸다" 로 적지 않았다. 코드 줄 번호와 함께 **"제가 이렇게 읽었는데 맞나요"** 로 적었다.
남의 파트 코드를 내가 잘못 읽었을 가능성이 늘 있고, 설령 맞더라도 결정은 그분 몫이다.
이슈 #133 은 질문 넷과 회의에서 정할 것 넷으로 끝난다. 문서 v1.1 은 PR 문구와 코드가 다른
곳을 표로 나란히 두고 "회의에서 하나로 맞출 것" 이라 적었다.

그리고 ruff 26건. 전부 그분 파일이었다. 공백·import 정렬·f-string 접두사·EOF 개행 23건은
동작을 안 바꾸니 내가 정리했고, 코드 줄을 고쳐야 하는 3건은 손대지 않고 무엇을 하면 되는지만
적었다. 파트 경계는 "고칠 수 있느냐" 가 아니라 "고쳐도 되느냐" 로 긋는다.

## 배운 것

1. **PR 본문은 주장이다.** 옮겨 적기 전에 줄 번호를 찾는다. 함수 이름이 나오면 `grep` 한다.
   "업로드했다" 가 나오면 서버를 본다. 숫자가 나오면 그 숫자를 만든 상수를 찾는다.
2. **표에 행을 더할 때는 근거의 축이 같은지 먼저 본다.** 다른 축의 숫자를 한 표에 놓는 순간
   읽는 사람은 같은 문제로 읽는다.
3. **남의 파트에서 찾은 것은 질문으로 낸다.** 줄 번호를 붙이면 상대가 10초 안에 맞는지
   확인할 수 있다. 그것이 "지적" 과 "확인 요청" 의 차이다.
