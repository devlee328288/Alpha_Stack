# 답하는 것은 경고가 아니라 기본키다 — 마이그레이션 v13

> 2026-09-07 · 이동원 · 이슈 [#144](https://github.com/devlee328288/Alpha_Stack/issues/144)

## 오늘 아침에 무엇이 있었나

KOSDAQ 업종지수를 받으려다 **KOSPI 업종지수 17종 40,324행을 덮어썼다.** 복구는 그날
안에 끝냈고, 다시 못 하게 **받기 전에 막는 문**을 세웠다([PR #150](https://github.com/devlee328288/Alpha_Stack/pull/150)).
그 문에는 이렇게 적어 두었다.

> 할 일: 기본키에 `index_class` 를 넣는 마이그레이션(v13)을 먼저 하고,
>        그다음 이 파일의 `SAFE_MARKETS` 에 시장을 더한다.

오늘 그 v13 을 했다.

## 왜 검사가 아니라 기본키인가

이 사고의 무서운 점은 **아무 일도 안 일어난 것처럼 보였다**는 것이다. 수집기는 정상
종료했고, 오류도 경고도 없었다. 그리고 **행 수는 오히려 늘었다.**

| | 사고 전 | 사고 후 |
|---|---:|---:|
| 전체 행 | 196,272 | **244,108** |
| KOSPI 종수 | 51 | 49 |
| 하루 종수 | 48 | 31 |

행 수만 보면 "잘 받았다" 다. `index_class` 별로 세어 보고서야 드러났다.

그래서 뒤에 서는 검사로는 부족하다. 덮어쓴 값은 검사가 되살리지 못한다. **막는 자리는
"쓰기 전" 이어야 하고, 쓰기 전에 막는 것은 경고가 아니라 `PRIMARY KEY` 다.**

```sql
PRIMARY KEY (bas_dd, index_name)              -- 옛것: 시장이 없다
PRIMARY KEY (bas_dd, index_name, index_class) -- v13
```

## SQLite 는 기본키를 못 바꾼다

`ALTER TABLE` 로는 안 된다. 공식 문서가 권하는 절차는 다섯 걸음이다 — 새 표 → 복사 →
기존 삭제 → 이름 변경 → **인덱스 재생성**. 마지막을 빠뜨리기 쉽다. 표를 지우면 그
표의 인덱스도 함께 사라지는데, 그건 조회가 느려질 뿐 **틀리지는 않아서** 티가 안 난다.

다섯이 한 트랜잭션에 있어야 중간에 죽어도 반쪽이 안 남는다. 우리 실행기가 이미
`BEGIN IMMEDIATE` 로 감싸고 `PRAGMA user_version` 까지 같은 트랜잭션에 넣고 있어서,
문장만 주면 원자성은 공짜였다.

## 실행기를 한 줄 넓혔다 — 조건은 하나인데 문장이 다섯이다

우리 마이그레이션 항목은 SQL 문자열이거나 **연결을 받아 문장을 만드는 함수**다
(`ALTER TABLE ADD COLUMN` 에 `IF NOT EXISTS` 가 없어서 생긴 규약이다). 그런데 표
재구성은 문장이 다섯인데 판단은 하나다 — *"이 DB 가 옛 기본키인가"*.

문장마다 그 조건을 다시 재면 어떻게 되나. **첫 문장이 표를 바꾸는 순간 조건이 뒤집혀
나머지 넷이 건너뛰어진다.** 새 표만 덩그러니 남고 옛 표가 그대로 살아 있는 상태가 된다.

그래서 지연 문장이 문자열 하나가 아니라 **목록**도 돌려줄 수 있게 했다.

```python
for 문장 in ([statement] if isinstance(statement, str) else statement):
    conn.execute(문장)
```

한 번 판단하고 다섯을 통째로 준다. 목록 가운데서 터져도 앞 문장까지 함께 되돌아간다
(시험 `test_목록_가운데서_실패하면_앞_문장도_되돌아간다`).

## 문이 하나였는데 둘이 됐다

`SAFE_MARKETS = {"KOSPI"}` 하나가 두 가지 이유를 겸하고 있었다. v13 뒤로는 그중 하나가
사라진다. 그런데 나머지 하나는 **남는다.**

| 문 | 무엇을 막나 | v13 뒤 |
|---|---|---|
| ① 구조 | 이 DB 의 기본키에 시장이 있나 | **DB 를 실측**해서 판단 |
| ② 정책 | 하루 호출 한도 (시장당 4,343콜 · 한도 10,000) | `SAFE_MARKETS` 그대로 |

①을 상수가 아니라 **`PRAGMA table_info` 로 재는** 이유가 있다. *"코드에 v13 이 있다"* 와
*"이 DB 가 v13 이다"* 는 다른 사실이다. 팀원이 옛 DB 파일을 물려받을 수 있고,
`migrate_path()` 가 아직 안 불린 채 수집이 먼저 돌 수도 있다. 코드를 근거로 문을 열면
그런 DB 에서 정확히 오늘 아침 사고가 재현된다.

그리고 **두 문의 문구를 섞지 않았다.** 구조가 이미 풀렸는데 "자료를 덮어쓴다" 고 하면
거짓말이고, 사람이 고칠 수 없는 것을 고치려 들게 만든다. 시험으로 못 박았다 —
`assert "덮어쓰" not in 말`.

## 표를 만드는 경로가 둘이다

이게 이 작업에서 가장 조용한 함정이었다. `index_price` 를 만드는 곳이 둘이다.

- `krx_index.SCHEMA` — `init_db()` 가 쓴다
- `migrations.INDEX_PRICE_SCHEMA_V13` — 마이그레이션이 쓴다

어느 쪽이 먼저 돌지는 상황에 달렸다. **한쪽만 고치면** 그 DB 는 옛 모양으로 태어난 뒤
`user_version` 만 13 으로 표시되고, 마이그레이션은 다시 돌지 않으므로 **기본키가 영영
안 고쳐진다.** 예외도 경고도 없다.

같은 함정이 이 파일에 이미 기록돼 있었다 — `add_column_sql` 의 주석이 v9 때 겪은 같은
일을 적어 두었다(*"두 경로가 같은 모양으로 모이게 하는 것이 요점이다"*). 그래서 이번엔
**두 모양을 통째로 대조하는 시험**을 붙였다.

```python
def 모양(conn):
    return [(r[1], r[2].upper(), r[3], r[5]) for r in conn.execute("PRAGMA table_info(index_price)")]
assert 모양(마이그레이션이_만든_DB) == 모양(init_db가_만든_DB)
```

## 실측 — 적용 전후

| | 전 | 후 |
|---|---:|---:|
| `user_version` | 12 | **13** |
| 기본키 | `(bas_dd, index_name)` | **`(bas_dd, index_name, index_class)`** |
| 행 | 196,272 | 196,272 |
| KOSPI 종수·기간 | 51 · 20100104~20260904 | 같다 |
| `close`·`volume`·`market_cap` 합 | — | **같다** |
| NULL 칸 수 (close·open·volume) | 4,105 · 24,941 · 20,836 | 같다 |
| 인덱스 | `idx_index_name_date` | 같다 |
| 표 수 · `daily_price` 행 | 21 · 9,231,938 | 같다 |
| 임시 표 잔여 | — | **0** |

그리고 새 키가 실제로 일하는지 확인했다 — 같은 날 같은 이름의 KOSDAQ 행을 넣어 보니
KOSPI 행을 덮지 않고 **둘이 나란히** 남았다(넣어 보고 되돌렸다).

`index_class` 가 빈 행이 있으면 새 기본키(`NOT NULL`)에 못 들어간다. 조용히 버리면 행이
사라지고, `NOT NULL` 위반으로 그냥 터지면 사람이 무엇을 해야 할지 모른다. **어떤 SQL 을
쳐서 확인하면 되는지까지** 담아 세운다. 우리 DB 는 0행이라 안 걸렸지만, 시험에는 넣어
두었다(`test_v13_은_index_class_가_비어_있으면_멈추고_할_일을_알려준다`).

## 그래서 KOSDAQ 을 받나

**아직 안 받는다.** 구조는 풀렸지만 하루 호출 한도가 남아 있고, 지금 쓰는 곳이 없다 —
개별종목 후보군은 KOSPI 업종지수만 쓰고, KOSPI200 트랙은 업종을 안 쓴다. 켜는 것은
한도에 여유가 있는 날의 별도 결정이다. 문이 그렇게 말하도록 문구를 고쳐 두었다.

## 배운 것

**"왜 꺼져 있나" 를 읽었으면 "켜면 무엇이 깨지나" 까지 봐야 한다** — 오늘 아침의 교훈이다.
거기에 하나가 더 붙는다. **"그 문이 막고 있는 것이 하나인가"** 도 물어야 한다.
`SAFE_MARKETS` 하나가 이유 둘을 겸하고 있었고, 하나가 풀렸다고 문을 통째로 열면
나머지 하나가 조용히 사라진다.

그리고 **고장을 고친 자리에 시험을 두는 것만으로는 모자란다.** 같은 종류의 고장이
다시 들어올 **경로**를 막아야 한다. 여기서는 그게 두 SCHEMA 를 대조하는 시험이었다.
