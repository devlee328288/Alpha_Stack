# 앞당기려면 종목이 아니라 지수가 필요하다

2026-09-07 · 이슈 [#159](https://github.com/devlee328288/Alpha_Stack/issues/159) · 재현 [노트북 06/12](../../../notebooks/06-검토·발견/12.앞당기려면-종목이-아니라-지수가-필요하다.ipynb)

## 무슨 일

오준영 님이 KOSPI200 조합 E 와 개별종목 조합 F 의 공통 OOS 첫 검증일이 `2014-02-17` 인 이유를
적으시며 *"앞당기려면 2010년 이전 HF 준비 데이터를 확보해야 한다"* 고 하셨다. "2010년 이전
데이터" 라는 말을 그대로 받으면 **종목 시세 3,600종을 2008년부터** 받는 일이 된다. 받을 수 있는지
원천 셋을 쳤다 — 종목은 FDR 도 KRX Open API 도 **0행**이었다.

그런데 준비구간을 먹는 것은 `hv_regime = hv_20 / 250일 평균` 이고, 그것은 **KOSPI200 지수 종가만**
쓴다. 개별종목 조합 F 는 `2010-02-01` 부터라 병목이 아니다. 필요한 것은 지수 **269거래일**이고,
FDR 의 지수 경로(GitHub 캐시 CSV)는 2000년부터 준다. 겹치는 닷새의 종가·전일비·등락률·거래량이
우리 KRX 값과 전부 같았다. 붙이면 첫 검증일이 `2013-02-12` — **249거래일** 앞당겨진다.

## 첫 번째 배움 — 요구를 말로 받지 말고 코드에서 센다

"2010년 이전 데이터" 는 결론이 아니라 증상이다. 무엇이 준비구간을 먹는지를 `build_model_dataset`
에 실제로 물으니 답이 **지수 하나**로 줄었다. 종목 3,600종 × 2년을 어디서 받을지 궁리했으면
오늘 안에 못 끝냈고, 결론도 "못 받는다" 였을 것이다.

같은 실수를 09-07 낮에도 했다 — 정지일을 전 시장(2.94%)으로 세다가 학습표본(0.016%)에서 다시
셌다. **영향 범위도 요구도, 구현된 코드가 실제로 도는 자리에서 센다.**

## 두 번째 배움 — 달력이 시장별 3행이라 앞당김을 747 로 셌다

첫 계산에서 앞당김이 **747거래일**로 나왔다. 1년 차이가 747일일 리 없다. `trading_calendar` 가
`(bas_dd, market)` 기본키라 날짜마다 `ALL`·`KOSPI`·`KOSDAQ` 세 행이고, 위치를 세는 사전을 거기서
만들어 **3배**가 됐다. `DISTINCT` 로 다시 세니 249.

아침에 `index_price` 에서 "행 수는 덮어쓰기를 못 잡는다" 를 배웠는데, 저녁에 같은 표 구조에서
"행 수는 거래일 수가 아니다" 로 한 번 더 걸렸다. **키의 축이 둘이면 셀 때마다 어느 축인지 말한다.**

## 세 번째 배움 — 같은 라이브러리라도 기호마다 길이 다르다

FDR 은 종목(`005930`)은 네이버에서 **최근 3,000거래일**만 주고, 지수(`KS200`)는 FinanceData 가
GitHub 에 올린 **연도별 CSV 캐시**에서 준다(`KrxIndexReaderCache`). 코드에서 URL 을 뽑아 확인했다.
"FDR 은 2010 앞을 안 준다" 는 우리 문서의 문장은 **종목에만** 참이었다.

그 캐시 저장소에는 LICENSE 가 없다(★5 · 09-07 에도 갱신 중). 지수값은 사실이라 저작권 대상이 아니라는
것이 통설이지만, 넣는다면 출처·받은 날·리비전을 대장에 적는다 — 모델 라이선스 대장과 같은 관례.
