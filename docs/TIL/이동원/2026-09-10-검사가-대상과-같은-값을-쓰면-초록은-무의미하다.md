## 무엇을 하려 했나

자본변동은 **결과로만** 있었다. `adj_close` 는 이미 펴진 값이고 `adj_source` 는 출처만
말한다. *"무슨 일이 언제 얼마만큼 일어났나"* 가 없어서 물을 때마다 923만 행을 역산했다
(4분). zipline 처럼 사건 표를 세우고, **기존 판정(chain)과 대조해 어긋난 건수를 세는 것**이
목표였다.

## 배운 것 셋

### ① 검사가 대상과 같은 값을 쓰면 초록은 아무것도 뜻하지 않는다

표를 깔고 보니 이랬다.

| 종류 | 행 | 맞음 |
|---|---:|---:|
| `rights_off` | 3,191 | **3,191** |
| `resume_revalue` | 783 | **783** |

3,974건이 전부 맞았다. 당연했다 — 이 둘은 배율을 `adjustment_factor` 에서 얻는데 그것을
다시 `factor_series` 와 견줬다. **같은 값끼리 비교한 것**이다.

억울한 건, 이 함정을 **이미 알고 피해 놨다**는 점이다. `series_restart` 는 `factor_series`
도 같은 `is_series_restart` 로 끊으므로 대조하면 안 된다고 주석까지 써 뒀다. 그래 놓고
바로 옆자리에서 밟았다.

*"검사가 대상과 같은 잘못을 공유하면 초록은 무의미하다"* 는 09-08 에도 한 번 겪었다
(실현수익률이 종가축이었던 건). 그때는 **잘못**을 공유했고 이번엔 **값**을 공유했다.
모양이 달라서 못 알아봤다.

**다음부터**: 대조를 설계할 때 *"이 증거는 대상이 만들 때 쓴 것인가"* 를 축마다 적는다.
표로 적으니 한눈에 갈렸다.

| 증거 축 | chain 이 이 축을 쓰나 |
|---|---|
| 액면가 | 안 쓴다 ✅ |
| 상장일 | 재시작 판정에만 (이전상장은 안 쓴다) ✅ |
| 기준가 | **이것이 곧 chain 이다** ❌ |
| 주식수 | ㉠ 갈래에서 쓴다 ❌ |

### ② 출처가 둘이라고 대조가 되는 것이 아니다

설계는 *"시세와 종목기본정보가 다른 API 에서 오니 주식수를 서로 대조하자"* 였다.
겹치는 **9,229,173행 전부 같았다**(불일치 0). 대조가 아니라 **복사**였다.

두 표가 다른 엔드포인트에서 온다는 것과 두 값이 독립이라는 것은 **다른 이야기**다.
KRX 는 같은 원장에서 둘 다 만든다.

부수 효과가 하나 있었다. 액면가·상장일이 **계단 함수**라는 걸 알고 나니 923만 행이 필요
없어졌다 — 바뀌는 자리 **4,493행**만 읽으면 된다. 처음에는 전량을 dict 로 올렸다가
**14분을 넘기고도 안 끝났는데**(메모리를 삼켰다) 계단으로 바꾸니 **264초**다.

### ③ 문턱은 고르는 것이 아니라 세는 것이다

액면가가 예고한 배율과 chain 계수가 어긋난 자리를 세려는데, 엄격한 등식으로 재니
**237건**이 나왔다. "어? 아까 실측은 15건이었는데."

전수 분포를 그려 보니 답이 있었다.

```
… 8.408e-06  ← 여기까지 662건 (전부 단수주)
   [ 아무것도 없음 — 88,700배 ]
    7.457e-01  ← 여기부터 4건
```

chain 은 재개일에 **주식수 배율**을 쓰는데 그 비율이 정수가 아니다. 417180 은 액면가배율이
정확히 `0.2` 인데 주식수비가 `0.1999999658` 이다 — **4주 차이**(단수주). 같은 사건을 두
축이 마지막 자리까지 다르게 부른 것이라 어긋남이 아니다.

문턱을 먼저 정했으면 원하는 답이 나왔을 것이다. **거꾸로 했다.** 그리고 그 문턱이 빈 구간
안에 있는지 확인하는 시험을 하나 걸어 뒀다 — 나중에 값을 옮길 때 막는다.

```python
def test_문턱은_빈_구간_안에_있다():
    assert 8.408e-06 < ca.AGREE_TOLERANCE < 7.457e-01
```

## 값을 안 고치기로 한 자리

기준가 갈래는 순환이라 못 잰다. 대신 chain 을 **안 쓰고** 재는 축을 하나 세웠다 —
*"주식수가 1.5배 밖으로 바뀌었는데 그 날 등락률이 가격제한폭 밖이다"*.

**17건이 나왔고, 17건 모두 그 종목의 마지막 7거래일에서 시작했다.** 그림으로 그리니
막대가 전부 7 에 모였다. 표로 훑었으면 지나쳤을 자리다.

정리매매다. 그 구간만 가격제한폭이 적용되지 않는다 — `LIQUIDATION_DAYS` 주석이 이미
적어 둔 사실이었다. 그래서 **원본 오류가 아니고**, 17건 전부 `is_liquidation` 이 덮어
`training_frame` 이 덜어내므로 **학습 유출은 0건**이다.

고칠 수 있었지만 안 고쳤다. 수정주가를 다시 만들면 FDR 창이 밀린 만큼 옛 행이 `chain`
으로 내려앉는데, 전부 상장폐지된 종목이라 얻는 게 없다. **`source_conflict` 로 표시만**
하고, 정리매매로 설명 안 되는 자리가 생기면 빌더가 붉은불을 켜게 했다.
