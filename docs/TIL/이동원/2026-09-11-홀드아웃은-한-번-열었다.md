## 1. 무엇을 했나

코드 재사용 자리의 업종·주권종류를 상장 구간으로 고친 뒤(PR #253), 16:18:48 에 홀드아웃(20240901 ~ 20260901)을 **한 번** 열어
`reports/unseal.log` 에 한 줄을 남겼다. 모델 파트 경로로 공식 입력 넷을 만들어 승인하고, ADR 0009 설정으로 **한 번** 돌렸다.
`check` 판정은 **확증 가능**. 결과(평가 478거래일 · 지수 Accuracy 0.4331 · 종목 0.3807 · 매수 후보 7,397)는 private
`alphastack-krx-holdout` 에만 올렸고, 개발본은 봉인본과 바뀐 행 0 이라 다시 올리지 않았다.

## 2. 왜 했나

홀드아웃은 한 번 열면 끝이다. 열기 전에 알던 결함(코드 재사용 74행)을 두고 열면, 연 뒤에는 고쳐도 그 결과를 확증이라
부를 수 없다. 그래서 순서를 **고친다 → 재배포 → 연다** 로 고정했다.

## 4. 어떻게 확인했나

- `check` ✅ — 개봉 1회 · 사전등록 `0d5bd5b` 이 개봉보다 앞섬 · 승인·결과 지문 일치 · 산출물에 원자료 가격·시크릿 없음
- 봉인본 개발구간 vs HF 개발본 — 37칸 · 7,888,945행 · **바뀐 행 0**
- `verify_hf_dataset --skip-download` 16:52 종료코드 0 — 2010~2024년 37칸 완전히 같음
- 09-14 재대조 — 공식 입력은 **두 벌**(16:21 · 16:25)이었고 차이는 총수익 두 칸뿐, 값은 같다. `_final` 은 드라이런 입력과 같은 키에서 값 차이 0 · 한쪽에만 있는 키 29행은 업종 스냅샷 반영일
- 09-14 재대조 — ADR 0010 실행(모델 파트 PC)의 입력 지문 셋이 이 PC 봉인본과 같다

## 6. 배운 것

- **끝 날짜도 설계다.** "가장 최근까지" 가 기본값처럼 보이지만, 마지막 사흘을 채우는 비용이 개발 자료 전체를 흔드는 것이면 사흘을 버리는 쪽이 싸다.
- **같은 날 만든 두 파일은 이름이 달라도 같은 것인지 재야 한다.** 이번에는 값이 같았지만, 승인한 쪽이 어느 것인지는 지문으로만 알 수 있었다.
- **"한 곳에만 있다" 는 규칙이 아니라 관찰이었다.** 막은 것은 업로드였고, 팀 안 복사는 막지 않았다. 문서에 적는 것은 막은 것이어야 한다.
