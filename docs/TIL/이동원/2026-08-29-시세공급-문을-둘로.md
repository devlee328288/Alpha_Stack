## 1. 무엇을 했나

지수만 있던 `supply/` 에 종목 시세 공급(`price_series`)을 얹었다. 그 전에 **정문에
난 구멍 둘을 먼저 막았다** — 상한 없는 조회와 문자열 비교로 뒤집히는 날짜 비교다.

그리고 학습 전용 경로(`supply/training.py`)를 **별도 이름으로** 신설했다.

## 2. 왜 했나

모델 파트(오준영)가 학습 자료를 받아 갈 문이 필요했다. 그런데 문을 열기 전에
**그 문이 실제로 미래를 막고 있는지** 확인해야 했고, 확인해 보니 막고 있지 않았다.

### 구멍 ① — `krx_store.window()` 에 상한이 없었다

하한만 걸려 있었다. "최근 N거래일" 을 고르고 `bas_dd >= floor` 만 걸었으므로 2020년
폴드를 학습하면서 불러도 **오늘까지가 함께** 나왔다. `supply/` 가 그 결과를 다시
자르지 않는 한 미래가 그대로 섞이는데, **예외는 나지 않는다 — 성능만 좋아진다.**

`bas_dd` 가 기본키 첫 칸이라 상한을 거는 비용은 없었다.

### 구멍 ② — `min(end, cutoff)` 가 문자열 비교라 조용히 뒤집혔다

```
min('2026-08-21', '20260825') == '2026-08-21'
```

`'-'`(0x2D)가 `'0'`(0x30)보다 작아서 **하이픈이 든 쪽이 언제나 작다.** `end` 를 ISO로
주면 항상 그쪽이 이기고, 그 값이 `bas_dd <= ?` 에 들어가면
`'20260821' <= '2026-08-21'` 이 거짓이라 **결과가 0행**이 된다. 여기서도 예외는 나지
않는다 — 빈 표를 받은 쪽은 "그 구간에 자료가 없구나" 로 읽는다.

## 3. 어떻게 했나 — 고른 것과 버린 것

### 버린 것 — "정리매매 행 제외를 인자로 여는" 안

착수 메모는 *"정리매매 플래그 행을 기본으로 제외할지 인자로 열지"* 를 물었다.
**둘 다 버렸다.**

그 판정은 [PR #9](2026-08-29-품질게이트-순환논법.md)에서 확인했듯 **미래를 본다** —
"이 뒤로 체결이 끊긴다" 는 그 시점에 알 수 없는 사실이다. `as_of` 정문이 그걸
계산해 행을 덜어내면 **문이 지키려던 경계를 문이 스스로 넘는다.**

손잡이 하나로 켜고 끄게 두면 언젠가 켜진 채로 예측 경로에 들어간다. 그리고 그때도
예외는 나지 않는다.

### 고른 것 — 손잡이가 아니라 **이름**으로 가른다

```
supply.price_series(as_of=...)   그 시점에 알 수 있었던 것만. 플래그 없음
supply.training_frame(...)       전 구간을 보고 정리매매·신규상장을 덜어낸다
```

`training` 이 이름에 박혀 있어서 **예측 코드에서 부르면 리뷰에 걸린다.**

이건 누수가 아니라 **표본 선택**이다. 모델은 그 행을 본 적이 없고 예측할 때도 그
판정을 쓰지 않는다. 다만 공짜가 아니라서 둘을 못 박았다.

- **곧 죽을 종목을 골라 빼면 생존 편향이 되돌아온다.** 우리가 빼는 것은 종목이 아니라
  **구간**이다. 소멸 종목 910개는 전부 남기고 마지막 10체결일만 뺀다.
- **덜어낸 양을 반드시 말한다.** `attrs["dropped"]` 에 무엇을 얼마나 뺐는지 남긴다.
  조용히 빠지면 표본 수가 왜 줄었는지 아무도 모른다.

### `holdout_start` 에 기본값을 두지 않았다

`as_of` 와 같은 수법이다. 기본이 "자르지 않음" 이면 빠뜨려도 돌아가고, **빠뜨린 그
한 번이 봉인 구간을 연다.** `None` 을 적는 것은 의도를 적는 것이다.

`evaluation.horizon.HOLDOUT_START` 를 여기서 import 하지 **않았다.**
`supply → evaluation` 은 계층 화살표를 거꾸로 뒤집고, 나중에 evaluation 이 supply 를
부르는 순간 순환이 된다. 값은 부르는 쪽이 넣는다.

### 반환을 `pandas.DataFrame` 으로 통일했다

피처·모델·평가가 전부 pandas 로 짜인다. 딕셔너리 목록을 주면 부르는 쪽마다
`pd.DataFrame(rows)` 를 한 줄씩 쓰게 되고, **빈 결과일 때 칸이 없는 표**가 만들어져
`df["close"]` 가 `KeyError` 로 터진다. 받는 쪽은 그걸 "자료가 없다" 가 아니라
"코드가 깨졌다" 로 읽는다. **행이 0개여도 칸은 언제나 있다.**

### 날짜 표기를 `as_bas_dd` 로 강제했다

구멍 ②를 고치는 방법으로 "부르는 쪽이 잘 맞춰 넣기" 를 버리고 **실수 자체를
불가능하게** 만들었다. 표기만 바꾼다 — "언제부터 알 수 있었나" 는 여전히
`latest_known_day` 다. 둘을 섞으면 경계가 하루씩 어긋나고 **그 하루가 곧 누수다.**

## 4. 어떻게 확인했나

테스트 48개 (경계 23 · 종목 18 · 저장소 상한 7).

실제 DB 로 확인(2026-08-29):

```
005930 삼성전자           전 4,097행 · as_of=2021-09-01 이면 2,880행
269620 시스웍             first_listing 1 (2017-12-26 상장) · halted 1
192410 감마누계열         liquidation 15 · halted 586
end='2021-08-31' 과 end='20210831' 이 같은 2,880행 → 표기 함정 해소
```

### 준비 비용을 한 번만 낸다 — 실측 10배

`training_frame` 을 종목마다 부르면 거래일 달력(920만 행 스캔)을 매번 다시 만든다.

| | 종목당 | 3,677종목 |
|---|---|---|
| context 없이 | 2.71초 | 166분 |
| context 재사용 | **0.266초** | **16.3분** (준비 0.77초 1회) |

`market_context()` 로 한 번 만들어 `training_frames()` 가 나눠 쓴다.
**모듈 전역에 몰래 캐시하지 않았다** — 수집 배치가 새 행을 넣은 뒤에도 낡은 달력을
계속 쓰게 되고, 그래도 예외는 나지 않는다. 새 거래일이 조용히 빠질 뿐이다.

## 5. 막힌 것 · 남은 것

- 전 종목 학습 자료 준비가 16.3분이다. 더 줄이려면 전 종목을 한 번에 흘려보내야
  하는데(`scripts/check_data.py` 가 그래서 98.6초다) 종목 단위 API 와 모양이 다르다.
  하루 한 번 도는 일이라 지금은 문제가 아니다.
- `krx_pg` · `krx_bundle` 에는 `end` 손잡이를 달지 않고 파이썬에서 잘랐다. 둘 다
  정본이 비었을 때만 쓰이는 비상 경로다(축약본은 150거래일).
- **자본변동(액면분할·병합)은 `training_frame` 이 빼지 않는다.** 그 날의 가격은 실제
  체결가이고, 문제는 앞뒤를 이어 붙일 때 생긴다. 이어 붙이는 쪽(라벨 계산)이
  `is_basis_adjusted` 로 판단할 일이다 — 라벨 작업에서 다룬다.

## 6. 배운 것

**"인자로 열어 둔다" 는 안전장치가 아니다.** 기본값이 안전해도 손잡이가 있으면
언젠가 반대로 놓인 채 지나간다. 그리고 데이터 누수는 예외를 던지지 않는다 — 성능이
좋아질 뿐이라 아무도 의심하지 않는다. 그래서 **경계를 지키는 일은 이름으로** 한다.

**조용한 실패를 세 번 만났다.** 상한 없는 조회 · 뒤집힌 문자열 비교 · 낡은 캐시.
셋 다 예외가 나지 않고, 셋 다 결과가 그럴듯하다. 이런 종류는 테스트를 "돌아가는가"
가 아니라 **"경계에서 정확히 몇 행인가"** 로 짜야 잡힌다.

**최적화는 답이 같은지부터 못 박는다.** context 재사용으로 10배를 얻기 전에 두
경로가 같은 표를 주는지 테스트로 먼저 고정했다.
