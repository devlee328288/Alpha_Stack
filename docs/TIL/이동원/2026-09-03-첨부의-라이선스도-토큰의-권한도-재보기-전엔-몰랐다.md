## 1. 첨부가 "MIT" 라 적은 모델의 카드에는 라이선스가 없었다

첨부는 18종에 라이선스를 적어 두었습니다. 그대로 옮겨 적으면 한 시간이면 끝날 표였습니다.
그런데 조사 폴더의 원칙이 *"라이선스가 카드에 명시된 것만 쓴다"* 라서 카드 API 를 한 번씩
두드렸습니다.

| 첨부 | 카드 |
|---|---|
| ProsusAI/finbert **MIT** | 미표기 |
| yiyanghkust/finbert-tone **MIT** | 미표기 |
| snunlp/KR-FinBert-SC **CC-BY-NC-SA** | 미표기 |
| facebook/nougat-base **MIT** | **cc-by-nc-4.0** |
| openai/whisper-large-v3 **MIT** | apache-2.0 |

18종 중 8종(표기 불일치 7 + 카드 자체가 없는 것 1). 첨부가 1순위로 꼽은 한국어 금융
감성 모델이 그 안에 있었습니다.

어디서 어긋났는지 짐작은 갑니다 — `ProsusAI/finBERT` **GitHub 저장소**는 Apache-2.0 입니다.
저장소 LICENSE 를 모델 라이선스로 읽은 것입니다. 코드와 가중치는 다른 물건이고, 가중치의
라이선스는 **모델 카드**에만 있습니다.

## 2. 호출한 14종이 전부 403 — 모델이 아니라 토큰이었다

인코더 가운데 시험 문장이 있는 14종에 실제로 보냈습니다. 전부 `403`. 처음엔 *"원격 추론이 안
되는 모델들이구나"* 하고 표에 ❌ 를 달 뻔했습니다. 본문을 읽었습니다.

```
This authentication method does not have sufficient permissions
to call Inference Providers on behalf of user data-student
```

`whoami-v2` 로 토큰을 봤더니 `repo.*` 와 `discussion.write` 뿐이었습니다. Fine-grained
토큰은 **"Make calls to Inference Providers"** 를 따로 켜야 하는데, 이 토큰은 데이터셋을
올리려고 만든 것이라 그 항목이 없었습니다. 서버에 *"이 모델 제공하나"* 를 따로 물으니
6종이 `live` 였습니다.

같은 403 이 세 가지 뜻일 수 있습니다 — 모델이 없다 · 서버가 제공하지 않는다 · **내 권한이
없다.** 상태 코드만 보고 표를 채웠으면 6종을 통째로 버렸을 겁니다.

팀장이 그 자리에서 권한을 켰고, 같은 스크립트를 다시 돌리니 200 이 7종이었습니다.
그런데 **400 도 둘로 갈라졌습니다.** `Model not supported by provider` 는 정말 제공하지
않는 것이고, `SentenceSimilarityPipeline … missing 'sentences'` 는 **경로가 다른 것**이었습니다
— `/pipeline/feature-extraction` 으로 부르니 MiniLM 이 0.3초에 384차원 벡터를 줬습니다.
저장소 클라이언트 `hf_data.py` 가 2026-08-02 에 같은 것을 실측해 둔 것을 오늘 다시 배웠습니다.
콜드 스타트는 `KURE-v1` 이 24.9초, 2.2GB 짜리 `bge-m3` 는 120초 게이트웨이를 넘겨 504.
한국어 제로샷(`xlm-roberta-large-xnli`)은 "영업이익이 시장 예상을 웃돌았다" 에 긍정 0.988.

## 3. "제공한다" 는 표시가 몇 분 사이 바뀌었다

`BAAI/bge-m3` 가 첫 조회에서 `live`, 다시 돌리니 `error`, 세 번 더 물어도 `error`.
한 번 조회한 값을 설계의 전제로 삼으면 안 됩니다. 기존 클라이언트(`hf_data.py`)가 실패를
예외가 아니라 값으로 돌려주도록 짜여 있는 이유를 오늘 몸으로 알았습니다.

## 4. 원료가 0행인데 모델 표부터 보고 있었다

첨부의 모델은 전부 **텍스트**를 먹습니다. 우리 DB 에 텍스트가 몇 행 있나 셌더니
`dart_disclosure` 0행, 뉴스 표는 없음. 모델을 아무리 골라도 넣을 것이 없었습니다.
그래서 설계의 첫 절이 모델이 아니라 **원료** 가 됐습니다 — DART 공시 제목이 접수일도
기록값이고 약관 제한도 없어 1차 원료입니다. 뉴스는 네이버 약관이 "저장(캐시 행위 포함)"
을 막아 팀 판단 뒤로.

## 5. GitHub 는 "얼마나 하면 막히는지" 를 말해 주지 않는다

강사님 저장소의 Actions 는 봇이 자기 저장소에 커밋합니다. 우리는 10일에 커밋 181건을
내는 팀이라 그 패턴을 들이면 커밋이 두 배가 됩니다. 계정 정지 이력도 있습니다.
GitHub 문서를 뒤졌지만 **판정 기준은 비공개**였습니다 — 커뮤니티 토론에서 스태프 답은
*"support 로 문의하라"* 뿐. 한도(Actions 공개 저장소 무료 · REST 5,000/h · 콘텐츠 생성
500/h)는 우리 사용량의 1% 도 안 되지만, 한도가 아니라 "자동 대량 활동" 판정이 문제입니다.

증명할 수 없으면 보수적으로 갑니다 — 봇 커밋 없이 **검사만** 하는 CI, `contents: read`,
도입 전에 `nektos/act` 로 로컬에서 돌려 push 0회로 검증.

## 배운 것

| 무엇 | 한 줄 |
|---|---|
| 첨부의 라이선스 | 저장소 LICENSE ≠ 모델 카드. **카드만 믿는다** |
| 403 | 셋 중 하나다. **본문을 읽어야** 갈라진다 |
| 400 | 둘 중 하나다 — 미제공 · **경로 다름**. 400 만 보고 버리면 멀쩡한 모델을 잃는다 |
| 콜드 스타트 | 25초까지. 타임아웃은 추측이 아니라 이 값으로 |
| 제공자 표시 | 흔들린다. 한 번 조회한 값에 설계를 걸지 않는다 |
| 설계 세션 | 코드가 0줄이어도 **실측은 0건이 아니다.** 실측이 설계를 두 번 바꿨다 |
| 판정 기준이 비공개면 | "얼마나" 를 증명하려 하지 말고 가장 가까운 패턴을 피한다 |
