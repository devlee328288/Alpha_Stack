## 2. 왜 했나

**③이 이 세션에서 가장 먼저 와야 했습니다.** F-05 의 수용 기준이 *"이 파일의 커밋 시각이
`unseal.log` 첫 행보다 앞선다"* 이기 때문입니다. 데이터를 더 들여다본 뒤에 쓰면 그건
가설이 아니라 관찰의 재진술입니다.

**④는 안 하면 이후 실험이 전부 오염됩니다.** `walk_forward` 의 `gap` 기본값이 0 이었습니다.
즉 아무 생각 없이 부르면 누수되는 설계였고, 누수는 **예외를 내지 않고 성능만 올립니다.**

**⑥은 역할이 바뀌어서**입니다. 세션 중간에 내 담당이 데이터 수집·전처리·크롤링·화면이고
`features/`·`models/` 는 미배정이라는 게 확인됐습니다. 원래 계획(F-06·F-07·F-10)은
모델링 파트라 내려놓고 내 파트를 정의하는 쪽으로 틀었습니다.

## 3. 어떻게 했나 — 고른 것과 버린 것

### ③ 주 지표와 검정 통계량이 서로 달랐다

[문제정의 §2](../문제정의/version1.0/문제정의.md)는 주 지표를 ΔSharpe 로,
§3.1 은 검정을 초과수익 평균으로 적어 두었습니다. **둘이 다릅니다.**

Sharpe 는 비율 통계량이라 block bootstrap 수렴이 평균보다 나쁩니다. 그래서
**검정은 평균으로, 보고는 Sharpe 로** 하되, 둘이 어긋나는 경우를 막으려고 기각 조건을
`p < 0.05` **AND** `ΔSharpe > 0` 연언으로 묶었습니다.

**느슨하게 바꾸는 방향이었다면 하지 않았을 것입니다.** 사전등록에서 기준을 완화하는 쪽으로
고치면 사전등록의 의미가 없습니다.

### ③ 값을 못 정하는 항목은 "고르는 규칙"을 잠갔다

회의안건이 *"확장창 vs 롤링창과 폴드 수를 사전등록 시점에 고정하라"* 고 요구하는데,
아직 개발 구간을 돌려 보지 않아 값을 정할 근거가 없었습니다.

- 지금 찍으면 → 근거 없는 숫자
- 나중에 정하면 → 사전등록이 아님

그래서 **값 대신 규칙**을 고정했습니다 — *폴드별 ΔSharpe 의 **중앙값**이 큰 쪽,
동률이면 확장창, 폴드 12, min_train 750.* 규칙이 잠겨 있으면 결과를 보고 유리한 쪽을
고를 수 없습니다.

평균이 아니라 중앙값인 이유는 **코로나 급락 폴드 하나에 끌려가지 않으려고**입니다.

### ④ `horizon` 이 두 뜻으로 쓰이고 있었다

이게 이 세션에서 가장 오래 붙든 문제입니다.

| 이름 | `walk_forward` 안에서의 뜻 | ADR-AS-0002 에서의 뜻 |
|---|---|---|
| `horizon` | 한 폴드에서 **검증할 시점 수**(검증창 길이) | **레이블 앞보기**(5거래일) |

우리 프로젝트는 둘 다 5라 **우연히 맞습니다.** 그런데 검증창을 넓히는 순간 갈라집니다.

```
horizon=60, gap=5   ← 검증창 60 · 레이블 5일. 올바른 호출
```

- 누수 규칙을 **검증창 기준**으로 검사하면 → 위 호출이 억울하게 막힌다
- `gap` 을 **검증창에 맞추면** → 60시점을 통째로 버려 검증 표본이 12배로 날아간다

그래서 `label_horizon` 을 따로 받고 **누수 판정은 언제나 그 기준**으로 했습니다.
생략하면 `horizon` 을 쓰므로 F-09 수용 기준(`gap == horizon`)은 그대로 만족합니다.

**파라미터를 하나 늘린 이유가 이것입니다** — 안 늘리면 규칙 자체가 덫이 됩니다.

### ⑤ 파일 해시가 아니라 내용 해시를 골랐다

F-02 수용 기준이 *"다른 날 두 번 돌려도 두 산출 JSON 의 해시가 같다"* 인데,
parquet **파일** 해시로는 그것을 보장할 수 없습니다. 실제로 파일 메타를 열어 보니:

```
created_by : parquet-cpp-arrow version 25.0.1
```

**pyarrow 를 올리는 순간 같은 자료의 파일 해시가 달라집니다.**
그래서 열 순서·행 순서·숫자 표기를 고정한 정규 형태를 해시했습니다.

### ⑥ 2차 자료를 안 믿고 `robots.txt` 를 직접 받았다

크롤링 가능 여부는 블로그 글로 판단할 게 아니라서 `urllib` 로 직접 받았습니다.
`finance.naver.com` 이 종목토론방을 **조건부로** 허용하고 있었습니다.

```
Allow:    /item/board.naver?code=*          ← 첫 페이지 허용
Disallow: /item/board.naver?code=*&page=*   ← 페이지 넘기기 금지
```

**과거 소급은 막혀 있고 앞으로 쌓는 것은 열려 있습니다.** 이 한 줄이 커뮤니티 데이터
설계를 통째로 정했습니다 — 백필하지 않고 **누적**합니다.

## 5. 막힌 것 · 남은 것

### 두 번 걸린 것 — heredoc

`\n` 이스케이프가 heredoc 을 지나며 **실제 개행**이 되어 f-string 이 깨졌습니다
(`SyntaxError: unterminated f-string literal`). 이스케이프를 아예 안 쓰도록
메시지를 **줄 리스트 join** 으로 바꿔 해결했습니다. 덤으로 읽기도 좋아졌습니다.

그리고 bash 가 **한글 변수명**을 못 다뤄 `case` 문 안의 `$요약` 이 통째로 날아갔습니다.
한글이 섞이는 스크립트는 Python 으로 씁니다.

### 스테이징 사고

`git add` 목록에 이미 옮겨진 `docs/ERD.md` 를 넣어 `fatal: pathspec did not match`
로 **전체 add 가 중단**됐고, 그 상태로 커밋해 **메시지가 내용보다 많은 커밋**이 됐습니다.
푸시 전이라 메시지를 실제 내용에 맞게 고치고 나머지를 별도 커밋으로 나눴습니다.

→ **교훈**: `git add` 뒤에는 `git diff --cached --stat` 으로 **무엇이 들어갔는지 눈으로 본다.**

## 6. 배운 것

**① 기본값이 곧 정책이다.** `gap=0` 은 "필요하면 켜세요" 가 아니라 **"빠뜨리면 조용히
틀리세요"** 였습니다. 예외를 내지 않는 오류는 기본값을 안전한 쪽에 두고 위험한 쪽을
**명시하게** 만들어야 막힙니다.

**② 같은 이름이 두 뜻이면 반드시 하나가 틀린다.** `horizon` 이 검증창 길이이자 레이블
앞보기였고, 값이 우연히 같아서 아무도 몰랐습니다. 우연한 일치는 **버그가 아직 안 터진
상태**일 뿐입니다.

**③ 재현성의 정본은 형식이 아니라 내용이다.** parquet 파일 안에 라이브러리 버전이
박힙니다. 버전에 매인 값을 지문으로 삼으면 언젠가 "같은 자료인데 다르다" 가 나옵니다.

**④ 제약을 먼저 읽으면 설계가 저절로 정해진다.** `robots.txt` 한 줄과 YouTube 쿼터 개편
한 줄이 커뮤니티·동영상 수집 설계를 통째로 정했습니다. 만들고 나서 확인했으면
전부 버려야 했습니다.

**⑤ 불편한 결론일수록 먼저 적는다.** 뉴스·커뮤니티·동영상은 과거가 없어 1차 백테스트에
못 씁니다. 지금 적어 두지 않으면 9월 둘째 주에 "왜 안 되지" 로 이틀을 버립니다.
