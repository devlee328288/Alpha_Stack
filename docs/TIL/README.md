# docs/TIL — 작업 기록

> 한 번의 작업 묶음이 끝날 때마다 여기에 한 장을 남깁니다.
> **PR 하나 = TIL 한 장**이 기본이고, PR 을 만들지 않은 작업(조사·회의 준비 등)도 남깁니다.
> 파일은 **`docs/TIL/<작성자>/` 아래**에 둡니다.
>
> 신설 2026-08-26 · 작성자 폴더 도입 2026-08-29

---

## 왜 이걸 쓰나

우리 팀은 2주 동안 네 명이 같은 저장소를 만집니다. 이때 가장 비싸게 잃는 것은
**"왜 그렇게 했는지"** 입니다. 코드는 git 이 남기지만, 그 코드를 쓰기 전에 무엇을 재 보고
무엇을 버렸는지는 아무데도 남지 않습니다.

세 가지를 위해 씁니다.

| 대상 | 얻는 것 |
|---|---|
| **팀원** | 내가 자리를 비운 동안 무슨 일이 있었는지 5분 안에 따라잡는다 |
| **미래의 나** | 2주 뒤 발표 준비할 때 "이 숫자 어디서 나왔더라"를 다시 찾지 않는다 |
| **평가자** | 결과물만이 아니라 **과정**을 보여준다. 이게 포트폴리오의 실체다 |

### ADR 과 무엇이 다른가

헷갈리기 쉬워서 미리 가릅니다.

| | [docs/decisions/](../decisions/) (ADR) | docs/TIL (이 폴더) |
|---|---|---|
| 남기는 것 | **결정** — 되돌리기 어렵고 나중에 "왜 이렇게 했지"가 나올 것 | **작업** — 그날 무엇을 했고 무엇을 알게 됐나 |
| 시점 | 결정할 때 한 번 | 작업할 때마다 |
| 수명 | 영구. 뒤집히면 새 ADR 이 대체한다 | 그날의 기록. 고치지 않는다 |
| 예 | "저장소를 Supabase 로 간다" | "Supabase 무료 티어 용량을 재 봤다. 결과는 …" |

**TIL 에서 결정이 나오면 ADR 로 옮깁니다.** TIL 은 그 ADR 을 링크만 겁니다.

## 파일 이름 — 작성자 폴더 아래에 둡니다

```
docs/TIL/<작성자>/YYYY-MM-DD-짧은-제목.md
```

예: `docs/TIL/이동원/2026-08-29-품질게이트-순환논법.md`

- **폴더는 작성자 이름**입니다. 팀원 네 명이 같은 저장소에 쓰기 때문입니다.
- 날짜는 **KST 기준 작업한 날**입니다.
- 하루에 여러 건이면 제목으로 가릅니다 — `2026-09-03-rsi-피처.md`, `2026-09-03-결측-처리.md`
- 제목은 한글·영문 아무거나 좋지만 **띄어쓰기 대신 하이픈**을 씁니다.

### 왜 작성자로 나누나

날짜순으로 평평하게 쌓으면 두 가지가 무너집니다.

**① 누가 무엇을 했는지 안 보입니다.** 파일 안의 `작성` 칸을 하나씩 열어야 압니다.
평가자가 "이 사람이 2주 동안 무엇을 했나" 를 보려면 폴더 하나면 됩니다.

**② 이름이 부딪힙니다.** 같은 날 두 사람이 비슷한 작업을 하면 파일명이 겹칩니다.

⚠️ **폴더가 한 단계 깊어졌으므로 상대 경로도 한 단계 깊어집니다.**
`../decisions/` 가 아니라 `../../decisions/` 입니다. 옮긴 뒤에는
`python scripts/check_doc_links.py` 로 확인합니다.

## 형식 — PR 을 쓰듯이

아래 6칸을 채웁니다. 빈 칸은 지우지 말고 **"없음"** 이라고 적습니다 —
"없음"과 "안 썼음"은 다릅니다.

```markdown
# 2026-09-03 · RSI·MACD 피처를 넣는다

| | |
|---|---|
| 작성 | 홍길동 |
| PR | [#12](https://github.com/devlee328288/Alpha_Stack/pull/12) |
| 브랜치 | `feat/rsi-macd-features` |
| 관련 | [ADR-AS-0003](../decisions/0003-수집-계층.md) · [회의안건 B-1](../회의안건/2026-09-01-킥오프.md) |

## 1. 무엇을 했나
(한 문단. 코드가 아니라 **결과**를 적는다.)

## 2. 왜 했나
(무엇이 막혀 있었나. 이걸 안 하면 무엇이 안 되나.)

## 3. 어떻게 했나 — 고른 것과 버린 것
(후보가 둘 이상이었으면 왜 이걸 골랐는지. 이 칸이 이 문서의 값어치다.)

## 4. 어떻게 확인했나
(테스트·실측·눈으로 본 것. **숫자는 실측만** 적는다 — AGENTS.md 5.4)

## 5. 막힌 것 · 남은 것
(다음 사람이 이어받을 수 있게.)

## 6. 배운 것
(다음에 같은 실수를 안 하려고 적는다. 없으면 "없음".)
```

## 쓸 때 지킬 것

**① 숫자는 실측만.** 재지 않았으면 "미측정"이라고 씁니다.
추측을 적으면 다음 사람이 그걸 근거로 판단합니다. ([AGENTS.md 5.4](../../AGENTS.md))

```markdown
❌ 수집이 한 30분쯤 걸린다
✅ 5년치 2,450콜 · 실측 42분 (1.03초/콜 × 6워커, 2026-08-26)
✅ 수집 시간은 미측정 — 아직 안 돌려 봤다
```

**② 실패도 적습니다.** 안 된 것을 적지 않으면 다음 사람이 같은 벽에 다시 부딪힙니다.
"세 시간 헤맸고 원인은 X 였다"가 이 폴더에서 가장 값진 한 줄입니다.

**③ 버린 선택지를 적습니다.** 고른 것만 적으면 나중에 "왜 A 를 안 썼지?"가 다시 올라옵니다.

**④ 링크를 겁니다.** 코드는 `file:line`, 결정은 ADR, 미결은 회의안건으로.

**⑤ 고치지 않습니다.** 나중에 틀린 것이 밝혀져도 그 문서를 수정하지 말고
**새 TIL 에서 정정**합니다. 기록은 그날의 상태를 보여주는 것이지 정답 모음이 아닙니다.
