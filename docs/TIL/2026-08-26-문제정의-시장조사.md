## 2. 왜 했나

`features/`가 첫 줄을 못 쓰고 있었습니다. **예측 대상이 안 정해져서**입니다.

그런데 파고 보니 문제가 더 위에 있었습니다 — **계획서에 문제 정의가 없었습니다.**
있는 것은 연구 동기였고, "누구의 어떤 문제"가 한 문장도 없었습니다.
문서 전체에서 *"사용자"·"투자자"·"이해관계자"* 라는 단어가 한 번도 나오지 않았습니다.

성공 기준 5개도 전부 **"산출물이 존재하는가"** 였습니다 —
*"예측 결과가 재현된다"* · *"동일 조건 비교표가 나온다"*.
**이 기준으로는 AUC 0.50 모델과 0.60 모델이 똑같이 "필수 달성"입니다.**

## 3. 어떻게 했나 — 고른 것과 버린 것

### 3.1 문제 정의 — 3안을 경합시켰다

| 안 | 프레이밍 | 결과 |
|---|---|---|
| ① **검증인프라** | "예측기가 아니라 **검증기**를 만든다" | ✅ **채택 (척추)** |
| ② 의사결정도구 | "개인투자자의 판단을 돕는 도구" | 도입부만 차용 |
| ③ 반증연구 | "예측력을 반증 가능하게 검정한다" | **사전등록·봉인 홀드아웃**만 차용 |

**①을 고른 결정적 이유**: 저장소 실측과 문서가 일치하는 배치가 이것뿐이었습니다.
`evaluation/` 478줄과 테스트 20개는 서 있고 `features/`·`models/`·`api/`는 빈
`__init__.py`입니다. **완성된 것을 첫 칸에 놓는 배치만이 정직합니다.**

**②를 버린 이유**: 예측 대상(지수)과 사용자 서사(개별 종목을 보는 개인)가 어긋납니다.
사용자 인터뷰가 0건이라 *"그 사용자는 지수를 안 보지 않나"*에 반박이 약합니다.

**③을 중심으로 안 둔 이유**: *"검출 한계가 7.9pp라 애초에 기각할 수 없는 실험"*을
첫 3분에 꺼내면 국비 부트캠프 평가에서 **"결과가 정해진 걸 왜 하나"**로 되돌아옵니다.

### 3.2 예측 지평 — 1일을 버리고 5일로 (이 결정이 프로젝트의 생사였다)

```
손익분기 방향정확도 = 0.5 + 왕복비용 / (2 × E|수익|)
```

| 조합 | 손익분기 | 문헌상 상한 | 판정 |
|---|---|---|---|
| 개별주 · 1일 · 0.23% | **62.72%** | 55%대 | 🔴 **맞혀도 진다** |
| ETF · 5일 · 0.05% | **51.24%** | 55%대 | 🟢 검정할 여지가 있다 |

**1일 지평으로 갔다면 "정확도가 얼마 나오든 지는" 실험을 2주 동안 했을 것입니다.**
그건 실험이 아니라 이미 답이 정해진 계산입니다.

### 3.3 백필 범위 — 5년을 버리고 16년으로

처음엔 5년으로 정했는데, 조사가 뒤집었습니다.

| 검증 표본 | 55% vs 52.72%의 z |
|---|---|
| 297일 (원본 보유량) | 0.59 ← **구분 불가** |
| 1,250일 (5년) | 1.20 |
| **2,500일 (10년)** | **1.70** ← 겨우 유의 |

거기에 Bailey 등의 최소 백테스트 길이 — **5년이면 전략 변형 45개까지**가 한계입니다.
모델 4종 × 하이퍼파라미터면 금방 넘습니다. 그래서 KRX가 주는 **전부**(2010-01-04~)를 받았습니다.

## 5. 막힌 것 · 남은 것

### 5.1 하루 한도를 다 못 씁니다

KRX는 **인증키당 1일 10,000회**입니다.

| 백필 | 콜 |
|---|---|
| 지수 16년 | 4,343 (43%) |
| 종목 16년 | 8,686 (87%) |
| 둘 다 | **13,029 (130%) — 초과** |

오늘은 지수를 우선했습니다. 개별종목은 **2013-01-16까지** 차 있습니다
(**7,726,776행 · 3,339거래일 · 3,413종목**). 2010-01-04 까지 채우려면 약 1,000일치를
더 받으면 됩니다 — `fetch_log`가 받은 날짜를 기억하므로 안전합니다.

> ⚠️ **세션 중에 이 수치를 한 번 틀리게 보고했습니다** — 6,006,583행 · 2016-08 로 적었는데,
> 그건 백필이 **도는 중에** 잰 값이었습니다. 백그라운드 작업의 중간 상태를 최종값처럼
> 적으면 안 됩니다. 끝난 뒤에 다시 재야 합니다.

### 5.2 미측정으로 남긴 것

- **5일 지평 손익분기** — √5 근사입니다. 실제 5일 절대수익 분포로 다시 재야 합니다
- **슬리피지** — 0.07%p는 0.3% − 0.23%의 잔차일 뿐 실측이 아닙니다
- **레이블 중립 클래스 비율** — ±1.0%로 잘랐을 때 세 클래스가 각 15~45%에 드는지
- **OOS 커버리지** — 폴드 간격이 horizon과 어긋나면 검증 창 사이가 빕니다 (손계산 약 19%)

### 5.3 다음 사람이 할 것

1. 개별종목 백필 이어받기 (`python scripts/fetch_krx.py --days 4343`)
2. 스냅샷 박제 + SHA-256 ([F-02](../요구사항.md))

## 6. 배운 것

### ① `429`를 안 주는 API가 있다 — 그리고 `401`로 답한다

가장 비싸게 배웠습니다. 지수 백필이 두 번 멈췄고, 두 번 다 **오진**했습니다.

| 시도 | 내 진단 | 실제 |
|---|---|---|
| 1차 | "일일 한도 소진" | ❌ |
| 2차 | "일시적 깜빡임" | ❌ (부분적으로만 맞음) |
| 3차 | **"동시 호출"** | ✅ |

같은 날 같은 키로 잰 결과입니다.

| 워커 | 결과 |
|---|---|
| 6 | 1,344일 받고 차단 |
| 4 | 100일 받고 차단 |
| **1** | **4,343일 완주** |

**KRX가 `429 Too Many Requests`가 아니라 `401 Unauthorized`로 답합니다.**
그래서 겉보기엔 *"인증키가 틀렸다"*로 보이고, **키를 아무리 확인해도 답이 안 나옵니다.**

> 👉 **교훈**: 인증 오류가 났을 때 키부터 의심하지 말고, **부하 조건을 바꿔 가며 재 본다.**
> 워커 수를 6 → 4 → 1로 바꾸며 재고 나서야 원인이 보였습니다.

### ② 웹 서버에 맞는 설계가 배치에서는 정반대로 작동한다

차단기(circuit breaker)가 **401 한 번에 즉시 차단**하도록 되어 있었습니다.
웹 서버에는 옳습니다 — 키가 틀렸는데 요청마다 KRX를 두드릴 이유가 없습니다.

**그런데 4,343콜 백필에서는 깜빡임 하나가 남은 3,000일을 45초 만에 전멸시켰습니다.**
(네트워크를 안 타므로 빨랐습니다.)

같은 코드가 **두 맥락에서 정반대로 작동**했습니다. 그래서 고칠 때 **두 요구를 각각
테스트로 못 박았습니다** — 한쪽만 보고 고치면 다른 쪽이 조용히 깨지는 자리입니다.

### ③ `*.db`는 `*.db-wal`을 못 막는다

`.gitignore`에 `data/*.db`가 있었는데, SQLite가 WAL 모드로 돌면
`krx_cache.db-wal`을 만듭니다. **하이픈 뒤가 붙으면 확장자가 달라져 패턴에 안 걸립니다.**

수집 5분 만에 그 파일이 **9.6MB**까지 자랐고 내용은 전부 실제 시세입니다.
이 저장소는 **PUBLIC**이고 KRX 약관 제11조 ②가 제3자 제공을 금지합니다.
누가 수집 중에 `git add -A`를 했으면 약관 위반이었습니다.

> 👉 **교훈**: `.gitignore`를 쓴 뒤 **`git check-ignore`로 실제로 막히는지 확인한다.**
> 눈으로 읽어서는 이걸 못 잡습니다.

### ④ 이관한 기본값은 원본 환경을 기억하고 있다

`STORE_BACKEND` 기본값이 `postgres`였습니다. 원본에는 Supabase가 서 있었으니 맞습니다.
**팀 저장소에는 그게 없고, `asyncpg`도 의존성에 없습니다.**

`.env.example`은 이미 *"팀 Supabase를 파기 전까지는 sqlite로 둔다"*고 적어 뒀는데
**코드가 반대**였습니다. 팀원이 clone 직후 `--status` 하나에
`ModuleNotFoundError`를 봅니다 — *"설정을 안 했다"*가 아니라 *"코드가 깨졌다"*로 읽힙니다.

> 👉 **교훈**: 이관할 때 **기본값이 원본 인프라를 전제하는지** 따로 훑는다.
> 상수는 코드처럼 안 보여서 리뷰에서 잘 안 걸립니다.

### ⑤ "정확도 55%"가 왜 아무 말도 아닌지 이제 숫자로 말할 수 있다

이게 발표에서 가장 쓸모 있을 것 같습니다.

1. KOSPI200에서 매일 "상승"만 찍어도 **52.72%** (실측 N=4,097)
2. 검증표본 297일이면 1SE가 2.89%p — 55%와 52.72%는 **z=0.59, 구분 불가**
3. 실력이 0이어도 250일 구간에서 **20번만 시도하면 우연히 56.0%**

> 👉 그래서 정확도를 스칼라로 반환하는 API를 **없애기로** 했습니다([F-10](../요구사항.md)).
> 그런 함수가 남아 있으면 **누군가는 반드시 그 숫자만 발표 표에 씁니다.**

## 7. 추가 기록 — heredoc 하나로 금지 명령을 실행할 뻔했다

TIL 은 고치지 않고 **새로 덧붙입니다**(폴더 규약). 위 6절을 쓴 뒤에 일어난 일입니다.

### 무슨 일이 있었나

PR 본문을 갱신하려고 셸에서 python heredoc 을 열었습니다. 경로 변수를 넣으려고
**따옴표를 뺐습니다.**

```bash
python - <<PY        # ← ❌ 따옴표가 없다
...
new2 = """같은 이유로 `gh pr merge` 금지도 문서가 아니라 스크립트가 거부하게 만들었습니다."""
...
PY
```

따옴표 없는 heredoc 은 **셸이 내용을 먼저 훑습니다.** 본문 안의 백틱이
명령 치환으로 읽혀 **`gh pr merge` 가 실제로 실행**됐습니다.

### 왜 사고로 안 끝났나

두 가지가 겹쳐 막혔습니다.

1. `gh` 가 비대화형에서 `--merge`/`--squash` 플래그를 요구해 **파싱 단계에서 실패**
2. 활성 계정이 개인 계정이라 애초에 collaborator 가 아님

즉 **운이 좋았습니다.** 플래그가 붙어 있었다면 머지됐을 수 있습니다.

확인한 것:

```
PR #2      state=OPEN · mergedAt=null
origin/main b01ba0b (그대로 — 움직이지 않음)
```

### 부수 피해

백틱이 명령 출력(빈 문자열)로 치환돼 **PR 본문에서 그 문구가 사라졌습니다** —
*"같은 이유로  금지도 …"*. 복구했습니다.

### 배운 것

**① 따옴표 없는 heredoc 은 문서를 코드로 읽는다**

마크다운 본문에는 백틱이 널려 있습니다. 그중 하나라도 명령처럼 생기면 실행됩니다.

```bash
python - <<'PY'      # ✅ 항상 따옴표. 변수가 필요하면 파일로 먼저 쓴다
```

**② 가드는 자기를 거치는 호출만 막는다**

`scripts/gh-team.sh` 가 `gh pr merge` 를 거부하도록 만들어 뒀는데,
이번 실행은 **wrapper 를 거치지 않은 생짜 `gh`** 였습니다.
스크립트 가드는 **마지막 그물이지 유일한 그물이 아닙니다.**

가드 자체도 약했습니다 — `$1 == "pr" && $2 == "merge"` 만 봐서
`gh pr merge --squash` 같은 변형에는 위치가 밀리면 안 걸립니다. 인자 전체를 훑도록 고쳤습니다.
