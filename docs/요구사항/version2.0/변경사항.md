# 요구사항 v1.0 → v2.0 변경사항

> 2026-08-27 · [v1.0](../version1.0/요구사항.md) → [v2.0](요구사항.md)
> **Major(+1.0)** 인 이유: **1차 범위가 기능 29건에서 Must 18건으로 좁혀졌습니다.**
> [docs/README §2](../../README.md) 의 *"범위가 크게 바뀐다"* 에 정확히 해당합니다.

---

## 1. 이게 v2.0 의 핵심 — 1차는 Must 18건입니다

v1.0 은 Must 18 · Should 5 · Could 4 · Won't 3 을 **절 셋으로 나눠** 적었습니다.
읽는 사람 입장에서는 *"그래서 2주에 뭘 하나"* 가 흐렸습니다.

**1차에서 안 한다는 점은 Should·Could·Won't 가 전부 같습니다.** 차이는 *언제 다시 볼
것인가* 뿐이라, **표 하나로 접고 '언제' 칸을 넣었습니다.**

| | v1.0 | v2.0 |
|---|---|---|
| 1차에 하는 것 | Must 18건 (§1) | **Must 18건 (§1)** — 수용 기준까지 그대로 |
| 미루는 것 | Should 5 (§2) · Could 4 (§3) · Won't 3 (§3) | **§2 표 하나** (12행 · `언제` 칸 = 9/8 재검토 / 2차 / 3차) |

## 3. 팀원 제안을 수용 기준에 넣었습니다

4번째 팀원이 제안한 것 중 **둘이 우리 요구사항에 없던 항목**이었습니다.

| 제안 | 어디에 들어갔나 |
|---|---|
| **F1-score** | **F-14 · F-15 수용 기준** — 폴드별 지표 목록에 F1 추가. F-15 는 6지표 → **7지표** |
| **확률보행·ARIMA 동기간 방향 적중률 비교** | **F-14 기준선 목록** — `always_up`·`majority_class`·`previous_direction` 에 더해 `timeseries/` 의 **ARIMA 예측 방향 적중률**을 같은 표에 |

> 💡 ARIMA 대조는 *"기존 방법보다 나아졌는가"* 에 직접 답하는 칸입니다. 우리가 이미
> `timeseries/` 2,063줄을 갖고 있어서 **추가 구현 비용이 거의 없습니다.**

**1일 이진 레이블 제안은 받지 않았습니다** — 손익분기 65.03% vs 문헌 상한 55%대.
근거는 [조사/예측지평](../../조사/예측지평.md)에 있고, 제안 쪽 이점(표본 5배)도 함께 적었습니다.
