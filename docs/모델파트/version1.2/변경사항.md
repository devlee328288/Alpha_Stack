# 모델파트 v1.1 → v1.2 변경사항 (2026-09-09)

> v1.1 을 낸 지 **하루가 안 돼서** 냅니다. 그 사이 조합 K 가 들어오고 선정 축 논의가 열렸는데,
> v1.1 의 관찰 하나가 **틀린 채로 남아 있었기** 때문입니다.

## 1. 🔴 먼저 — v1.1 의 관찰 하나를 정정합니다

v1.1 [조합 A~J 성적표](../version1.1/조합-A부터-J-성적표.md) §2.1 에 이렇게 적었습니다.

> **피처가 적을수록 좋았습니다** — 상위 둘(I 4개 · J 5개)이 가장 적은 둘입니다.

**성립하지 않습니다.**

| | v1.1 (조합 A~J) | v1.2 (조합 A~K) |
|---|---|---|
| 1위 | 조합 J · 피처 **5개** · +2.27%p | **조합 K · 피처 14개 · +2.43%p** |
| 2위 | 조합 I · 피처 4개 · +2.09%p | 조합 J · 피처 5개 · +2.28%p |
| 피처 수 ↔ 성적 | *"적을수록 좋다"* | 🔴 **Spearman ρ = −0.0506 · p = 0.8826** |

**K 하나 때문이 아닙니다.** 열한 조합 전체로 상관을 재면 ρ 가 0 이고 p 가 0.88 입니다 — **애초에
관계가 없었습니다.** v1.1 은 상위 두 점만 보고 규칙을 세웠습니다.

가장 적은 것(I, 4개)과 가장 많은 것(K, 14개)이 **둘 다 상위**이고 중간(C 7개 −0.49%p · F 9개
−0.28%p)에 하위가 몰려 있습니다. 답은 **개수가 아니라 축**이고, 그건 v1.0 §2.3 에 이미 있던
결론입니다. v1.1 이 뒤집었다가 v1.2 가 되돌립니다.

**무엇을 배웠나** — 관찰을 적을 때 **전체에 대한 상관계수와 p 값**을 같이 적지 않으면, 두 점으로
만든 규칙이 문서에 남습니다. 앞으로 *"~할수록 ~하다"* 를 적을 때는 숫자를 붙입니다.

## 4. [#197](https://github.com/devlee328288/Alpha_Stack/issues/197) 결정 기록 — 라벨 축은 **㉮ 유지**

**결정: 절대 ±2% 라벨을 유지한다.** ([ADR 0006](../../decisions/0006-개별종목-중립대와-평가기준선.md) 그대로 · 이 이슈로 바꾸지 않음)

데이터 파트가 *"횡단면 상대값이 절대 ±2% 라벨과 축이 어긋난다"* 는 가설로 라벨 변경을 제안했고,
오준영 님이 **거절**하셨습니다. 근거가 정확했습니다.

> 조합 F 의 성능만으로 횡단면 피처와 절대 라벨의 축 충돌이 원인이라고 확정하기는 어렵다.
> **조합별 피처 구성이 함께 달라 원인이 분리되지 않기 때문**이다.

그리고 데이터 파트의 실험(조합 G + 전처리)도 같은 약점이 있었습니다 — 라벨을 안 바꾸고 피처만
바꿨으니, 성능 하락이 "축 충돌" 때문인지 "그 변환이 이 조합에 안 맞아서" 인지 갈라지지 않습니다.
**한 번에 하나만 바꿔야** 하는데 그러지 못했습니다.

| | |
|---|---|
| ✅ 절대 ±2% 라벨 **유지** | 횡단면 상·하위 20% 라벨은 "실제 상승·하락" 이 아니라 "당일 후보 중 상대적 상위" 를 예측하게 되므로 **예측 목표 자체의 변경**에 가깝다 |
| ✅ 라벨 변경 실험 **하지 않음** | |
| 🔵 조합 K LogReg **전처리 전·후 ablation** | 피처 구성을 고정하고 전처리만 바꾸는 통제 실험 · 오준영 님 검토 중 |

`preprocess_cross_section` 은 기본값이 ①winsorize·②z-score 만 켜져 있고 ③중립화·④순위는 인자를
줘야 켜지므로, 두 줄 비교면 **순위·중립화 없이 winsorize·z-score 만의 효과**가 나옵니다.

```python
from features.preprocessing import preprocess_cross_section
X_before = dataset.x
X_after  = preprocess_cross_section(dataset.frame, feature_cols)   # ①② 만
```

🔴 **다만 [#205](https://github.com/devlee328288/Alpha_Stack/issues/205) 가 정해진 뒤에 돌리시는 것이
깨끗합니다** — 조합 K 표본에 거래정지 오염 448행이 들어 있고, 그 이슈에서 ㉯로 정해지면 표본이
160,387 → 159,939 로 바뀝니다. 전처리 효과와 표본 변경이 섞이면 또 원인이 분리되지 않습니다.

## 5. 새로 적은 것 — 다중검정

v1.1 까지는 *"기준선 대비 +N%p"* 만 적었습니다. v1.2 는 **후보를 몇 개 뽑았는지**를 함께 적습니다.

| | v1.1 | v1.2 |
|---|---|---|
| 후보 수 | 40 (10조합 × 4모델) | **44** (11조합 × 4모델) · 총 **1,584 fit** |
| 1위의 유의성 | (적지 않았음) | 단일검정 **p = 0.0074 ✅** · **Bonferroni(N=44) 🔴 미통과** |

Bonferroni 는 가장 보수적인 보정이고(조합 I·J·K 는 피처를 공유하므로 과하게 엄격합니다), *"버려라"*
가 아니라 **"발표할 때 시행 횟수를 함께 적어라"** 로 읽습니다. 그리고 `baseline_win_folds` 10/12 가
평균값 하나보다 강한 증거입니다 — ADR 0007 이 그것을 3차 기준에 둔 것이 좋은 설계였습니다.
