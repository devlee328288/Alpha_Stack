# `data/manual/` — 사이트에서 손으로 직접 받아 온 파일

> **여기에 두는 것**: 팀장(이동원)이 브라우저를 열고 클릭해서 내려받은 파일.
> **여기에 두지 않는 것**: 팀원이 건네준 파일(→ [`data/inbox/`](../inbox/README.md)),
> 코드가 API 로 받아 오는 것(→ 파일을 거치지 않고 `krx_cache.db` 로 곧장 간다).
>
> 받는 방법은 [직접 수집 가이드](../../docs/데이터파트/version2.3/직접수집_가이드.md)에
> 사이트별로 적혀 있습니다.

---

## 왜 `data/inbox/` 와 나눴나

한 폴더가 두 축을 다 받고 있었습니다. `data/inbox/README.md` 는 *"팀원이 건네준 파일을
놓는 자리"* 라고 적혀 있는데, 옛 수집 가이드는 팀장이 손으로 받은 것도 **같은 곳**에
넣으라고 적혀 있었습니다. 그래서 파일 하나를 보고 *"이게 누가 어디서 가져온 것인가"* 를
되짚을 수 없었습니다.

출처를 되짚지 못하면 값이 우리 것과 다를 때 **누구에게 물어봐야 하는지**를 모릅니다.
그래서 폴더로 가릅니다.

| 폴더 | 누가 | 어떻게 | 무엇으로 확인하나 |
|---|---|---|---|
| [`data/inbox/`](../inbox/README.md) | 팀원 3명 | HuggingFace private 에 올림 | `inbox_batch.origin='huggingface'` |
| **`data/manual/`** (여기) | 팀장 | 사이트에서 클릭해 내려받음 | `inbox_batch.contributor` 에 출처를 적는다 |

> ⚠️ **표준 관례에 있는 이름이 아닙니다.** Cookiecutter Data Science(`external` = 제3자
> 출처) · Kedro(가공 단계) · dbt `seeds`(정적/동적) · AWS 랜딩존(마스킹 필요성) ·
> 메달리온(가공 단계) 다섯을 조사했지만, **"손으로 받았나"로 폴더를 가르는 표준은
> 없었습니다.** 관례는 전부 *취득 방법*이 아니라 *신뢰 경계*나 *가공 단계*로 나눕니다.
> 우리가 이 축을 쓰는 이유는 우리 수집이 자동과 수동 두 갈래로 갈리기 때문이고,
> 그 사실을 여기 적어 둡니다.

## 어떻게 쓰나

### 1. 종류별 폴더에 원본 그대로 놓습니다

```text
data/manual/
  ohlcv_stock/     종목 시세      (KRX 전종목 시세 등)
  ohlcv_index/     지수 시세
  financial/       재무·공시      (OpenDART 일괄다운로드 등)
  macro/           거시 지표      (ECOS · KOSIS · 관세청)
  news/            뉴스
  reference/       참고표         (KIND 상장법인목록 · 상장폐지 이력)
```

폴더가 없으면 만들어서 넣으면 됩니다. **파일 이름은 바꾸지 않아도 됩니다** —
검사기가 내용을 보고 판정합니다.

**받은 파일을 손으로 고치지 마세요.** 무엇을 어떻게 고쳤는지는 검사기가 기록으로
남기는데, 손으로 고치면 그 기록이 사라집니다. 엑셀로 열어 저장만 해도 종목코드
`005930` 이 숫자 `5930` 으로 바뀝니다 — 그런 파일은 격리됩니다.

### 2. 인코딩을 맞추고, 뜻 없는 이름을 알아보게 합니다

```bash
python scripts/normalize_manual.py --dry-run   # 무엇을 할지 먼저 봅니다
python scripts/normalize_manual.py             # 변환합니다
```

**원본은 건드리지 않습니다.** 변환본이 `data/manual/normalized/` 아래에 새로 생기고,
무엇을 무엇으로 바꿨는지는 `normalized/MANIFEST.json` 에 남습니다.

**왜 필요한가** — KRX 정보데이터시스템이 주는 CSV 는 `cp949` 입니다. 편집기나 pandas 가
기본값(UTF-8)으로 열면 한글이 깨지거나 `UnicodeDecodeError` 로 죽습니다.
실측 2026-09-02: `투자자별_거래실적/` 35개가 전부 cp949 였습니다.

**이름도 문제입니다.** 같은 화면이 `data_4907_20260902.csv` 처럼 **KRX 일련번호**로
파일을 떨어뜨리는데, 번호는 내용과 아무 관계가 없고 머리글까지 똑같아서 열어 봐도
무엇이 무엇인지 알 수 없습니다. 그래서 값으로 판별해 이름을 붙입니다.

| 무엇 | 어떻게 알아내나 |
|---|---|
| 기간 | 시계열 파일의 `일자` 칸을 그대로 읽습니다 |
| 순매수 | 매도·매수는 0 이상입니다 — **음수가 있으면 순매수**입니다 |
| 거래량 / 거래대금 | 같은 날 같은 투자자의 대금이 수량보다 큽니다 |
| 매도 / 매수 | 생김새가 같아 구별되지 않습니다 → **`순매수 = 매수 − 매도` 검산** |

실측 2026-09-02 · 5개 묶음 전부 **검산 100.00%** 로 확정됐습니다. 이 검산은 항등식이
아닙니다 — 잘못된 배치에서는 일치율이 0.00% 였습니다.

> 🔴 **뜻이 있는 이름은 절대 바꾸지 않습니다.** `data_<숫자>_<숫자>` 무늬만 손댑니다.
> 받는 사람이 화면에서 무엇을 골랐는지는 그 사람만 알고, 그 지식이 이름에 들어 있습니다.
> 스크립트가 값에서 알아낼 수 있는 것은 그보다 적습니다 — 어느 시장·어느 상품군을
> 받았는지는 파일 안에 없습니다. **직접 이름을 붙여 넣으셨다면 그대로 유지됩니다.**

**두 번 돌려도 안전합니다.** 원본의 SHA-256 을 기록해 두고 그대로면 건너뜁니다.
내용이 바뀌면 해시가 달라져 자동으로 다시 변환합니다.

**사본으로 보이는 것은 견주어 보여 줍니다.** 브라우저가 같은 자료를 여러 번 받으면
`... (1).csv` 로 쌓이는데, 이름이 그렇다고 내용이 같은 것은 아닙니다. 어느 칸이 다른지
알려 주고, **고르는 것은 사람이 합니다.**

### 3. 검사기를 돌립니다

```bash
python scripts/check_inbox.py
```

합격분은 `inbox_accepted` 에, 격리분은 `inbox_quarantine` 에 들어가고,
무엇이 왜 안 들어갔는지는 `reports/inbox/<날짜>/` 에 사람이 읽을 수 있게 남습니다.

### 3. 출처를 적어 둡니다

어디서 받았는지는 파일에 안 적혀 있습니다. 같은 폴더에 **같은 이름 `.txt`** 를
하나 두면 나중에 되짚을 수 있습니다.

```text
data/manual/ohlcv_stock/
  20260901_전종목시세.csv
  20260901_전종목시세.txt      ← "KRX 데이터마켓플레이스 MDCSTAT015 · 2026-09-01 받음"
```

## ⚠️ 알아 둘 것 세 가지

### 이 폴더의 파일은 커밋되지 않습니다

`.gitignore` 가 `data/manual/*` 를 막습니다(이 README 만 예외). 이 저장소는 **PUBLIC**
이고, KRX 시세는 이용약관 제12조가 제3자 배포를 금지합니다.

> 전역 규칙(`*.csv` · `*.parquet`)은 CSV·parquet 만 막습니다. 직접 받는 것은
> **`.xlsx` · `.json` · `.zip` · `.xml`** 이 많아서, 이 폴더 전용 규칙이 없으면
> 그대로 공개 저장소에 올라갑니다.

### 검사기가 보는 확장자가 정해져 있습니다

`.csv` · `.tsv` · `.xlsx` · `.xls` · `.parquet` · `.json` 을 봅니다.
**`.zip` 은 풀어서 넣어야 합니다** — 압축된 채로는 건너뜁니다.

OpenDART 일괄다운로드는 ZIP 안에 탭 구분 TXT 가 들어 있습니다. 풀어서 확장자를
`.tsv` 로 바꿔 주세요.

### 재배포 조건은 출처마다 다릅니다

| 출처 | 우리 저장소·발표에 실을 수 있나 |
|---|---|
| KRX (데이터마켓플레이스 · KIND) | ❌ 약관 제12조 — 값을 문서·발표자료에 싣지 않습니다 |
| 공공데이터포털 (금융위 시세·재무) | ✅ 이용허락범위 **제한 없음** |
| KOSIS **국내**통계 | ✅ 상업적 이용·재배포 허용 |
| KOSIS **국제·북한**통계 | ❌ 비상업적만·재배포 금지 |
| ECOS (한국은행 **작성분**) | ✅ 출처를 밝히면 재배포 가능 |
| ECOS (타 기관 작성분) | ⚠️ 작성기관을 확인해야 합니다 |
| OpenDART | ⚠️ 금감원 고지 확인 필요 |

> 헷갈리면 **싣지 않는 쪽**을 고릅니다. 건수·비율만 적어도 문서는 성립합니다.
