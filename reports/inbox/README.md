# reports/inbox — 무엇이 들어왔고 어떻게 판정했나

`python scripts/check_inbox.py` 를 돌리면 날짜 폴더가 생기고 그 안에 판정이 쌓입니다.

```text
reports/inbox/
  2026-09-01/
    요약.md                       그날 들인 것 전부 한 장
    ohlcv_stock_시세_0831.md      파일별 판정 — 사람이 읽는 것
    ohlcv_stock_시세_0831.json    파일별 판정 — 기계가 읽는 것
```

## 왜 두 가지로 내나

판정을 받을 사람은 팀원이고, 그 사람이 알고 싶은 것은 `{"rule": "high_ge_low"}` 가 아니라
*"내 파일 8행 중 3행이 안 들어갔고, 그중 하나는 고가가 저가보다 낮아서"* 입니다.
그래서 사람이 읽을 것과 기계가 읽을 것을 **둘 다** 냅니다.

사람용 `.md` 에는 이런 절이 있습니다.

| 절 | 답하는 것 |
|---|---|
| 결과 | 몇 행이 들어오고 몇 행이 격리됐나 |
| 왜 격리됐나 | 사유별 행 수 + 규격이 적어 둔 뜻 |
| 우리가 손댄 것 | 칸별로 무엇을 무엇으로 바꿨나 (표본 20건) |
| 못 읽은 값 | 값이 **있었는데** 형이 안 맞은 것 — 빈 칸과 다르다 |
| 우리가 채우고 검사한 것 | 시점 칸을 채웠나 / 규칙보다 이르지 않았나 |
| 물어볼 것 | 이름만 보고는 정할 수 없어 남겨 둔 칸 |
| 규격에 없는 칸 | 버리지 않고 `extras` 로 담은 것 |

## 🔴 보고서에 자료를 싣지 않습니다

이 저장소는 **PUBLIC** 입니다. 시세는 KRX 이용약관 제11조 ②가 제3자 제공을 금지하고,
뉴스 본문은 언론사 저작물입니다.

그래서 보고서가 담는 것은 **판정과 표본뿐**이고, 표본조차 값이 실제로 바뀐 자리의
before → after **20건까지**입니다. 원본 행은 `data/inbox/` 와 `krx_cache.db` 에만 있고
둘 다 커밋되지 않습니다.

재현에 필요한 것은 파일이 아니라

- [`ingest/inbox/schemas/`](../../ingest/inbox/schemas/) — 무엇이 들어와야 하는가 (규격)
- 이 폴더 — 무엇이 들어왔고 어떻게 판정했나 (기록)

이고, 그 둘은 커밋합니다.
