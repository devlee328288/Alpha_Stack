코드와 문서만으로는 *"이 표에 뭐가 들었나"* 를 알 수 없습니다. 저장소를 뒤져야 하고,
뒤져도 실행해 보기 전엔 모릅니다. 이 폴더의 노트북은 **마크다운 설명 + 코드 + 실행된
출력**을 한 장에 담아 그 물음에 바로 답합니다.

GitHub 웹이 `.ipynb` 를 그대로 렌더링합니다. **받지 않고 링크만 눌러도 읽힙니다.**

## 쓰는 규칙

1. **실행한 채로 커밋합니다.** 출력이 빈 노트북은 내지 않습니다 — 그러면 이 폴더가
   존재하는 이유가 없어집니다.
2. **마크다운을 먼저 씁니다.** 무엇을 왜 보는지 한 문단 적고 코드를 붙입니다.
3. **숫자에는 잰 날짜를 붙입니다.** 자료는 매일 자라므로 "920만 행" 은 언젠가 틀립니다.
4. **원본 자료를 노트북에 붙여 넣지 않습니다.** KRX 이용약관 제11조 ② 가 제3자 제공을
   금지하고, 이 저장소는 **Public** 입니다. 표본 몇 줄과 집계까지만 남깁니다.
5. 남의 폴더에 넣기 전에 담당자에게 먼저 묻습니다.
6. **`ruff` 가 노트북 코드도 검사합니다.** `.py` 와 같은 규칙(줄 길이 100 · `zip(strict=)`
   등)이 걸리므로, 커밋 전에 `.venv/Scripts/python.exe -m ruff check .` 로 확인하세요.
   지금 남아 있는 33건은 전부 이관 코드의 부채이고 **노트북 몫은 0건**입니다.

## 실행

노트북 도구는 `dev` 그룹에 있습니다.

```bash
uv pip install --python .venv/Scripts/python.exe -e ".[dev]"
```

VS Code 에서 `.ipynb` 를 열고 커널로 `.venv` 를 고르면 그대로 돌아갑니다.
명령줄에서 다시 실행하려면:

```bash
.venv/Scripts/python.exe -m nbclient notebooks/01-데이터수집/01.KRX시세받기.ipynb
```

⚠️ DB(`data/krx_cache.db`, 1,578MB · 2026-08-31 기준)는 `.gitignore` 라 저장소에
없습니다. 노트북을 **다시 돌리려면** 먼저 `python scripts/fetch_krx.py` 로 채워야
합니다. 읽기만 할 거면 커밋된 출력으로 충분합니다.
